# fraud_structure_v1 — 사기 구조 특성화: 데이터가 가진 구조 중 backbone·현재 모델이 못 잡는 것은 무엇인가 (등록 2026-11-09, 실행 전)

## 0. 목적과 위치

진단 단계(학습 0, GPU 0). 지금까지의 설계는 "backbone 출력의 오차 축"에서 출발했다. 이 단계는 반대로 **데이터의 사기 구조**를
4층으로 먼저 재고, 각 구조를 (a) 실제 데이터가 실제로 갖는지(정상 대비 효과 크기), (b) backbone 원형과 현재 모델(동결 backbone +
전이표 + 라벨 라우팅 head)이 재현하는지(바닥 배)를 한 표로 만든다. 표에서 "실제에 있고 · 현재 모델이 못 잡는" 구조 2–3개가
다음 아키텍처 단계의 **설계 대상**이 된다(귀납 편향을 데이터 구조로 정당화). 사용자 지시(2026-11-09): "데이터를 잘 잡아내는
모델 아키텍처 — 그 데이터 특징을 먼저 신경써라".

## 1. 재는 구조 (두 데이터: IBM 2013 train 1,000 / dev 240, Sparkov train 688 / dev 147; 봉인 test 미읽음)

기존 1단계 지표(지속률·구간 수·구간 길이·24h 구간·사기 간격/금액/업종/온라인 주변분포)는 재지 않고 참조만 한다. 새로 재는 것:

| 층 | 구조 | 통계량 | 거리 |
|---|---|---|---|
| A 라벨 과정 | 구간 간 간격(같은 고객의 24h 구간 사이 시간) | 시간 배열 | log-W1 |
| A | 구간 시작 위치(시퀀스 내 상대 위치) | 배열 | W1 |
| A | 사기 고객의 시퀀스 길이 / 비사기 고객 | 중앙값 비 | 상대차 |
| B 구간 내 출력 | 금액 상승(구간 마지막/첫 금액 log 비, 길이 ≥ 3) | 배열 + 중앙값 | W1 |
| B | 구간 내 금액 변동(CV, 길이 ≥ 3) | 배열 | W1 |
| B | 구간 내 가맹점 반복(나이 ≥ 2 행 중 같은 구간 앞 행과 같은 가맹점) | 비율 | 절대차 |
| B | 구간당 서로 다른 가맹점 수 / 길이 | 배열 | W1 |
| B | 사기 행의 **새 가맹점** 비율(그 고객 과거에 없던 가맹점) — 정상 행 대비 | 비율 | 절대차 |
| B | 사기 행의 새 업종 비율 — 정상 대비 | 비율 | 절대차 |
| B | 사기 행의 새 채널 비율(IBM use_chip) — 정상 대비 | 비율 | 절대차 |
| B | 구간 내 간격(나이 ≥ 2, 분) | 배열 | log-W1 |
| B | 사기 행 시각(시간대 24구간; 실제는 원 타임스탬프, 생성은 dev 첫 시각 + 누적 간격 **근사**) — 정상 대비 TV, 야간(0–6시) 비율 | 분포/비율 | TV / 절대차 |
| C 구간 간·전조 | 진입 직전 정상 5행의 금액 / 고객 과거 중앙값 | 배열 | log-W1 |
| C | 진입 직전 5행의 새 가맹점 비율 — 전체 정상 대비 | 비율 | 절대차 |
| C | 진입 행 금액 / 고객 과거 중앙값 | 배열 | log-W1 |
| C | 구간 종료 직후 정상 행 간격 / 고객 과거 중앙값 | 배열 | log-W1 |
| D 고객 수준 | 어떤 고객에게 사기가 가는가: 맥락 변수(IBM: cards_before, events_per_year_before, first_year; Sparkov: 맥락 수치열)의 사기 고객–비사기 고객 표준화 평균차 | SMD | 절대차 |
| D | 사기 고객 일치(생성은 같은 dev 고객 맥락에 조건부이므로 실제 사기 고객 집합과의 Jaccard; 우연 수준 병기) | Jaccard | — (바닥 없음) |
| D | 사기 가맹점 집중(사기 행 중 상위 10 가맹점 비율; 정상 대비) · 둘 이상 고객이 공유하는 사기 가맹점 비율 | 비율 | 절대차 |
| D | 사기 업종 집중(상위 3 업종 비율; 정상 대비) | 비율 | 절대차 |

바닥: train 고객 n_dev명 무작위 부분표본 200회(seed 20261107) vs dev의 같은 거리; **바닥 배 = 생성 거리 / 바닥 중앙값**, ≤ 3배는 잡음.
효과 크기(실제): 사기 vs 정상 비율의 비(≥ 1.5 또는 ≤ .67) 또는 TV ≥ .10이면 "구조 있음".

## 2. 비교 대상 (기존 생성물, 새 생성 0)

IBM: ARGN 원형 `native_*`, ARGN + 현재 모델 `routed_subst_table_*`, RTF 원형 `rtf_native_*`, RTF + 현재 모델 `rtf_table_*` (fit 2 × 생성 2).
Sparkov: ARGN 원형 `native_*`, ARGN + 전이 head `gap_and_transition_*`, REaLTabFormer `w60` (생성 2).

## 3. 사전 판단

- **설계 대상** = 실제에 구조 있음 **and** 현재 모델(두 backbone 중 하나 이상)의 바닥 배 ≥ 3 **and** 두 데이터 중 하나 이상에서 성립.
  바닥 배가 큰 순으로 상위 3개까지 다음 단계의 아키텍처 부품 설계 대상으로 등록한다.
- **이미 재현됨** = 현재 모델 바닥 배 ≤ 3 → 부품 불필요, 모델 설명에 "유지"로만 기록.
- **데이터에 없음** = 효과 크기 미달 → 설계 근거로 쓰지 않는다(시뮬레이터 한계로 기록).
- 시각(시간대) 재현은 근사이므로 설계 대상 선정에는 쓰지 않고 참고로만 둔다.
- 결과가 "현재 모델이 모든 구조를 ≤ 3배로 재현"이면 아키텍처 추가 근거가 없음을 그대로 기록한다.

## 4. 실행

`benchmarks/fraud_structure.py`(numpy/pandas/scipy), `scripts/run_fraud_structure.py --dataset ibm|sparkov`. CPU. 산출:
`docs/fraud_structure_v1/{ibm,sparkov}/REAL_STRUCTURE.csv`(train 서술 + 효과 크기), `GENERATIONS.csv`, `FLOOR_SUMMARY.csv`, `RATIOS.csv`,
`RESULTS.md`. 봉인 test 미읽음; IBM 시각은 `raw_events.parquet`에서 train·dev 고객만 읽는다.
