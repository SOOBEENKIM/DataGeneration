## 3. 판정

- **M1 기각.** 사기 온라인 비율 비율 15.0은 원형(17.1)의 절반이 아니며, 라벨 단독 P(온라인) .27 < .6.
- **M2.** p=1.0이 p=.5보다 일관되게 낫다(혼합은 head가 다시 문맥에 기댄다). 그래도 생성에 옮겨가지 않는다.
- **M3 충족**(표준 지표 ±.03). **M4 기각**(.008).

## 4. 해석 — 왜 치환으로도 라벨 경로가 열리지 않는가

라벨 임베딩 경로 자체는 살아 있다(코드 0/1 임베딩 거리 1.2, 다른 열과 같은 척도, use_chip regressor
Linear(1174→16)에 직접 입력). 그런데도 학습이 라벨 단독 응답을 .27 이상으로 밀지 못한다. 치환 학습에서
사기 행이 가진 신호는 라벨(현재·이력)뿐이므로, 남는 설명은 **용량·간섭**이다: use_chip head는 은닉 16
유닛을 정상 거래(가중 합 50%)와 사기 거래(가중 합 50%)가 공유한다. 라벨 방향 e₁−e₀로 출력을 크게
바꾸려면 정상 행에서도 쓰는 유닛을 건드려야 하고, 두 손실이 같은 무게라 **타협점**(.25–.45)에서 멈춘다.
가중을 더 키우면 정상 품질이 깨지고(이미 표준 지표가 경계), 줄이면 사기가 사라진다. 이는 Sparkov에서
`amount_balanced_shared`(.78)보다 `amount_balanced_routed`(.85)가 나았던 것과 같은 방향의 증거다.

## 5. 함의

상태별 출력 축을 head 수준에서 고치려면 **사기 상태 전용 파라미터**(라벨로 라우팅되는 별도 head:
정상 행은 원형 head 그대로, 사기 행만 새 head)가 필요하다. 그러면 정상 품질과의 간섭이 구조적으로
없고, 사기 head는 사기 행 1,100여 개(train)로 natural 가중 학습을 하면 된다. 실패하면 head 수준으로는
불가능하다고 결론 내리고 backbone 학습(라벨 조건부 손실)으로 넘어간다. 이 설계는 이 등록 밖이며 별도
프로토콜이 필요하다.
