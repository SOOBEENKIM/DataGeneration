# ibm_masked_heads_v1 — 문맥 치환(마스킹) 학습으로 라벨 경로에 신호 강제 (등록 2026-11-08, 학습 전)

목적: [ibm_output_heads_v1](../ibm_output_heads_v1/RESULTS.md)에서 동결 backbone 위 head 재학습은
teacher-forced에서는 사기 채널을 배우지만(use_chip 사기 CE 1.95→.58) 자유 생성에서는 사기 온라인
비율 .27→.34(실제 .88)에 그쳤다. 라벨 경로 분해: head는 "라벨 + 실제 사기 문맥(같은 행의 짧은
간격·큰 금액, 사기 이력의 실제 필드)"의 상호작용을 배웠고, 라벨만으로는 P(온라인) .2–.3이다. 생성
시 문맥은 정상 거래와 같으므로 그 값이 그대로 나온다. 이 단계는 **학습 입력의 사기 행 문맥을
정상 행의 것으로 치환**해 head가 사기 출력을 **라벨(과 라벨 이력) 경로**로만 낼 수 있게 강제한다.

## 1. 관측 오류와 근거

`ibm_output_heads_v1/LABEL_PATH_PROBE.csv`: 실제 사기 행 P(온라인) .62/.47 → 라벨만 0으로 .20/.19;
실제 정상 행 .12 → 라벨만 1로 .29/.22. 자유 생성 온라인 비율 .33–.34는 후자와 일치한다. 학습 조건
(실제 문맥)과 생성 조건(생성 문맥)의 불일치가 원인이다.

## 2. 가장 가까운 선행

- 노출 편향 대응: scheduled sampling(Bengio et al. 2015), professor forcing — 자기 생성 문맥으로 학습.
  여기서는 생성기를 돌리지 않고 **실제 정상 행의 필드를 사기 행 입력에 치환**해 "라벨=1, 필드=정상"
  조건을 흉내 낸다(값싼 대용).
- 입력 마스킹/드롭으로 특정 경로에 의존을 강제하는 학습(feature dropout, counterfactual augmentation).
- 자체 선행: `ibm_output_heads_v1`(치환 없음), Sparkov amount/category head.
새 모델 구조가 아니라 **학습 입력 분포의 교정**이다.

## 3. 중복과 남는 가설

치환·마스킹 자체는 선행과 겹친다. 남는 것: (M1) 치환 학습으로 자유 생성에서 사기 온라인 비율·사기
업종·사기 금액·간격이 원형의 절반 이하로 줄고(이상적으로 바닥 3배 이내) 라벨 경로 단독 P(온라인)이
.6 이상으로 오르는가. (M2) 치환 확률 .5(실제 문맥과 치환 문맥 혼합)와 1.0(사기 행은 항상 치환) 중
어느 쪽이 생성에 옮겨가는가. (M3) 정상 출력 품질 비용이 +.05 이내인가. (M4) 효용(stable 이력 AUPRC)이
.009에서 .2 이상으로 오르는가.

## 4. 비교 실험

- 기반·대상·동결 범위·손실·검증·예산은 [ibm_output_heads_v1 수정안 3](../ibm_output_heads_v1/PROTOCOL.md)과
  같다(gap·amount·category·use_chip head, 라벨-첫-열, balanced 가중, Adam 3e-4, 창 100, batch 8,
  전체 시퀀스 val, patience 5, 최대 100 epoch). natural 가중은 쓰지 않는다(이미 기각).
- **치환**(`substitute_inputs`): 배치마다 사기 행(라벨=1)을 확률 p로 고르고, 그 행의 입력 토큰 중
  gap·merchant·amount·category·use_chip을 **같은 시퀀스 창 안의 무작위 정상 행** 토큰으로 바꾼다.
  라벨·SLEN/SIDX/SDEC는 그대로. **손실의 목표값은 원래(치환 전) 토큰**이다. 치환된 입력은 같은 행의
  선행 열 임베딩과 이후 행의 이력(LSTM 입력) 양쪽에 들어가므로 "사기 라벨 + 정상 필드" 조건이 학습
  입력에 생긴다. 창 안에 정상 행이 없으면 치환하지 않는다. 가중(884)은 라벨 기준으로 그대로 적용.
- 검증: 매 epoch 두 가지 — 실제 문맥 val 손실과 **치환 문맥(p=1) val 손실**. 조기 종료 기준은 치환
  문맥 손실(생성 조건에 가까움). 둘 다 기록.
- 팔: `mask50`(p=.5), `mask100`(p=1.0) × fit 2 = head 학습 4회. 생성: 라벨 첫 열 + 전이표 + head,
  2 × 2 × 2 draw = **8회**. 비교군: 원형, transition_label_first, heads_balanced_table.
- 평가: 1단계(`--dataset ibm`, 등록표 추가), 효용(stable), 라벨 경로 탐침(`probe_output_heads_label_path.py`
  를 head 경로 인자로 일반화).

## 5. 판단 조건

- **M1 채택**: `mask*` 중 한 팔의 두 fit 평균에서 사기 온라인 비율 비율이 원형(17)의 절반 이하이고
  라벨 단독 P(온라인) ≥ .6. 바닥 3배 이내면 강한 채택. 둘 다 아니면 기각 → 상태별 출력 블록(라우팅)
  설계로 넘어간다.
- **M2**: 두 팔의 생성 측 사기 출력 지표 비교로 기록.
- **M3**: 표준 지표 절대 악화 ≤ +.05.
- **M4**: 이력 AUPRC ≥ .2 지지, ≥ .4 강한 지지.
- 새 방법의 우위 주장이 아니라 "학습 조건 교정으로 head 재학습이 생성에 옮겨가는가"의 확인이다.

## 6. 실행 후 갱신

학습 로그(두 val 손실), head 해시, 생성 8개 지표·효용, 라벨 경로 탐침, 실패를 `RESULTS.md`·CSV에 남긴다.

## 수정안 1 — 열별 조기 종료, 학습률 (2026-11-08, 첫 학습 완료·생성 전)

첫 학습(4회, 16–38 epoch)에서 치환 문맥 val 손실(4열 합)이 일찍 평탄해졌고 라벨 경로 탐침은
P(온라인|정상 행, 라벨=1) .15–.20으로 거의 움직이지 않았다(`attempt1_joint_stop/`). 원인: 합산 기준에서
use_chip은 10%(CE 1.3 대 금액 4.6·간격 4.7)라 금액·간격의 잡음이 종료를 결정했고, 별도 소규모 확인
(use_chip만, p=1, lr 3e-3)에서 라벨 경로가 epoch당 +.02씩 **느리지만 학습됨**을 봤다(.155→.28, 6 epoch).
수정: (1) head는 독립 모듈이므로 **열별로** 치환 문맥 val CE가 최선인 epoch의 가중치를 따로 고르고,
모든 열이 patience 5를 소진하면 멈춘다, (2) lr 3e-4 → 1e-3. 최대 100 epoch·그 외 동일. 판단 조건 불변.
