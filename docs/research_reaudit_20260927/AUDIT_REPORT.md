## 어디서 연구 진행과 해석이 잘못됐는가

### 1. 서로 다른 모델·목표·설정을 하나의 연속된 성능 개선처럼 설명했다

| 단계 | 실제 구조/목표 | 재점검 판단 |
|---|---|---|
| 초기 CoF-SeqGen | 거래열 diffusion, fraud head와 고정 teacher의 일치 손실, 전체 창의 any-fraud 조건 | 지금의 자연 발생 거래열 ARGN과 조건이 다르다. teacher와의 일치는 현실 관계의 충분조건이 아니다. |
| CoF-SAF/CS-SAF controlled | 짧은 거래열, gap→copy/new 또는 observable-repeat, 집단별 상호작용 | 반복곡선 개선과 전체 mark 전이 악화가 함께 있었다. controlled 성공을 Sparkov 사기 문제의 해결로 이전할 수 없다. |
| 외부 U/G/D/D_bin | 고객 context+최근31거래 GRU, gap→merchant→amount→category/type | D_bin은 일부 금액 관계를 실제 개선했다. Sparkov에서는 screen 통과, Berka 비용 초과. 사기 상태 전체를 해결한 실험은 아니다. |
| ARGN relation pilot | engine2.4.0, window32, category logit에 gap×직전category 경로 | 개선1.08%로 등록5% screen 미달. category가 merchant/amount 뒤여서 현재 두 필드를 직접 제어하지 못했다. |
| Berka 재현 | 공식 공개 자료·engine1.0.4, parent/child 학습·생성 | 논문 종합 품질 약.79 대비.785. 유효한 출발점이며 완전 동일 환경 재현을 뜻하지 않는다. |
| Sparkov encoding/control | native window100, AUTO/DIGIT·순서 대조 | codec 영향을 먼저 확인한 것은 유효했다. Sparkov 적용이지 원 논문의 Sparkov 재현은 아니다. |
| B/B+S 및 후속 가중치/순서 | full retained history, 고정 field 순서; S는10개 과거 특징→history projection | 원형과 변경된 설정이다. B/S 내부 비교는 맞지만 이것만으로 원 논문 구조의 한계를 확정할 수 없다. |

예전 controlled 문제에서 핵심인 같은 merchant 반복은 Sparkov에서는 드물었다
(기존 외부 감사 약.204%). 반복 전용 경로를 오래 확장하기 전에 실제 외부 문제의
어떤 오차를 줄일지 연결했어야 한다. 또 초기 `models/cof_seqgen.py`의 문서상
label loss 계수는.1인데 실행 식은1.0이다. **과거 설명과 코드의 불일치**이며
현재 ARGN 오류의 원인으로 확대하지 않는다. 기존 코드는 소급 수정하지 않았다.

### 2. train에서도 못 배운 문제를 생성 중 누적 오차 중심으로 설명했다

아래는 직전 거래가 사기인 위치에서 다음 사기의 평균 예측 확률이다.
각 범위는 두 학습 seed다. 임의로 고른 최상 결과가 아니다.

| 모델 | 학습 거래 | 개발 거래 |
|---|---:|---:|
| 관측 지속률 | 90.81% | 91.09% |
| B | 64.42–70.58% | 67.70–71.31% |
| B+S | 76.72–79.03% | 77.48–81.94% |
| 거래별 가중치 B | 1.11–4.06% | 1.16–4.37% |
| 거래별 가중치+라벨 우선 | .72–1.62% | .73–1.74% |
| train-only Markov | 90.80% | 90.80% |

**희귀 전환이 학습 자료에서도 맞지 않는다. 과적합이나 생성 이력 누적만으로
설명되지 않는다.** 고객 평균 손실은 짧은 사기 전용 고객을 거래 수 대비 크게
가중했고, 거래별 손실로 바꾸면 전체 비율은 나아지지만 희귀 지속 관계는 사라졌다.
이는 현재 설정에서 목적·최적화·정보 전달의 문제를 확인한 것이다. 세 요소 중
하나를 유일 원인으로 확정한 것은 아니다. 공유 loss/early stopping이 희귀 field
학습을 충분히 보장하지 않는다는 가설은 남지만 gradient 크기까지 측정한 증거는 없다.

### 3. 단순 대조로 설명되는 개선을 먼저 분리하지 못했다

ARGN의 가중치는 그대로 둔 채, 다음 label 확률만 학습 전이표 또는 기간표로
바꾸고 그 label에 조건화해 나머지 거래를 생성했다. 정답 label을 사후에 붙이거나
사기 비율·구간 길이를 강제한 것이 아니다.

| 지표 | 실제 | 기존 거래별 손실·라벨 우선 ARGN | ARGN+Markov | ARGN+기간표 |
|---|---:|---:|---:|---:|
| 사기 비율 | .644% | .487–.632% | .543–.693% | .583–.634% |
| 평균 사기 구간 | 10.05건 | 1.01–1.02건 | 9.99–11.16건 | 10.13–10.60건 |
| 정상 복귀율 | 8.91% | 98.16–99.03% | 8.96–10.01% | 9.44–9.87% |

이 결과는 **기본 전환을 회복할 수 있다는 실제 생성 증거**다. 다음 모델은 이
수준을 기준으로 삼는다. 연구를 포기할 근거도, 이 표만으로 논문 기여를 완성했다는
근거도 아니다. 대조 head는 개인·길이 조건을 생략했고 그 손실도 드러났다.

### 4. 남은 문제는 구체적이다

1. **누구에게 사기가 생기는가:** 실제147명 중114명에게 사기가 있었고 모두
   한 구간씩 관측됐다. 단순 head는62–79명에게 구간을 분산시켰다. 실제 사기
   전용 고객12명도 생성에서는0명이다. 전체 발생률·평균 지속률만 맞추면 이
   고객 구성이 맞지 않을 수 있다. 관측 한 구간을 “최대 한 번” 규칙으로 강제하지 않는다.
2. **사기 때 어떤 금액이 나오는가:** 실제 사기 금액 중앙값361.07에 비해
   단순 head를 연결한8개 생성물은48.17–54.95다. 직전20거래 중앙값 대비
   사기 금액 비율 중앙값도 실제6.93배, 생성 약.99–1.13배다.
3. **관계 오차가 표본 수 때문인가:** 실제 고객의 독립 bootstrap 두 표본 간
   개인 금액 비율 log-W1의 중앙값은.074,2.5–97.5% 범위는.034–.185다.
   새 생성물은1.075–1.155였다. 다중 조건 TV의 재표본 변동 중앙값도.210,
   상위97.5%는.257이다. 이는 관측 개발 표본 안의 기술적 변동이며 모집단의
   엄밀한 하한이나 통계적 유의성 검정은 아니다.

따라서 전환만 고친다고 개인 금액 관계가 자동으로 좋아지지 않는다. 이 결과를
보고 등록한 후속 금액 진단에서는 실제 과거·실제 label/category/gap/merchant를
모두 주어도 **학습 사기 금액 중앙값408.43에 대해50.81–51.18, 개발 사기 금액
361.07에 대해50.78–50.92**를 생성했다. 정상 거래는 각각46.00에 대해44.30–48.87,
47.44에 대해44.02–49.06이었다. DIGIT 직접 복원 기준이다.

**사기 조건부 금액도 학습 자료에서부터 맞지 않는다.** 생성 이력이 바뀌어서만
생긴 문제가 아니다. 첫 금액 digit의 실제 이력/한 단계 생성 logits를23,540위치에서
대조해 일치시켰다. 다만 head 용량·label 정보 전달·희귀 표본 loss/최적화 중 어느
하나가 유일 원인인지는 이 진단으로 확정하지 않는다. 전체 오류에서 각각이 차지하는
인과적 비율을 계산한 것도 아니다.

### 5. 평가 해석도 바로잡는다

- 실제로 종료한101건만 골라 사기 확률이 높았다는 사실만으로 “종료를 못 배움”을
  확정할 수 없다. 잘 보정된91% 지속 모델도 실제 종료9%의 사건에91%를 줄 수
  있다. calibration은 **과거로 정의한 위험 집합**의 예측 평균과 관측률을 비교해야
  한다. 이전 종료 subset 표는 오류 기술용이며 독립된 calibration 검정이 아니다.
- 실제 이력 진단에서는 실제 길이/position도 입력했다. 자연 생성은 예측한 길이를
  사용한다. 두 경우의 차이를 모두 이력 누적 탓으로 돌리지 않는다.
- “평소 금액” 지표는 전체 개인 lifetime 기준이 아니라 **직전20거래 중앙값**이다.
  사기가 이어지면 그 기준도 바뀐다. 정상 이력 기준과 현재 rolling 기준을 구분해
  추가로 보아야 한다.
- Sparkov는 simulator 산출물이다. 원본 version과 생성 seed를 확정하지 못한
  현재 표에서 하나의 사기 구간 법칙을 실제 금융 일반 법칙으로 주장하지 않는다.
- CPAR 최적화·가까운 최신 모델의 동일 과제 비교가 남아 있다. “최신 모델 모두를
  이겼다/모두 이 문제를 못 푼다”는 현재 결과가 아니다.

## 이후의 ARGN 개발은 이렇게 좁힌다

**유지:** 혼합형 codec, native 거래 decoder, 고객 context, 기존 평가와 생성물.
**개발 후보:** (a) 개인·episode 이력에 조건화된 전환 head와 (b) 해당 상태에
조건화된 거래 출력의 학습을 분리해 검증한다. 기존 CS-SAF 전체를 이식하지 않는다.

실제 이력에서도 금액 조건부 생성이 나쁜지 확인했고, 현재 두 모델에서는 나빴다.
따라서 다음 최소 학습 대조는 **희귀 상태별 출력부가 주어진 조건부 분포를
학습하도록 하는 변경**이다. 전환의 자연 발생 확률과 거래 출력의 상태별 학습을
분리하고, class reweight/일반 조건부 head만으로 충분한지 먼저 본다. 큰 encoder나
diffusion을 동시에 추가하지 않는다.

다음 학습 후보의 구체적인 범위는 [개발 명세](NEXT_DEVELOPMENT.md)에 있다.
이는 **구현·학습 완료라고 주장하는 모델이 아니다.** 이번에 실행 완료한 것은
10개 저장 모델의 진단, known-method head 연결8개 생성, 두 모델의 조건부 금액
sampling, 원문/코드/결과 재점검이다.
향후 핵심 주장은 “상태를 넣었다”가 아니라 단순 head·일반 조건부 모델보다
개인 이력–사기 구간–거래 속성의 결합을 개선하고 그 이유를 분리해 보였다는
결과여야 한다. 이를 입증할 때까지 기여는 후보로 둔다.

## 검증과 보관

전환 참조 확률은 전체1,094,506개 인코딩 위치에서 독립 표 집계와 일치했다.
동일 teacher 입력에서 label 외 logits는 bitwise 같고 기존 checkpoint가 그대로
로드됐다. 최초 진단의 nested-array 읽기 오류는 [amendment](AMENDMENT_01.md)와
실패 log로 보존했으며 학습 코드나 가중치의 오류로 혼용하지 않는다.
8개 생성물의 label 비율·구간·종료율·고객 수5개 지표를 별도 반복문으로 검산했다.
[완료 증거](completion_evidence.json), [CPU 확인](transition_reference_cpu_gate.json).

전체 raw 데이터·checkpoint는 로컬 artifacts에 보존한다. GitHub에는 코드·조건·
집계·검산·독해 기록을 저장한다. 기존 실패를 지우거나 성공으로 소급 변경하지 않았다.
