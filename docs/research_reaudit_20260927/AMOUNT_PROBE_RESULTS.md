# 실제 label을 주어도 사기 금액을 놓친다

학습 데이터의 모든 사기4,739위치와 동수의 정상 위치, 개발 데이터의 모든
사기1,146위치와 동수의 정상 위치를 사용했다. 같은 선택을 두 checkpoint에
적용하고 위치별4회 금액 sampling을 했다. 실제 과거·static context·현재
label/category/gap/merchant·길이/position을 제공했다. 금액의 내부 digit은
정답을 주지 않고 모델이 차례로 생성했다.

| split / 실제 label | 실제 금액 중앙값 | 모델1 생성 중앙값 | 모델2 생성 중앙값 |
|---|---:|---:|---:|
| optimization / 정상 | 46.00 | 44.295 | 48.870 |
| optimization / 사기 | 408.43 | 50.810 | 51.175 |
| development / 정상 | 47.44 | 44.020 | 49.055 |
| development / 사기 | 361.07 | 50.920 | 50.780 |

사기 금액 log1p-W1은 학습1.937–1.949, 개발1.921–1.923이었다.
이는 사기 금액의 조건부 생성이 train에서도 나쁘다는 증거다. 단순 과적합이나
자유 생성 이력 오류만의 문제로 설명할 수 없다. 정상 중앙값이 맞는 것이 정상
분포 전체의 완전한 재현을 뜻하지는 않는다.

같은 사기 prefix에서 현재 label을 정상으로 바꾸면 금액 중앙값이 학습46.44–47.67,
개발46.30–47.78로 낮아진다. label 경로가 완전히 비활성인 것은 아니지만 실제
사기 금액과의 차이를 학습하지 못했다. 이 변경은 모델 민감도이며 현실의 인과
효과나 타당한 counterfactual을 식별한 결과가 아니다.

이번 금액은 원형 DIGIT 토큰을 직접 수치로 복원한 값이며 보호된 tail 재표본추출
전이다. 실제 금액도 같은 codec로 비교했다. native decoder까지 포함한 기존
자유 생성 결과와 혼동하지 않는다. teacher digit NLL은 label별 원래 난이도도
다르므로 NLL 크기만으로 실패를 판정하지 않았다.

모델별11,770위치의 첫 금액 digit logits가 실제 이력 전체 forward와 한 단계
generation 사이에서 허용 오차 내 일치했다. label/앞 필드·history 조건 경로가
달라진 진단 오류를 점검한 것이다. 모델별 약68초, 두 GPU에서 완료했다.
두 실행의 선택 파일 SHA256도 같고 가중치는 그대로다. 최종 test 미접근.
