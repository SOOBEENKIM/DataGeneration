# Sparkov ARGN 기준 실험: 관계 오류와 원인 대조

실행 범위: ARGN 자식 모델 8회 학습(4설정×2seed), 공통 context용 부모 모델
1회, CPAR 128 epoch 1회와 재표집 진단 대조. 생성 데이터 54개를 보존하고
전체 출력 검증을 통과했다. 요청한 1~2단계의 진단이며 새 제안 모델의 학습은 없다.

**이번 단계의 결론은 ‘ARGN의 구조적 한계를 입증했다’가 아니다. 전체 사기
비율이 가까워도 세부 관계는 어긋났고, 그중 큰 부분은 수치 전처리와 학습·생성
설정에서 발생함을 분리했다.** 이 원인을 제거·통제한 기준과 비교해야 이후
제안 모델의 기여를 평가할 수 있다.

| 조사 대상 | 현재 판정 | 근거의 범위 |
|---|---|---|
| 금액·간격 전처리 | 오류 원인 확인 | 학습 없는 encode/decode에서 손실, 공식 다른 encoding 대조 |
| 학습량 | 설정 영향 확인 | native 14 epoch 상한과 상한만 해제한 대응 학습 |
| 생성 순서 | 설정 영향 확인 | 같은 가중치·고객별 길이에서 merchant/category 오차 감소 |
| 이력 표현 | 사용됨을 확인, 구조적 부족은 미확정 | 실제 prefix, 이력 제거·가맹점 교란 진단 |
| 희귀 사기 흐름 | 잔여 오류 확인, 학습 원인은 미확정 | 사기 연속 길이·위치와 금액 이력의 구성 대조 |
| 체크포인트 선택 | 검증 변동 확인, 잘못된 선택은 미입증 | 고정 가중치의 window·순서 반복 평가 |
| CPAR 신규 고객 조건 | 입력 지원 제약 확인 | 학습에 없던 지역을 native encoder가 처리하지 못함 |

## 무엇을 생성하고 비교했는가

[Berka 재현](../argn_fraud_audit_v1/BERKA_REPLICATION_RESULTS.md)에서 확인한
공식 engine 1.0.4를 고정했다. 이는 버전을 명시한 재현 기준이며 최신 engine
전체나 모든 ARGN 구현에 대한 결론이 아니다. Sparkov에서는 성별·지역·출생연도·
도시 인구를 조건으로 새 고객 거래열을 생성한다. 각 거래는 간격, 가맹점, 금액,
업종, 정상/사기 라벨을 포함하고 다음 거래는 생성된 과거를 사용한다.

실제 미래 라벨·거래·길이와 `entity_any_fraud`를 조건으로 주지 않았다.
원본 라벨을 거래 필드와 함께 학습한 뒤 생성 라벨과 특성의 결합관계를 직접
평가했다. 사후 탐지기로 라벨을 붙이거나 6:4 같은 비율을 강제하지 않았다.

| 구분 | 고객 | 거래 | 사기 거래 | 사기 비율 |
|---|---:|---:|---:|---:|
| 외부 train | 688 | 916,567 | 5,214 | 0.568862% |
| 개발 validation | 147 | 177,997 | 1,146 | 0.643831% |

ARGN 내부 학습/체크 분할은 619/69명으로 고정했다. CPAR은 native 절차상
688명 모두를 최적화에 사용하므로 유효 학습 자료가 완전히 같은 비교는 아니다.
ARGN codec 통계는 공식 분석 절차에 따라 내부 체크 69명을 포함한 외부 train
688명에서 만든다. 외부 validation 147명은 codec 학습에도 사용하지 않는다.
주 비교는 같은 147명의 validation 정적 속성으로 생성한다. ARGN에는 별도 부모
모델에서 생성한 공통 147개 context로 생성하는 민감도 대조도 포함한다.
독립 test 이벤트는 읽지 않았다. 반복 사용한 validation이므로 탐색 결과다.
행 재표집과 1차 전이 재표집은 정적 고객 속성을 사용하지 않는 진단 대조다.
학습 행을 직접 재사용하므로 관계 보존의 일부 기준을 확인할 수 있지만
개인정보보호를 달성한 생성 모델로 해석하지 않는다.

CPAR의 범주형 context encoder는 학습에서 없던 지역(DE·HI·RI)을 받으면
KeyError를 낸다. 해당 검증 고객은 4명이다. 원래 147명 ARGN 결과를 유지하고,
CPAR과의 비교는 **모든 모델과 실제 자료를 공통 143명으로 제한해** 별도로
계산한다. 지역을 다른 값으로 바꾸거나 validation 범주를 학습에 추가하지
않았다. 제외 기준에는 사기 라벨이나 생성 품질을 쓰지 않았다.
[지원 범위와 사전 변경 기록](CPAR_CONTEXT_SUPPORT_PROTOCOL.md).

기본 AUTO ARGN의 전체 사기 비율은 .443~.683%로 일부 생성은 원본 .644%와
가까웠지만, 아래 관계 오차는 컸다. 12회 학습 고객 재표집 범위는 분할·표본
변동의 참고이며 이론적 최저 오차나 통계적 유의성 기준은 아니다.

| 147명 기준 관계 TV(작을수록 가까움) | 기본 ARGN 4개 생성 | 학습 고객 재표집 12회 |
|---|---:|---:|
| 가맹점–업종 | .730~.779 | .037~.045 |
| 사기 거래의 업종–금액 구간 | .455~.496 | .057~.106 |
| 사기 거래의 간격–재방문–개인 금액비 | .424~.466 | .067~.124 |

## 확인한 원인 1: 학습 전 수치 변환 손실

AUTO는 gap과 amount에 NUMERIC_BINNED를 선택했다. **신경망 학습 없이**
원본 validation을 encode→decode하기만 해도 다음 변화가 발생했다.

| 원단위 통계 | 원본 | AUTO roundtrip |
|---|---:|---:|
| 전체 평균 금액 | 73.36 | 148.75 |
| 사기 평균 금액 | 521.58 | 3,712.33 |
| 사기 금액 p90 | 1,013.73 | 11,924.27 |
| 사기 금액 p99 | 1,172.25 | 14,852.05 |

마지막 금액 구간은 약 539.94~15,305.95로 넓었다. 같은 구간 안에서 값을
다시 뽑으면 라벨은 그대로여도 금액–라벨 관계가 바뀐다. 반면 사기 금액의
거친 분위 구간 TV는 약 .0035여서 이 문제를 거의 드러내지 못했다. 따라서
초기 구간 지표가 작다는 사실을 ‘전처리 영향이 작다’고 일반화하면 잘못이다.
[원단위 평가 보완 기록](AMOUNT_SCALE_PROTOCOL.md), `numeric_metrics.csv`.

gap의 첫 경계도 0, 157, 344, 535초…였다. 원본 0<gap<=5초인 45건에 대해
AUTO roundtrip 10회 결과는 30~51건으로 겉보기 개수는 비슷했지만, 원래 해당
조건이던 거래를 유지한 수는 0~7건이었다. 60초 이내 사기는 원래 5건인데
roundtrip에서는 9~18건이 됐다. 이 결과는 생성물이 원본 행과 일대일로 같아야
한다는 주장이 아니라, **같은 구간 내부의 세부 시간과 라벨 정보를 학습 전에
구별할 수 없게 만든다는 근거**다.

공식 DIGIT gap 설정은 10회 모두 5/60/300/1800초 조건의 소속과 사기 건수를
보존했다. gap·amount 모두 DIGIT일 때 금액은 검증 자료 전체에서 정확히
복원됐고 사기 평균도 521.58을 유지했다. gap 극단값 보호에 의한 한 관측치의
변화는 남았다. 이는 roundtrip 결과이며 **학습 후 생성 품질의 보장은 아니다**.
두 설정 모두 별도 2회 학습으로 생성 품질을 확인했다. DIGIT은 모델 크기와
손실의 numeric subcolumn 수도 바꾸므로 순수 정밀도만 바꾼 neural 비교는 아니다.

5초 조건의 validation 사기는 단 1건이다. 이 셀에서 정확한 모집단 사기율이나
새 방법의 우월성을 결론내릴 수 없다. 건수와 고객 bootstrap 구간을 함께 남겼다.

## 확인한 원인 2: 학습 한도와 생성 순서

engine 1.0.4의 기본 학습 한도는 고객 수에 따라 `ceil(688/50)=14 epoch`로
제한됐다. 단순히 큰 max_epochs를 전달해도 이 상한이 적용된다. 상한 계산
한 줄만 격리해 바꾼 대조에서는 동일한 데이터·모델·옵티마이저·window 100·
검증/early stopping을 유지했다. 설치 라이브러리는 변경하지 않았다.

기본 두 학습은 14 epoch에서 끝났고 선택된 체크포인트는 14/13 epoch였다.
상한 해제 후에는 native early stopping으로 22/30 epoch에서 끝나 17/25 epoch를
선택했다. 대응하는 첫 14 epoch의 **기록된 학습 이력**은 같았다. 학습량에 따른
개선은 있었지만 ‘충분히 수렴했다’거나 상한이 모든 오류의 원인이라는 뜻은 아니다.

더 분명한 생성 설정 효과도 있었다. **학습된 가중치를 그대로 고정한 채**
업종(category)을 가맹점보다 먼저 생성하자 merchant/category TV가 첫 학습에서
약 .649~.651→.175~.176, 두 번째에서 .410~.411→.153~.154로 줄었다.
같은 seed/context에서 고객별 생성 길이도 동일했다. 이 변화는 새 학습 데이터나
긴 학습 때문에 생긴 것이 아니다. 반면 label을 먼저 생성하는 설정은 일부
관계를 바꾸지만 전체 사기 비율을 낮추기도 해 모든 지표의 개선책은 아니었다.

ARGN의 flexible order를 이용한 기존 설정 대조이며 새 모델 기여가 아니다.
기본값이 이 데이터의 가맹점–업종 관계에 불리했다는 증거다. 내부 학습 자료
619명에서 만든 가맹점별 최빈 업종 조회는 validation 업종의 99.218%를 맞춘다.
이 조회는 관계가 강하게 존재함을 확인하는 진단이며 거래열 생성 모델은 아니다.

## 오류는 언제 나타났으며 이력은 사용되는가

기본/상한 해제 AUTO 결과에서는 첫 거래부터 학습 자료에 없던 merchant/category
조합이 나왔다. 이후 위치에도 문제가 남았다. 첫 위치는 고객당 한 건뿐이므로
TV 자체의 크기를 장기 구간과 단순 비교하지 않고, 학습에 없던 조합 비율과
실제 자료의 대응 통계를 함께 확인한다. `positions.csv`에 위치별 표본 수가 있다.

실제 과거를 제공하는 고정 가중치 진단에서도 기본 모델의 업종 정확도는
약 51~55%, 상한 해제 후에는 약 64~85%였다. 현재 가맹점 정보를 고객 간
섞으면 크게 악화되고, 첫 거래 이후 이력 표현을 0으로 만들 때도 악화됐다.
따라서 모델이 가맹점이나 이력을 전혀 쓰지 않는다고 말할 수 없다.
동시에 실제 과거에서도 남는 오차가 있으므로 긴 rollout의 누적 오차만으로
모든 문제를 설명하기 어렵다.

이 진단은 실제 prefix 최대 512개와 native 실제 길이 positional encoding을
사용한다. 온라인 사기 탐지기 성능이나 자유 생성 성능으로 부르면 안 된다.
이력 표현을 제거한 민감도 실험은 표현을 더 크게 만들면 원래 문제가 해결될
것이라는 인과적 증거도 아니다.

## 고객 구성과 평가 변동에서 주의할 점

학습 자료에는 거래 100건 이하 고객 52명, 합계 507건이 있고 모두 사기였다.
이들의 실제 길이는 7~15이고 다른 고객의 최소 길이는 471이었다. validation은
해당 고객 12명/132건이며 19건짜리 고객도 있다. 생성 결과에 16~470 길이가
나오는 경우, `길이<=100`의 사기율 차이는 라벨 모델만 아니라 길이·고객 구성
변화의 영향을 받는다. 실제 총 길이는 미래 정보이므로 생성 조건으로 넣지 않았다.

거래별 사기율 0.5689%와 고객별 사기 비율을 동일 가중 평균한 8.2084%는 다른
양이다. 짧은 사기 전용 고객 때문에 차이가 크다. 고객 단위 학습 가중과 거래
단위 평가의 차이는 가능한 기전이지만, 가중만 바꾼 대조를 하지 않았으므로
확정 원인이라고 부르지 않는다.

고정된 네 체크포인트에서 native 검증을 20회 반복하면 무작위 window/열 순서로
loss 표준편차가 약 .07~.14였다. 둘 다 고정하면 0이었다. 이 변동은 checkpoint
선택 해석에 필요하지만 ‘잘못된 epoch를 골랐다’거나 ‘더 학습하면 해결된다’는
증명은 아니다. `validation_noise_*.csv`에 개별 값을 보존했다.

## 전체 비교와 남은 오차

최종 전체 설정의 수치는 [COMPARISON.md](COMPARISON.md), 원단위 수치는
`numeric_metrics.csv`, 조건부 비율과 건수는
`conditional_rates_customer_bootstrap.csv`에서 확인한다. 생성 반복의 최솟값~
최댓값은 기술 범위이며 95% 신뢰구간이나 독립 학습 반복을 늘린 것처럼 해석하지 않는다.

gap·amount를 모두 DIGIT으로 바꾼 뒤 생성한 사기 평균 금액은 기본 열 순서에서
371~539로, AUTO 상한 해제의 2,288~3,558보다 원본 522에 가까워졌다.
category-first에서는 546~650이었다. 그러나 전체 사기 비율은 각각
0.487~2.825%, 0.994~4.165%로 흔들렸다. 따라서 금액 표현의 개선을 전체 관계
보존의 성공으로 부를 수 없다. numeric subcolumn 수와 모델 파라미터도
3,593,840→4,807,342로 변했으므로, 잔여 라벨 오류가 정밀도 자체 때문인지
학습 가중·선택 시점·길이 구성 때문인지는 이 비교만으로 식별되지 않는다.

CPAR은 143명에 대해 각각 17,883 / 17,486건을 생성했다. 같은 원본 고객은
174,879건이며 고객별 길이 중앙값은 1,042건인데, 두 생성 결과는 모두 82건이었다.
전체 사기 비율은 원본 .638%에 비해 1.387~1.441%였다. 사기 구간의 평균 길이는
원본 10.05에서 1.02~1.03으로 짧아졌고, 최대도 2~3건이었다. 일부 DIGIT ARGN의
지나치게 긴 사기 구간과 방향이 다른 오류다. 공통 고객 비교 전체 수치는
[SUPPORTED_COMPARISON.md](SUPPORTED_COMPARISON.md)에 있다.
CPAR의 사기 평균 금액도 68.48~70.42로 원본 518.55와 달랐으며,
merchant/category TV는 .920~.921이었다. 유효한 숫자·라벨이 생성됐다는
형식 검증 통과와 관계 재현 성공을 구별해야 한다.

CPAR은 SDV 1.38.0/DeepEcho 0.8.1, 128 epoch, full sequence, 1회 학습이다.
native 연속형 손실은 전역 패딩 배열의 뒤쪽 `length_i`개 target을 사용하고,
범주형/결측 target은 앞쪽을 사용하는 구현을 유지했다. 이 정렬 관례를
임의로 수정하지 않았으며 CPU 가속은 같은 loss와 gradient를 내는지 검사했다.
그러므로 수치 결과가 나쁘다고 CPAR 구조 자체의 능력 한계로 일반화해서는
안 된다. 128회도 기본 설정에 따른 실행이지 수렴·최적화 완료의 증명은 아니다.
CPAR은 같은 현재 상태에서 거래 필드들을 각각 샘플링하며, 현재 뽑힌 가맹점이나
라벨을 다른 현재 필드에 다시 넣지 않는다. ARGN의 행 내부 순차 조건화와 다른
구조다. 이 차이는 진단 후보이지만 이번 수치 오류 전부의 원인으로 입증한 것은 아니다.

### 추가로 좁힌 잔여 문제: 사기 연속 구간과 개인별 금액 이력

원단위 평가 뒤 별도로 등록한
[사기 연속 구간 진단](FRAUD_RUN_DIAGNOSTIC_PROTOCOL.md)에서는 원본 train의
533개, validation의 114개 관찰 구간 모두 길이가 최대 19였다. validation의
평균은 10.05였다. 이는 관찰 창 안의 길이이며 실제 사기가 항상 19건 이하라는
보편적 제약을 뜻하지 않는다. 처음/마지막 관측 거래에 닿은 구간 수도 기록했다.

gap·amount DIGIT의 기본 순서는 가장 긴 구간이 생성 반복별 101~3,008건,
category-first는 172~2,677건이었다. 각각 사기 거래의 31.8~79.5%,
55.1~83.4%가 연속 사기의 21번째 이후에 있었다. 원본 두 분할에서는 0%였다.
긴 사기 구간에서는 ‘직전 20회 금액 중앙값’ 자체가 사기 거래들로 구성될 수
있어, 평균 사기 금액이 가까워도 평소 이력 대비 금액 관계는 달라진다.

이를 구분하려고 연속 사기의 위치를 1 / 2~5 / 6~10 / 11~20 / 21+로 나눴다.
생성 표본의 위치 구성을 원본 비중으로 **평가 안에서만 재가중**했을 때,
금액/이력 비율의 log-W1은 DIGIT 기본 순서에서 원래 1.035~1.157에서
.589~.945로, category-first에서는 1.158~1.227에서 .653~1.043으로 줄었다.
하지만 원본 train-vs-validation .038보다 여전히 컸다. 구성 차이가 관련됨을
보이는 기술적 분해이며, 라벨을 바꾸면 오차가 인과적으로 그만큼 줄어든다는
실험은 아니다. 생성 라벨·금액·출력 행은 수정하지 않았다.

따라서 이후 검증해야 할 구체적인 문제는 **사기 금액 분포만이 아니라 사기
시작·지속·종료와 개인별 금액 이력이 함께 보존되는가**다. 왜 긴 사기 구간이
생겼는지는 손실 가중, 길이 조건 학습, 검증·체크포인트 선택, 이력 표현 등
후보가 남아 있으며 구조적 한계로 확정하지 않았다. 전체 개별 값은
`fraud_run_summary.csv`, `fraud_run_age_bands.csv`에 있다.

## 이 단계에서 확정하지 않은 것

- 희귀 상황의 모든 오차가 ARGN 구조의 한계라는 주장, 또는 모든 원인을 찾았다는 주장.
- 공식 DIGIT이나 열 생성 순서 변경을 새로운 제안 모델이라고 하는 주장.
- 아직 설계·검증하지 않은 CS-SAF가 ARGN보다 낫다는 주장.
- 재사용한 개발 validation, ARGN 2회/CPAR 1회 학습으로 SOTA 순위를 확정하는 주장.
- 전체 이력의 모든 관계, 절대 시각·위치, 사기 탐지 유용성, 개인정보보호를 검증했다는 주장.

다음 방법을 설계할 때는 이번 전처리·설정 오류를 통제한 기준에도 남는 관계
오차를 먼저 목표로 삼아야 한다. 현재 증거만으로 특정 새 구조가 정답이라고
정하지 않는다. Sparkov는 시뮬레이션 자료이므로 실제 금융기관의 사기 기전을
보존했다는 일반화도 별도 자료와 검증이 필요하다.
