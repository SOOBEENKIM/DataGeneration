# ibm_merchant_memory_v1 — 고객 이력 참조형 가맹점 생성: 상태 조건부 반복/새로움 게이트 + 과거 가맹점 포인터 + 사기 공유 풀 (등록 2026-11-09, 실행 전)

## 0. 설계 대상과 근거 ([fraud_structure_v1](../fraud_structure_v1/RESULTS.md) 설계 대상 1)

데이터 구조(IBM 2013 train): 정상 행은 고객이 **이미 간 가맹점을 반복**(새 가맹점 비율 .08), 사기 행은 **새 가맹점**(.55, 6.6배)이며 사기
가맹점은 **고객 간 공유 풀**(191개 가맹점이 사기 1,303행을 냄; 사기 가맹점의 .74가 둘 이상 고객에 등장, 정상 .22; dev 사기 가맹점의 .97이
train 사기 풀 안). 남은 문제의 증거: ARGN+현재 모델은 정상 행 새 가맹점 .33(고객 습관 부재), 사기 .34(사기/정상 대비 1.0 vs 실제 6.6),
고객당 가맹점 수 376 vs 실제 91–95, 공유 풀 .26(뒤집힘) — 바닥 8.8배. RTF+현재 모델은 정상 .07은 맞추나 사기 .21(14.4배).
backbone 원인: ARGN은 가맹점 25,088개 중 15,678개를 `_RARE_`로 병합하고 9,411 코드의 범주 예측으로 내며, LSTM 이력은 "이 고객이 어디를
갔는가"를 코드 단위로 보존하지 못한다(이력 참조 기제 없음). 효용과의 연결: 등록된 TSTR 분류기(`fraud_utility_v1`, `stable`)의 특징에
`seen_merchant`·`seen_merchants_5`가 있어, 새로움 구조가 깨진 합성 데이터는 탐지기에 그 신호를 가르치지 못한다 — 가맹점 축이 효용을
막는 경로가 명시적이다.

## 1. 부품 (동결 backbone 위 생성 시 모듈; 새 학습은 표 추정 수준)

행 t의 상태 s_t(정상/사기 + 구간 나이, 전이표가 정함)가 주어졌을 때 가맹점 m_t를:

1. **게이트** g = P(새 가맹점 | s_t, 위치 구간) — train에서 (라벨, log 위치 구간 6개)별 비율로 추정한 **표**(해석: "이 거래가 습관인가
   새로움인가"의 확률, 데이터 .08/.55와 직접 대조).
2. **반복 가지**(1−g): 그 고객의 과거 가맹점 집합 위 분포 — 빈도 가중 vs 최근성 가중(Anderson 2014의 멱법칙 커널) 중 **train 고객 10%
   hold-out 로그가능도**로 하나를 고르고(또는 혼합 1개 파라미터), 선택을 기록한다.
3. **새로움 가지**(g): 정상 상태 → backbone 가맹점 분포에서 **과거 가맹점을 마스크**하고 재정규화해 표집; 사기 상태 → 확률 π로 train 사기
   공유 풀(빈도 가중)에서, 1−π로 마스크된 backbone 분포에서 표집. π = train 사기 새 가맹점 행 중 풀 안 비율(train 내부 추정, dev 미사용).

backbone 가중치·라벨 과정·다른 열은 그대로다(가맹점 선택이 바뀌면 이후 열은 backbone이 그 값에 조건부로 낸다). RTF는 가맹점 토큰
위치의 LogitsProcessor로 같은 세 단계를 적용한다(과거 가맹점 토큰 집합은 생성 토큰에서 추적).

## 2. 가장 가까운 선행 (2026-11-09 재검색 4회)

| 요소 | 선행 | 겹침 | 차이 |
|---|---|---|---|
| 반복/탐색 게이트 + 과거 항목 포인터 | RepeatNet(Ren et al., AAAI 2019): 세션 추천에서 repeat/explore 모드와 이력 위 포인터 | 구조 동일(게이트 + 이력 분포 + 전역 분포) | 추천(다음 항목 예측 정확도)이 목적; 우리는 **라벨 상태가 게이트를 조건화**하고 합성 데이터 충실도·TSTR로 평가, 동결 생성기 위 모듈 |
| 재소비 역학 | Anderson et al.(WWW 2014) 최근성 멱법칙 재소비; Benson et al.(WWW 2016) 전체 소비열 생성 모형(새로움 확률 + 최근성 가중 반복) | 반복 가지의 커널, "열 생성" 관점 | 라벨 상태 없음, 다른 열과의 결합 없음; 우리는 다변량 거래열의 한 열에 적용 |
| 복사/포인터 기제 | Vinyals 2015 pointer networks; Gu 2016 CopyNet; See 2017 pointer-generator | 입력(과거) 복사 vs 생성 혼합 | 텍스트; 우리는 표 열의 고카디널리티 범주 + 상태 조건부 |
| 사기 합성의 반복 진단 | 2604.13125(Sajja 2026): 합성 사기 행의 device 반복 등 behavioral fidelity 진단 | "반복 구조가 깨진다"는 관측 | 처방 없음; 우리는 처방 + 효용 연결 |
| 합성 거래 생성기의 가맹점 | TabularARGN(희귀 병합 범주), REaLTabFormer(토큰), TransactionGPT·FPM 2401.01641(임베딩 목적) | 가맹점을 범주/토큰으로 생성 | 이력 참조 기제 없음(읽은 범위) |

읽은 범위에서 **합성 거래열 생성기에 라벨 상태 조건부 반복/새로움 가맹점 기제를 넣고 충실도·효용으로 평가한 논문은 없다**(없다고 단정하지 않음).
RepeatNet·Benson 2016은 관련 연구에 개념적 선행으로 적는다.

## 3. 가설과 사전 판단 (바닥 배 = fraud_structure_v1·1단계 바닥 중앙값 대비, fit 2 × 생성 2 평균; 효용 fit 평균)

- **H1 (구조 복구).** `full` 팔에서 새 가맹점 비율(사기·정상 각각) 바닥 배 ≤ 3, 공유 사기 가맹점 ≤ 3, 1단계 `S_merchants_per_customer`
  ≤ 3(현재 ARGN 수십 배). 하나라도 ≥ 3이면 그 항목의 원인(게이트/포인터/풀)을 ablation으로 특정해 기록.
- **H2 (효용).** ARGN `full` 효용 ≥ **.25**(현재 .142; 사용자 목표). .20–.25면 "부분", < .20이면 "가맹점 새로움은 이 탐지기의 효용 경로가
  아님"으로 기록하고 세 번째 구조(ARGN 구간 내 간격)로 간다.
- **H3 (ablation = 설명).** 사기 새 가맹점 절대차에서 `full` < `gate_only` < `repeat_blind` 순이어야 "상태 조건부 게이트"와 "사기 풀"이 각각
  필요함이 보인다. `repeat_blind` ≈ `full`이면 상태 조건화 불필요로 기록.
- **H4 (대조).** 라벨 과정 지표(지속률·구간 수·24h 구간)·가맹점 무관 표준 지표 변화 ≤ .01; 새 업종·진입 금액비 비악화. 위반 팔은 무효.
- **H5 (backbone 불문).** ARGN에서 H1 충족 시 RTF `rtf_full` 실행: 사기 새 가맹점 ≤ 3배, 효용 ≥ .50(현재 .448). ARGN H1 미충족이면 RTF는
  하지 않고 원인부터 기록.

## 4. 설계

| 팔 | 게이트 | 반복 가지 | 새로움 가지 | 생성 |
|---|---|---|---|---|
| 참조 `routed_subst_table`(현재 모델) | — | — | backbone | 기존 4 |
| `repeat_blind` | 라벨 무시, 위치만 | 포인터 | backbone 마스크 | 4 |
| `gate_only` | 상태 조건부 | 포인터 | backbone 마스크(풀 없음) | 4 |
| `full` | 상태 조건부 | 포인터 | 정상: 마스크 backbone / 사기: 풀 π + 마스크 backbone | 4 |
| `rtf_full` (H5 조건부) | 상태 조건부 | 포인터 | 위와 같음, LogitsProcessor | 4 |

- 동결 fit: ARGN `native_20261108/09` + `routed_subst_{fit}` head + 전이표(현재 모델 그대로), RTF fit 20261108/09 + 전이표. 생성 seed 20261011/12.
- 추정(모두 train만): 게이트 표, 포인터 커널 선택(hold-out LL), π, 사기 풀 분포. dev는 보고 전용, 봉인 test 미읽음.
- 평가: fraud_structure_v1 지표(바닥 재사용) + 1단계 지표(`run_rare_state_persistence.py --dataset ibm`, 등록 추가) + 효용(`stable`).
- 하지 않는 것: backbone 재학습, 업종 열 적용(가맹점 결과 뒤 수정안으로), Sparkov(가맹점 풀 693개라 구조 약함), 구간 내 간격.
- 예산: 추정 < 1분, ARGN 생성 12(각 ~1–2분), RTF 생성 4(각 ~30분). 총 ≤ 3시간.
- 스크립트 `scripts/run_ibm_merchant_memory.py`, 모듈 `benchmarks/argn_merchant_memory.py`(+ `rtf_ibm_module.py` 확장).
