# ibm_state_first_v1 — "State-First" 생성 원리의 일반화: 학습 가능한 상태 과정 + K-상태 라우팅 (등록 2026-11-09, 실행 전)

## 0. 승격하는 주장

지금까지의 모듈(동결 backbone + 전이표 + 라벨 라우팅 사기 전용 head)은 사실상 다음 분해를 **분리된 파라미터로, 상태를
먼저** 생성하는 설계다:

> p(시퀀스) = Π_t p(상태_t | 상태 이력) · p(출력_t | 상태_t, 이력)

사용자는 2026-11-09 이것을 부품 모음이 아니라 **"State-First Sequence Generation" 설계 원리**로 승격해 모델 기여로
주장하기로 했다. 그러려면 지금의 최소 인스턴스(전이표 = 상태 과정 계수 ~130개, 라벨 2값 라우팅)가 **일반화되는지**를
보여야 한다: (1) 상태 과정을 학습 가능한 모델로 바꾸면 전이표가 남긴 배분 축(고객당 구간 수 3.2배, 24h 구간 수 10.6배)이
더 닫히는가, (2) 라우팅을 라벨 2값에서 **상태 K개**(사기 진입 / 사기 지속)로 늘리면 전이표+2값 라우팅이 남긴 출력 축
(사기 간격 W1 2.3배)이 닫히는가, (3) 그 결과 효용이 상한(.61)에 얼마나 다가가는가. **전이표·2값 라우팅이 이기면 "단순한
인스턴스가 충분하다"로 되돌아가며 그것도 결과로 기록한다.**

## 1. 관측 오류와 근거 (이 단계가 겨냥하는 남은 축)

[ibm_routed_heads_v1](../ibm_routed_heads_v1/RESULTS.md) 모듈(`routed_subst_table`, ARGN, 바닥 배): 지속률 .6, 사기 고객 .4,
나이 1 종료 .9 — 닫힘. **남은 것**: 고객당 구간 수 3.2, 24h 구간/고객 10.6, 사기 간격 W1 2.3, 사기 금액 W1 2.3, 효용 .14/.61.
[ibm_realtabformer_v1](../ibm_realtabformer_v1/RESULTS.md) RTF+전이표: 고객당 구간 수 1.9, 24h 구간 4.7, 효용 .45.
[ibm_baselines_v1](../ibm_baselines_v1/RESULTS.md): 표준 처방 5종 효용 ≤ .04, 전이표는 모든 fit에서 배분 복구.
진단: 전이표는 (직전 라벨, 구간 나이, 과거 사기 여부)만 보므로 **고객당 구간 수와 구간 간 간격을 통제할 정보가 없다**
(과거 사기 횟수·마지막 사기 이후 경과를 모름). 2값 라우팅은 **진입 행과 지속 행을 같은 head로** 내므로 IBM의 "구간 내 간격
34분 / 진입 간격 정상 수준" 이중 구조를 한 분포로 섞는다.

## 2. 가장 가까운 선행 (2026-11-09)

| 요소 | 선행 | 겹침 | 차이 |
|---|---|---|---|
| 상태 과정 먼저 → 상태 조건부 방출 | HMM/HSMM·regime-switching 생성, marked point process(상태 조건부 mark) | 분해 형식 | 선행은 잠재 상태·끝까지 공동 학습; 우리는 **관측 라벨 상태**를 동결 backbone 밖에서 명시 모델링 |
| 상태 조건부 분리 head | 행 단위 정상/사기 분리 생성(FraudDDPM, EmDT 2603.13566), long-tail decoupled heads | 사기를 별도 파라미터로 | 순차 자기회귀 안에서 **상태(진입/지속)별** 라우팅, backbone 동결 |
| 학습 가능한 전이 | 자체 Sparkov 전이 head(`argn_gap_episode_v1`), 생존/위험 모델 | 라벨 이력 → 다음 라벨 | 라벨 이력 통계(횟수·경과)를 특징으로 하는 **backbone 외부** 분류기, 두 backbone에 같은 것 적용 |
| 진단 벤치마크 | 2604.13125, 2607.21636 | 표준 지표가 가림 | 둘 다 처방 없음 |

## 3. 가설과 사전 판단 (바닥 배 = 1단계 바닥 중앙값 대비, fit 2 × 생성 2 평균; 효용 fit 평균)

- **M1 (학습 상태 과정 > 전이표).** 라벨 이력 특징(직전 라벨, 구간 나이, 과거 사기 여부, **과거 사기 횟수, 마지막 사기 이후
  사건 수, 위치**) → P(사기) 분류기(HistGradientBoosting, train 라벨열만)로 전이표를 대체. 채택: 고객당 구간 수 **와** 24h
  구간 수 비율이 전이표 팔의 절반 이하이고, 지속률·사기 고객·나이 1 종료가 1.5배 이내 유지, 표준 지표 변화 ≤ .01, 효용이
  전이표 팔보다 .02 이상 낮지 않음. 기각이면 전이표를 상태 과정으로 유지하고 "상태 과정은 저차원으로 충분"을 기록.
  RTF에도 같은 분류기를 LogitsProcessor로 적용해 backbone 불문 여부를 본다(`rtf_learned`).
- **M2 (K-상태 라우팅 > 2값).** 사기 행을 **진입(직전 라벨 정상 또는 첫 사건) / 지속(직전 라벨 사기)** 두 상태로 나눠 각각
  별도 head 복사본(`state_regressors/predictors[s]`), 사기 행만·치환 학습(`routed_subst` 규칙). 채택: 사기 간격 W1 ≤ 1.5배
  이고 사기 온라인·금액·업종이 2값 팔보다 나빠지지 않으며 효용 +.03 이상. 기각이면 "출력 분리는 라벨 2값으로 충분".
- **M3 (모델 주장).** State-First 최선 팔(ARGN)의 효용이 **≥ .30**(상한의 절반)이면 "강", **≥ .20**이고 M1 또는 M2 채택이면
  "충분" — 이때 기여 C를 "State-First 생성 원리(학습 가능한 상태 과정 + 상태별 라우팅, backbone 동결)"로 주장한다.
  RTF `rtf_learned` ≥ .45(전이표와 동등 이상)이면 원리의 상태 과정 부분이 두 backbone에서 성립. **둘 다 미달**이면 모델
  주장은 최소 인스턴스(전이표 + 2값 라우팅)에 한정하고 논문 형식은 진단+평가+최소 처방으로 되돌린다.
- **M4 (대조).** 어떤 팔에서도 정상 행 출력·표준 지표는 변하지 않아야 한다(≤ .01). 변하면 그 팔은 무효.

## 4. 설계

데이터·분할·평가는 이전 단계 그대로(IBM 2013, dev 240, 봉인 test 미읽음, 바닥 200회 재사용, `stable` 효용). 동결 fit:
ARGN `native_20261108/09`, RTF fit 20261108/09. 생성 seed 20261011/12. 스크립트 `scripts/run_ibm_state_first.py`,
모듈 `benchmarks/argn_state_first.py`.

| 팔 | 상태 과정 | 출력 라우팅 | 새 학습 | 생성 |
|---|---|---|---|---|
| `table_r2` (참조 = 기존 `routed_subst_table`) | 전이표 | 2값(기존 head) | 0 | 기존 4 |
| `learned_r2` | **학습 분류기** | 2값(기존 head 재사용) | 분류기 1 | 4 |
| `table_r3` | 전이표 | **진입/지속 2-상태 head** | head 2(fit별) | 4 |
| `learned_r3` | 학습 분류기 | 2-상태 head | — | 4 |
| `rtf_learned` | 학습 분류기(LogitsProcessor, 창 간 이월) | 없음(RTF 원형) | 0 | 4 |

- 상태 분류기: train 1,000명 라벨열만으로 특징 6개 → HistGradientBoostingClassifier(기본값, 조기 종료 없음, `max_iter`
  200, seed 20261109). 평가: development 라벨열 teacher-forced log-loss를 전이표와 비교해 기록(선택에는 쓰지 않음).
  생성 시 메모리를 (n, prev, age, ever, n_frauds, since_last)로 확장해 매 스텝 predict_proba.
- 2-상태 head: `attach_state_heads` — 라벨 임베더 pre-hook에서 (trn) 라벨열 shift로, (gen) 모듈 메모리의 직전 라벨로
  상태를 정한다. 학습은 `train_routed_heads`와 같은 규칙(사기 행만, 치환 p=1, lr 1e-3, 열별 조기 종료, 최대 100 epoch),
  상태별 head는 해당 상태 행만으로 학습. 라우팅 열: gap·amount·category·use_chip(가맹점 제외, 이전과 동일).
- 하지 않는 것: backbone 재학습, 하이퍼파라미터 탐색, 가맹점 축, 비교군 재실행, 봉인 test.
- 예산: ARGN head 학습 2회(각 ≤ 10분), 생성 12회(각 ~1분), RTF 생성 4회(각 ~27분). 총 ≤ 3시간.

## 수정안 1 — 상태 분류기 설정 (2026-11-09, 분류기 적합 직후·생성 전)

기본 설정 HistGradientBoosting(max_iter 200, 정규화 없음)은 **발산**했다: train 정확도 .9974가 기저율(.9988)보다 낮고
P(사기 | 직전 사기)가 0(관측 .62), dev teacher-forced 사기 행 log-loss 13.5(전이표 1.59). 원인은 극단 불균형에서 순수 잎의
작은 헤시안이 만드는 거대한 잎값(Newton step)으로 판단한다. 수정: 후보 3개(기본, l2 1·lr .05·min_leaf 50, l2 10·lr .02·
min_leaf 100·depth 4)를 **train 고객의 10% hold-out log-loss**로 고른 뒤 전체 train으로 재적합한다. development는 선택에
쓰지 않는다(보고만). 발산한 모형의 기록(`STATE_PROCESS.json` 첫 버전)은 `STATE_PROCESS_default_diverged.json`으로 보존한다.

## 수정안 2 — 2-상태 라우팅의 생성 시 마스크 형상 오류 (2026-11-09, 1차 생성·평가 후)

`table_r3`·`learned_r3`의 1차 생성(각 fit 2 × 생성 2)은 사기 출력이 원형과 동일했다(사기 온라인 비율 바닥 19.7배, 효용 .001–.002).
원인: 생성 시 라벨 코드가 (B,1)로 들어오는데 상태 마스크에 끝 축을 붙이지 않아 (B,1,H) 출력과 (B,B,H)로 브로드캐스트됐고,
엔진이 마지막 행을 취하면서 라우팅이 배치 마지막 고객의 상태를 따랐다(사실상 항상 원형 head). 학습 경로(B,T,1)는 영향 없음
(항등 검사 통과, head 학습 정상). 수정 후 두 팔을 다시 생성한다. 1차 생성물은 `runs/<arm>_<fit>_bug1/`로 보존한다.
