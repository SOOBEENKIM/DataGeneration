# Berka 기준 실험: 새 학습 1회 완료

2026-09-27. 이전 Sparkov 감사 전에 Berka 논문 재현을 완료하지 않았던 순서를 바로잡았다. **이번에는 저자 공개 생성물 5회분을 재평가하고, 원본 Berka로 부모·자식 모델을 새로 학습·생성한 1회 결과까지 확인했다. 새 생성물의 분포 점수는 원문 보고 범위 안에 있다.**

이 결과를 ‘Berka와 같은 설정으로 Sparkov를 실행하면 실패한다’는 증거로 사용할 수 없다. 이전 Sparkov와는 공식 패키지 버전, 부모 생성 여부, 배치와 내부 데이터 처리 등이 달랐다. [조건 비교표](BERKA_SPARKOV_COMPARABILITY.md).

## 데이터와 학습

- 원본: 저자 저장소 commit `97781f9cab4ef91e347dfc31650e38ef8dcf2e56`의 계좌 **2,250개**, 거래 **526,442행**. 공개 외부 holdout은 학습·이번 accuracy 평가에서 읽지 않았다.
- 공식 engine **1.0.4**, QA **1.5.3**, torch **2.5.1 CPU**, seed **20260927**. 설치 소스는 공식 wheel과 동일함을 확인했고 기존 Sparkov 환경은 변경하지 않았다.
- 원본 부모 테이블을 학습해서 합성 부모 2,250개를 만들고, 실제 부모·거래로 학습한 자식 모델에 그 합성 부모를 제공했다. 날짜 문자열·원래 행 순서·원래 필드를 보존했다.
- 부모: 마지막 24 epoch / 선택 19 epoch, 3,024 updates. 검증 기준 조기 종료. 학습 약 9.45초.
- 자식: 마지막 **45 epoch / 선택 43 epoch**, **5,670 updates**. 학습 약 **20.76분**. 이 버전은 입력 계좌 수에 따라 기본 100 epoch를 `ceil(2250 / 50) = 45`로 자동 제한한다. 따라서 자식은 **native epoch 상한**으로 종료됐으며, 조기 종료로 수렴을 입증했다고 쓰지 않는다. 300분 시간 상한에는 닿지 않았다.
- 생성: 계좌 **2,250개**, 거래 **522,392행**. 중복 주 키·연결할 부모가 없는 거래·거래가 없는 계좌는 모두 **0**. 거래 생성 약 45.56초. CPU와 패키지 차이가 있어 원문 GPU 시간과 속도 우열을 비교하지 않는다.

## 재현 범위와 남은 확인

공개 저장소에는 정확한 engine/QA 버전 고정과 Berka 전용 학습·순차 평가 스크립트가 없다. 따라서 **당시 공식 버전과 공개 데이터·절차에 기반한 재현**이며, 저자의 모든 설정이 동일함을 증명한 완전한 재현이라고 부르지 않는다. 새 학습은 1회이고 DCR/privacy는 평가하지 않았다.

QA 1.5.3의 공개 연속 거래 추출 코드는 임의 위치가 아니라 첫 두 거래를 선택한다. 독립 fixture로 이를 확인했다. 사전에 구분한 임의 인접 쌍 평가에서는 저자 5회 평균 overall .8832 / coherence .9086, 새 실행 .887 / .909였다. 이때 참조 구간도 달라지므로 이 차이만으로 초기 상태나 누적 오차의 원인을 확정하지 않는다.

공개 생성물과 새 생성물 모두 개설일의 2,247 / 2,250개가 `_RARE_`다. 원본 문자열을 범주형으로 처리한 결과와 일치하는 현상이다. 새 거래에는 해석할 수 없는 날짜 99행, 저장 순서상 알려진 날짜가 전 거래보다 이른 경우 41,402행도 있다. **표의 점수가 비슷하다는 사실은 시간·금액·고객의 모든 관계가 보존됐다는 뜻이 아니다.** 원문 대조를 위해 이를 삭제·정렬·보정하지 않았고, 이런 현상을 ARGN 구조의 필연적 한계로 단정하지 않는다.

앞선 실행 시도 두 건은 캐시 쓰기 경로와 키 자료형 호환 문제에서 멈췄다. 값을 바꾸거나 모델을 수정하지 않고 해결했으며 실패 manifest도 보존했다. hyperparameter를 탐색해 가장 높은 점수를 선택한 결과가 아니다.

## 다음 대조의 기준

Berka에서 기본 학습·생성·평가 흐름이 작동한다는 실증 기준을 확보했다. 다음 Sparkov 대조는 공식 버전, 부모→자식 생성 절차와 기본 설정을 명시적으로 고정하고, 데이터 특성상 필요한 필드 처리와 라벨 추가를 구분하는 단계다. 이전 Sparkov 오류를 곧바로 ARGN의 구조적 한계 또는 새 모델 기여로 연결하지 않는다.
