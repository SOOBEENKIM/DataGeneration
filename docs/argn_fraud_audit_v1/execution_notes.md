# 실행·해석 기록

- 2026-09-26~27, Linux 워크스테이션 CPU. 호스트 RTX3090 4개가 모두 약20.8GiB/100% 사용 중임을 읽기 전용으로 확인했다. 다른 작업을 종료하지 않았다. 각각 torch/OMP/MKL thread4로 두 학습을 실행했다. Mac GPU 이식은 하지 않았다.
- GitHub `SOOBEENKIM/DataGeneration`의 기존 ARGN 연구 브랜치와 로컬 출발점 `c1463e52f3d5785d25dcd78a82c553d2c13e804e`가 일치했다. 공식 A와 기존 대조·실패 기록을 보존할 근거가 있어 삭제하지 않았다. 이번 코드는 별도 worktree/branch다.
- 최초 과거 생성물 감사는 pandas nullable numeric dtype 처리 오류로 완료되지 않았다. 숫자형을 float/NaN으로 정규화하고 회귀 검사를 추가한 뒤 감사를 다시 실행했다. 새 신경망 학습은 이 수정 commit `2ccc01e` 이후에 시작했다. 이 기술 수정은 seed나 학습 설정 탐색이 아니다.
- 준비된 codec은 fit 고객550명에서만 추정했다. `analyze`가 기본적으로 내부 check까지 읽는 것을 피하기 위해 새 workspace의 check 파티션을 잠시 이동하고 복구했다. check의 **고객 수**만 학습 메타데이터에 등록했다. target 통계 열 hash, 원본 역할표/입력 hash와 공식 소스 hash를 남겼다.
- 두 새 기준 모델은 native train/early-stop/checkpoint 선택을 사용했다. 논문 수치를 재현했다고 부르지 않는다. 라벨 추가 외에도 window, flexible generation, value protection, codec fit 범위와 생성 고객 조건이 과거 파일럿과 달라져, 과거 대비 차이를 라벨 또는 새 구조의 단독 효과로 해석할 수 없다.
- 실제 이력 예측 진단에서 현재 merchant의 column embedding만 교란했다. gap/merchant 자신의 예측이 그대로인지, history 출력 제거가 첫 거래 예측을 바꾸지 않는지 검사했다. 조회표 진단은 첫 과거 A 결과를 본 뒤 추가한 탐색 검사다.
- 설치된 공식2.4.0 손실은 동일 batch를 복제하면 평균 값이 절반으로 변한다. 실제 같은 체크포인트·동일 내용으로 확인했다. `_calculate_sample_losses`는 거래별 분자를 batch 전체 mask 합으로 나눈 후 batch 평균을 낸다. 따라서 로그의 학습/검증 loss를 직접 per-event NLL로 읽거나, batch64/32의 값 차이를 과적합으로 해석하지 않는다. 이 사실 자체가 관계 오류의 원인이라는 증거는 아니다. 공식 구현은 수정하지 않았다.
- 모든 생성에서 정상/사기 비율을 강제하지 않았고, 미래 전체기간의 사기 여부나 실제 거래열 길이를 조건으로 주지 않았다. 무효 라벨을 삭제하거나 정상으로 고치지 않았다. 시각 자체의 일주기 관계는 이번 gap 기반 입력의 평가 범위 밖이다.
- 최종 test outcomes를 사용하지 않았다. validation은 이전 연구에서도 여러 번 본 개발 자료다. real–real 절반 분할12회는 표본 크기가 다른 참고값이며 독립 확인/유의성 검정이 아니다. 5초 이내의 사기1건은 안정적인 성공 기준으로 사용하지 않는다.
- 단계1의 관찰과 단계2의 일부 원인 배제까지만 입증한다. 충분한 학습·최적화 또는 새로운 생성 방법의 기여를 입증한 것으로 확대하지 않는다. CPAR/IFT-GAN/TabDiT와 라벨 포함 동일 조건의 우월성 비교는 이 실험에 포함되지 않는다.
