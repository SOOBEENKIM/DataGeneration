# ARGN 라벨 포함 기준 모델과 원인 진단 — 실행 기준

2026-09-26. 사용자 지시: 기존 DataGeneration의 ARGN 작업을 감사하고, 관계 오류의 위치·원인을 확인한 뒤 필요한 변경과 대조 실험으로 진행한다. 기존 파일럿의 자동 확장 금지 문구는 그 종료된 실험에 적용한다. 이번은 명시적으로 요청된 별도 연구 단계다.

출발 commit: `c1463e52f3d5785d25dcd78a82c553d2c13e804e`, GitHub `research/argn-relation-pilot-v1`와 로컬 일치 확인. 공식 기반·대조·산술 검증이 존재하므로 전부 삭제할 근거는 없다. 과거 실패 판정을 보존한다. 새 브랜치: `research/argn-fraud-audit-v1`.

## 과제와 데이터

- Sparkov 고객별 거래의 gap, merchant, amount, category, event_is_fraud를 공동 생성한다. 라벨은 범주형 생성 필드다. 정상/사기 비율을 외부에서 강제하지 않는다.
- 정적 조건은 성별, 지역, 출생연도, 도시 인구다. ID는 연결 키다. 미래 전체 기간의 `entity_any_fraud`와 위치는 포함하지 않는다. 시각 자체의 일주기/요일 보존은 이번 gap 모델의 주장에 포함하지 않는다.
- 기존 고객 분할 fit550/check138/validation147을 사용한다. canonical 데이터는 이 고객들만 parquet filter로 읽는다. test outcomes는 읽지 않는다. validation은 여러 번 사용한 개발 자료이며 최종 독립 검증으로 부르지 않는다.
- 새 학습의 codec은 fit 고객만으로 추정한다. 새 workspace의 check 파티션을 analyze 동안 보관했다가 복구하고, 학습용 check 개수만 metadata에 등록한다. check 수치나 어휘로 codec을 맞추지 않는다. 원본 파일과 기존 workspace는 수정하지 않는다.
- 생성 고객 조건은 validation의 정적 정보 전부다. 자연 길이 생성으로, 길이나 비율을 사후 맞추지 않는다. 기존 파일럿의 fit 고객 표본 조건과 다르므로 과거 결과와 차감을 새 구조의 효과라고 주장하지 않는다.

## 출처와 고정 설정

- [TabularARGN v2](https://arxiv.org/abs/2501.12012v2), [공식 mostlyai-engine](https://github.com/mostly-ai/mostlyai-engine), 기존 설치 버전2.4.0. 이것이 2026년 최신 패키지 버전이라는 뜻은 아니다.
- 공식 Medium, window100, flexible generation 활성화, native AdamW·학습률 heuristic·스케줄·조기종료를 그대로 사용한다. 논문과 설치 구현의 early-stop patience 차이(논문5, 코드4)를 기록한다. 새 경로/손실/탐지기 없음.
- 사기 범주를 보존하는지 확인하면서 native value protection을 켠다. 기존 파일럿은 이를 껐고 window32·고정 열 순서를 사용했으므로 새 기준 모델과 설정이 다르다.
- fit seed2개, 각각 generation seed2개. 최대100epoch/30분, batch64, CPU thread4. GPU4개가 모두 약20.8GiB·100% 사용 중이어서 기존 작업을 건드리지 않고 CPU로 수행한다. 새 CPU 학습이 시간 상한에 닿으면 충분한 학습으로 판정하지 않는다.
- 실행 코드/설정/공식 소스/입력/체크포인트 hash와 실제 step·epoch·소요시간을 남긴다. checkpoint는 native check loss로 선택한다. 결과에 따라 이 실행의 seed·예산·판정 기준을 뒤에서 늘리지 않는다.

## 1단계: 어떤 관계가 언제부터 어긋나는가

과거 저장 생성 데이터6개를 독립 재분석한다. 전체·생성 위치(첫 거래,2–32,33–100,101–500,501+)별 merchant–category 관계를 본다. 해당 위치의 고객/거래 수와 fit에 없던 조합의 비율을 원본과 함께 기록한다. fit에 없다는 것을 불가능한 조합이라고 부르지 않는다.

새 라벨 모델에서는 전체 라벨 비율, 정상/사기별 category–amount 및 gap–previous category–category, 과거에 사용한 merchant 여부와 직전20거래 금액 중앙값 대비 현재 금액의 관계를 본다. 과거금액은 shift 후 rolling, 최소5개이며 이력 부족을 별도 범주로 둔다. 조건별 사기 비율과 조건 발생량을 모두 보고한다. 5초 구간의 작은 표본을 숨기지 않는다.

## 2단계: 원인 분리

1. 원본을 native encode→decode해 관계가 얼마나 달라지는지 검사한다. codec 손실과 신경망 생성 오류를 분리한다.
2. 시작 거래부터 관계가 깨지는지, 뒤쪽에서만 커지는지 본다. 위치별 고객 구성·길이 차이를 기록하므로 기울기만으로 누적오차의 인과 증명을 하지 않는다.
3. 실제 이력에서의 모델 예측과 현재 merchant 필드를 교란한 예측을 대조하는 추가 진단을 설계한다. 이는 행 안의 정보 활용을 보는 진단이며 실제 거래의 인과효과가 아니다.
4. 학습곡선·window sampling·선택 손실의 변동을 확인한다. 적은 학습량이나 기본 표현 문제를 새로운 구조적 한계로 포장하지 않는다.

원본 validation을 고객 단위로 반복 분할한 real–real 거리를 비교용으로 함께 제시한다. 이 자료 절반끼리의 차이는 생성 비교와 표본 크기가 달라 참고 수준이며 유의성 검정을 대신하지 않는다. 사기 조건별 표본/고객/양성 수를 전부 공개한다. 미등록 범주·무효 라벨을 지우거나 정상으로 바꾸지 않는다.

## 3–4단계로 넘어가는 조건

사기 라벨을 포함한 기준 생성기가 유효하게 학습되고, 같은 종류의 오류가 반복되며, 진단이 원인을 좁혔을 때 변경 하나를 사전 명세한다. 확인 전에 기존 R 경로를 되살리거나 새로운 모듈을 발명하지 않는다. 일반 같은-용량 변경 및 제안 요소 제거 대조를 포함한다. 충분한 baseline이 문제를 해결하면 새 모듈의 필요성을 주장하지 않는다.

CPAR·TabDiT는 같은 거래열 과제의 비교 후보, IFT-GAN은 사기 증강 및 시간 관계의 가까운 선행연구다. 이번 ARGN 진단만으로 이 모델들 대비 우위를 주장하지 않는다. 단계별 상태와 다음 미해결 작업을 README에 남긴다.
