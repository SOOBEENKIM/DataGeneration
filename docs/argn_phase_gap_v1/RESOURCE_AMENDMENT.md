# GPU 경합 기록: 이동 계획 취소, 원래 실행 완료 — 2026-09-27

**실제 리소스 변경은0건이다.** 아래는 지연 중 작성한 이동 계획이었다.
중단 전에 두 PID의 명령행을 모두 확인하는 안전 검증에서 한 PID가 이미
정상 종료한 것을 확인했다. 검증 이후에만 SIGTERM을 보내도록 되어 있어
어느 프로세스에도 신호를 보내지 않았다. 두 번째 생성도 양쪽 모두 완료돼
이동 계획을 취소했고, 미실행 resume script는 제거했다. 실제 완료 상태는
원래 DISPATCH_COMPLETE.json이며 원래 GPU2·3/프로토콜을 유지했다.

아래의 이동/재시작 서술은 **실행되지 않은 당시 계획**이며 결과 이력이 아니다.

14:10 UTC에 비어 있던 GPU2·3에서 두 부모를 시작했다. 각 첫 생성
(seed20261011)은82초 전후에 완료했다. 이후 다른 사용자의 VLLM 작업이
GPU2·3을 점유하여 두 번째 생성은 수 분간 완료되지 않았다. 타인의 작업은
건드리지 않는다. 이미 완료한 첫 생성과 원래 launch/log/manifest를 보존하고,
우리 worker만 SIGTERM으로 종료한다. 원래 dispatcher의 중단 종료 코드를
성공으로 고치지 않는다.

리소스만 빈 GPU1(UUID GPU-4e575de7-5122-2c13-d12d-9ee15e4a1af9)으로
변경해 두 번째 seed20261012를 부모별로 순차 재시작한다. 원래 PROTOCOL 및
CFG는 소급 변경하지 않는다. 모델, 입력, 조건부 분포, 평가, seed는 동일하다.
전체 generate 호출은 매번 모델을 새로 초기화하며 seed를 다시 지정하므로
완료된 첫 generate를 재실행할 필요가 없다. 중단 도중의 SyntheticData는
uncompleted_native 디렉터리로 보존한 뒤 공식 generate를 다시 호출한다.
첫 번째 보존 parquet hash와 라벨·길이 일치를 다시 확인하고, 두 번째 생성도
기존 기준의 라벨·길이와 정확히 비교한다. 원래 모델 가중치 hash를 유지한다.

별도 resume script와 RESUME_MANIFEST/LAUNCH/COMPLETE에 코드·문서 hash,
GPU 상태, 중단 PID, 시작·종료를 기록한다. 원래 worker의 중단은 실험 팔의
성능 실패가 아니며 결과가 없는 두 번째 draw만 다시 생성한다. 이 변경은
새로운 학습·seed 탐색·최종 test 접근을 추가하지 않는다.
