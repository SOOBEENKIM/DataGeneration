# 현재 조건의 생성 오류가 금액에 전달되는 경로

balanced_shared 두 부모에서6조건×4draw×2,292위치 sampling 완료.
실제 과거와 실제 사기 label을 항상 줬다. 표는 사기1146위치의 두 모델 범위다.

| 현재 거래에서 실제로 주는 정보 | 생성 사기 금액 중앙값 | 사기 금액 log-W1 |
|---|---:|---:|
| 업종·간격·가맹점 모두 |339.27–356.93|.0555–.0889|
| 없음: 세 필드 모두 생성 |217.78–243.28|.8215–.8306|
| 업종만 |341.80–352.03|.0723–.0975|
| 간격만 |214.63–249.70|.8138–.8717|
| 가맹점만 |219.81–266.83|.7521–.8277|
| 업종·가맹점 |341.66–353.11|.0588–.0772|

실제 사기 금액 중앙값은361.07이다. 업종만 실제 값으로 돌려도 금액 분포가
크게 회복된다. **상류 category의 조건부 생성 오류가 금액에 전달되는 경로**를
확인했다. 간격이나 가맹점만의 복원에서는 비슷한 효과가 없었다.

여전히 실제 과거를 제공한 진단이다. 자유 생성과의 남은 차이는 이력뿐 아니라
길이·사기 발생 고객/시점 구성도 포함한다. 단일 인과 원인이나 분산 분해 수치로
해석하지 않는다. 모델이 특정 원본 가맹점이나 업종을 복사해야 한다는 주장이 아니다.

첫 금액 digit의 native/cache logits는 두 모델 합계4,584위치에서 일치했다.
모델·cache hash가 유지됐고 test 거래를 열지 않았다. 개별 결과는 metrics CSV,
완료 근거는 COMPLETE JSON이다. 이 근거로 별도 등록한
[업종–금액 제거 대조](../../argn_category_amount_v1/PROTOCOL.md)를 진행한다.
