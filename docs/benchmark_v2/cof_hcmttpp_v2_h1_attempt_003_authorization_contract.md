# CoF-HCMTTPP-v2 H1 attempt_003 authorization contract

## Meaning of attempt_003

`attempt_003` is the only production attempt admitted by this source state.
It is not an architecture, hyperparameter, threshold, or model-selection
retry. It is the first H1 evaluation that may reach training and validation
after two deterministic implementation failures were corrected:

- `attempt_001` stopped in the initial RQS inverse mathematics before a valid
  training/evaluation result;
- `attempt_002` stopped at the parent/spawn/backend ownership hand-off before
  fit, sampling, evaluation, or the H1 gate; and
- the CPU-synthetic execution-readiness gate then traversed ownership claim,
  spawn serialization, backend attach, H1 build, one finite
  `event_nll -> backward -> optimizer step`, and RQS boundary checks.

Both failed attempt trees, both correction reports, the prior readiness
document, its passed source/relevant-source/boundary identities, and the
current readiness-boundary identity are authorization-bound.

## Exact execution scope

Each authorization owns exactly one dataset cell:

- dataset: `amlsim` or `sparkov`, never both;
- candidate: `H1`;
- seed: `4001`;
- attempt: `attempt_003`;
- requested updates: `20000`; and
- whole-cell wall cap: `7200` seconds.

The runner creates `ownership_attempt_003.lock` and the matching append-only
attempt path. `attempt_001` and `attempt_002` remain immutable. Arbitrary
attempt numbers, generic retry, attempt sweep, early stopping, tuning,
threshold changes, H2, C1-v1 retry, C2-C4, internal test, and Sparkov
fraudTest remain fail-closed.

The official CLI intentionally has no `--device` argument. Each SSH worker
must expose exactly one distinct physical GPU through `CUDA_VISIBLE_DEVICES`;
the backend continues to use logical `cuda:0` without performing a GPU
inventory query.

## Preparation boundary

Plan and dry-run open no frozen NPZ body, import/build no model, query no GPU,
invoke no CUDA path, and write no runtime artifact. Authorization validation
must PASS before data/model/device dependency construction. Cross-dataset
authorization use fails at document identity validation.

Authorization JSON and the SSH/tmux launch plan are append-only provenance
files created only after this source/config/test state is committed. No source
commit may follow their creation.
