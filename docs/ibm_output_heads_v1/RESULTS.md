## 3. 왜 teacher-forced 개선이 생성으로 이어지지 않는가

라벨 경로 분해가 답한다. 재학습된 head가 사기 채널을 내는 조건은 "라벨=1 **그리고** 사기다운 문맥
(짧은 간격·큰 금액·사기 이력)"이다. 자유 생성에서는 간격·금액 head가 사기 조건화를 배우지 못했고(§1)
이력도 생성물이므로, use_chip head가 받는 문맥은 정상 거래의 것이다. 그 조건에서 라벨 1이 주는
P(온라인)은 .22–.29이고, 실제 생성 결과 .33–.34와 일치한다. 즉 **teacher-forced head 재학습은 사기
신호를 라벨 임베딩 경로가 아니라 실제 문맥 상관에 실어 배웠고, 그 문맥은 생성 시 존재하지 않는다**
(노출 편향의 한 형태). 금액·간격의 구간 부호화 head가 사기 조건을 못 배우는 것도 같은 축이다.

## 4. 판정과 함의

- 구간 축(전이표)과 상태별 출력 축은 분리되어 있고, 후자는 **동결 backbone + teacher-forced head 재학습
  으로는 복구되지 않는다**. 남는 설계 후보: (i) 사기 행에서 라벨 외 문맥을 무작위로 가리고 학습해
  라벨 경로에 신호를 강제하는 것, (ii) 간격·금액·채널·업종을 사기 상태에서 **함께** 내는 상태별 출력
  블록(Sparkov `amount_balanced_routed`의 라우팅과 같은 계열), (iii) 생성 시 자기 문맥에서의 학습
  (student forcing). 어느 것도 이 등록 안에서 수행하지 않는다.
- 효용은 상태별 출력이 복구되기 전까지 바닥에 머문다. Sparkov 효용 재측정(사기 금액·간격 W1 ↔ 행
  단독 탐지기 |ρ| .8)과 일치한다.
- 기여 C의 문장은 "전이표(구간) + 상태별 출력 블록"이며, 두 번째 부품의 최소 형태는 아직 없다. 이
  단계의 기여는 부정 결과와 그 원인 분해(라벨 경로 대 문맥 경로)다.
