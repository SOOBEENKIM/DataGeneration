# User-directed MeLD 500-epoch preliminary comparison — 2026-10-02 KST

The user superseded the proposed 600-epoch boundary with 500 epochs. This is a
prospective compute-budget amendment, not a performance-based checkpoint choice.
Original source, protocols, data, vendor and completed comparisons remain frozen.
The old 1000-epoch/100000-update attempt is paused, NOT reported as completed.

## Boundary and preservation

Keep both existing VAE workers (20261021/22) training without changing their loaded
code. A persistent supervisor suspends their original CPU dispatcher to prevent
its automatic final evaluation. At the atomic epoch-500 last checkpoint, suspend
only the identified worker, copy the resumable model/optimizer/RNG state, best
internal checkpoint, curve and status, verify epoch/hash/selection consistency,
then terminate that worker. One partially computed next epoch may be discarded;
the preserved epoch-500 trajectory itself is unchanged. No external job is touched.
If the exact boundary is missed or a worker exits unexpectedly, fail explicitly;
never relabel an epoch-501 or later checkpoint as epoch 500. After both transfers,
retire the original dispatcher. The preserved epoch-500 last file can resume the
original longer VAE run. Both the last and best-up-to-500 models are retained.

Stage two uses the BEST internal reconstruction checkpoint among epochs <=500,
as in the original selection rule. This may be earlier than epoch 500. Re-evaluate
with the original fixed internal noise; block if reconstruction has zero fraud
true positives or nonfinite loss. This is reconstruction, not fraud detection or
free-generation performance.

## Limited second stage and early results

Use the original pinned-public-code Sparkov architecture, mixed data parser,
619/69 optimization/internal customers, all 3123 positions, static conditions,
batch32/micro8, float32, AdamW, Linear velocity/cosine transport, EMA .9999 and
250 Euler sampling steps. No transaction truncation, new labels, true future
counts or change to the candidate/CPAR outputs. No final-test reads.

Cap DiT at **2000 optimizer updates per fit**, compared with the original 100000.
Validate fixed-noise internal transport loss and checkpoint every 250 updates.
Select the lowest INTERNAL EMA transport loss; no development selection. Keep
resumable optimizer/RNG checkpoints, including the final 2000-step state.
At updates 500 and 1000 generate one full 69-customer INTERNAL cohort using the
current EMA and immediately evaluate it. At update 1000 also generate an online
(non-EMA) internal diagnostic, because EMA .9999 retains substantial initialization
weight at this short budget. This diagnostic does not change EMA, training or
selection, and is not substituted for the primary output. Preserve all RNG states
around preview sampling so it does not alter subsequent training draws.
At the cap, use the selected EMA to generate internal once and development twice
(20261031/32), with the same decoding and native EOS rule as the original adapter.

Two fits remain independent seeds; previews are NOT extra independent fits. Keep
143 common-support and 147 full-development results distinct. Save missing fraud,
onset and long-tail support explicitly as missing; never drop a failing fit. The
evaluator computes the frozen common metrics and also retains generated data for
merchant/category/amount inspection. All labels/amounts/gaps are generated by MeLD.

This is a **limited-budget feasibility/learning-progress pilot**, NOT an adequately
trained latest baseline, exact paper reproduction, convergence or SOTA result.
Bad early generation cannot establish MeLD's inherent limitation or our superiority.
No automatic model promotion, push, final-test opening, or longer-budget restart.
