# 2026-09-28 생성 라벨 경로의 고객 식별자 연결 수정

실제 경로 3개 split의 250개 짧은 시간 재생은 완료됐다. 생성 라벨 경로를 추가할 때
진단 코드의 ID 검사가 중단시켰다. metadata.entity_id는 encoding record 순번이고
생성 파일의 entity_id는 원래 고객 키다. 둘을 같은 키로 간주한 새 진단 코드의 오류이며,
기존 모델이나 생성 결과의 오류가 아니다. 원본 결과 및 실제 경로 진단은 바꾸지 않는다.

기존 전처리 때 기록한 argn_followup_diagnostics_v1/positions.parquet의
record–customer_id 대응표를 사용한다. D1_INPUTS.json의 원래 SHA256로 확인하고,
147명의 일대일 대응, 177,997개 행의 라벨/거래 위치, 이번 horizon 안의 실제 간격 일치를
검증한다. 정렬 순서 추정이나 일부 고객 삭제로 검사를 우회하지 않는다.

참고로 기존 디코딩 자료에는 이번 horizon 밖에서 최대값 제한 때문에 원본 gap과 다른
행이 1개 있다. 이번 first200 시간 재생에는 차이가 없으며 원본 파일은 수정하지 않는다.

실패한 wrapper/로그와 완료된 3개 split 결과를 hash로 보존한다. 이미 완료한 실제
경로는 재실행하지 않고 생성 라벨 경로 8개만 이어 수행한 후 합친다. 모델·난수·지표·목표·
사전 고정 구간은 그대로다. 현재 후보에 유리한 결과를 고르는 변경이 아니다.
