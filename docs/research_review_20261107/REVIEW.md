# 연구 검증과 재설계 제안 — 2026-11-07

이 문서는 제안이다. 기존 프로토콜, 결과, 모델은 바꾸지 않았다. 새 학습·생성·GPU 작업·test 조회·commit·push는 없다. 사용자가 방향을 정하면 `docs/RESEARCH_DECISIONS.md`에 날짜를 붙여 반영한다.

## 1. 결론

1. **지금 내세우는 주장이 이 연구에서 가장 약한 결과다.** 현재 초점은 "개인 속도로 시간 출력을 보정한다"인데, 위치만 쓰는 보정과의 차이가 세 번의 독립 학습에서 0과 구별되지 않는다.
2. **가장 강한 결과는 9월 27일 이전에 이미 나왔다.** 거래열 생성기가 드문 상태(사기) 구간의 지속을 학습하지 못하고, 그 원인이 누적 생성 오차가 아니라는 진단이다. 이 결과는 기여로 정리되지 않은 채 "기준 정돈"으로만 분류돼 있다.
3. **사기 관련 수치의 일반성에 근본 제약이 있다.** Sparkov의 사기는 시뮬레이터 규칙으로 만들어진다. 고객마다 하루짜리 사기 구간 하나를 넣고 그날의 정상 거래를 지운다. "사기 시작 시 개인 대비 시간 변화"는 이 규칙의 산물일 가능성이 높다.
4. **최신 문헌에는 이 연구가 들어갈 빈자리가 있다.** 순차 생성기를 평가한 벤치마크는 라벨·희귀 사건을 다루지 않고, 사기 행동을 평가한 벤치마크는 행을 독립으로 생성하는 모델만 다뤘다. 두 조건이 겹치는 연구는 찾지 못했다.
5. **제안:** 연구 질문을 "드문 상태 구간의 동역학을 순차 생성기가 보존하는가, 왜 못 하는가, 최소한 무엇을 고치면 되는가"로 다시 세운다. 시간 보정은 부록 수준의 제거 실험으로 내린다.

## 4. 문제점과 한계

중요한 순서다.

**① 연구 질문이 한 문장으로 서 있지 않다.** 주제가 CoF-SeqGen(탐지 목적) → CS-SAF(금액·행동 출력) → ARGN 상태 우선 → 시간 보정으로 옮겨 왔다. 각 단계는 직전 단계의 남은 오류를 고치는 식으로 정해졌다. 9/30 감사도 "오류를 하나씩 고쳐야만 논문 단계로 간다는 방식은 바꿔야 한다"고 적었다. 그 뒤에도 질문은 시간 보정에 머물렀다.

**② 현재 주장의 효과가 통계적으로 확인되지 않는다.** 3절의 약한 결과 표와 같다. 개발 고객은 147명이고 독립 학습은 3회다. 이 규모로는 0.003 수준의 차이를 확인할 수 없다.

**③ Sparkov의 사기는 시뮬레이터 규칙이다.** 원본 코드(`datagen_transaction.py`)를 읽었다. 고객의 약 98%에 사기 구간을 정확히 하나 넣는다. 구간은 하루이고 날짜는 무작위다. 그날의 정상 거래는 지우고 별도의 사기 프로필에서 뽑은 거래로 채운다. 로컬 수치와도 맞는다. 개발 147명 중 114명이 사기를 겪고, 구간은 평균 10건이며, 구간 안에서는 91%가 사기로 이어진다.
- 따라서 "사기 시작 시 개인 대비 시간 변화"는 정상 프로필에서 사기 프로필로 바뀌는 규칙을 다시 맞히는 일이다. 실제 사기 행동의 보존이라고 말하기 어렵다.
- 이 코드는 현재 공개 버전이다. Kaggle 데이터는 이전 설정(구간 1–7일)으로 만들어졌을 수 있다. 구조는 같다.
- Seq2Synth와 사기 행동 벤치마크 모두 Sparkov를 쓰지 않는다. 사기 행동 벤치마크는 실제 데이터인 IEEE-CIS를 쓴다.

**④ 비교군이 약하다.** 9/29 재검토와 9/30 감사가 이미 지적했고 아직 해결되지 않았다.

| 비교군 | 상태 |
|---|---|
| CPAR | 128/256 epoch. 정상 간격 0.87로 매우 나쁘다. 강한 비교군이 아니다 |
| MeLD | 사용자 지정 예산의 예비 실험. 충분히 학습하지 않았다 |
| LBDTPP | 사기율 58–64%로 적용 실패. 원 논문은 단일 범주 mark만 다루고 금융 데이터가 없다 |
| TabDiT | 공개 저장소에 학습 코드가 없다 |
| TimeAutoDiff | 실행하지 않았다. 원 논문은 길이 48 고정 구간이고 시간을 입력으로 받는다 |
| **REaLTabFormer** | **실행 기록을 찾지 못했다.** Seq2Synth에서 종단 충실도 상위이고 TabQueryBench에서 1위다 |

**⑤ 방법이 하나의 모델이 아니다.** 동결한 ARGN 위에 전이·지속 head, 업종·금액 출력, 간격 출력, 초기 상태–길이 혼합, 첫 사기 hazard, 시작 금액 전문가, 시간 혼합 출력, 위치 보정이 차례로 쌓였다. 각각은 알려진 구성이다. 지금 형태로는 "무엇을 제안하는가"를 한 문단으로 쓸 수 없다.

**⑥ 평가가 외부 기준과 연결돼 있지 않다.**
- 지표(로그 간격 W1, 직전 20건 중앙값 대비 비율)는 이 연구에서 정의했다. Seq2Synth의 시간 간격·종단 지표와 대응시키지 않았다.
- 실제 대 실제 기준선이 없다. 사기 행동 벤치마크는 실제 데이터를 반으로 나눠 구한 오차로 나눈 배율을 보고한다. 0.09라는 W1이 큰지 작은지는 이 기준선이 있어야 말할 수 있다.
- 활용도(합성 데이터로 학습한 탐지기)와 프라이버시 평가가 없다. 금융 합성 데이터 논문에서는 둘 다 기본 항목이다.
- 개발 147명을 20회 넘는 실험에서 반복해 봤다. 현재 수치는 모두 탐색 결과다.

**⑦ 데이터가 하나다.** 9월 이후의 모든 사기 관련 결과가 Sparkov 하나에서 나왔다. Berka에는 사기 라벨이 없다.

**⑧ 자료가 GitHub에 없다.** 9/28 이후의 실험 코드와 보고서는 서버와 이 PC 백업에만 있다.

| [MoTPP](https://arxiv.org/html/2609.21382v1) | 출력 head만 바꿨다. 근거는 동시각 사건이 최대 46%라는 구체적 부적합이다. 여러 지표에서 지고, 제거 실험이 없다 | 작은 변경도 구체적 부적합을 근거로 하면 논문이 된다. 제거 실험과 비용 보고는 내 쪽이 더 낫다 |
| [LBDTPP](https://arxiv.org/html/2606.24982v1) | 단일 범주 mark, 금융 데이터 없음. 이론은 가정 아래의 상한이다. 누적 오차를 직접 분리한 실험은 없다 | 전체 필드 거래 생성의 비교군으로 부적합하다. 내 진단(실제 과거에서도 실패)은 이 계열의 전제와 다른 원인을 가리킨다 |
| [TabQueryBench](https://arxiv.org/html/2607.03926v1) | 49개 정적 데이터. 조건을 걸면 82.6%에서 점수가 떨어진다. 꼬리·희귀 값은 최고 모델도 0.45. 순차 데이터는 범위 밖 | 희귀 부분집단 충실도는 정적 표에서도 미해결로 인정된 문제다. 순차로 확장한 연구는 비어 있다 |
| [FINESSE](https://arxiv.org/abs/2609.11993), [PersonaLedger](https://arxiv.org/html/2601.03149) | 규칙·에이전트 기반 시뮬레이터. 사기 라벨이 있는 공개 데이터를 낸다. 실제 데이터와의 대조 검증은 없다 | 추가 데이터 후보. 둘 다 시뮬레이션이라는 한계는 같다 |

**문헌에서 읽히는 빈자리.** 고객 단위로 거래열을 생성하는 모델이 드문 라벨 구간의 발생·지속·종료와 그 구간의 시간·금액 변화를 보존하는지 평가한 연구를 찾지 못했다. 가장 가까운 두 연구는 각각 절반만 다룬다. 이것은 내가 읽은 범위에서의 판단이고, 없다고 단정하지 않는다.

## 6. 연구 질문 재정의 (제안)

**한 문장.** 고객별 거래열 생성기는 드문 상태 구간의 동역학을 보존하는가, 보존하지 못한다면 원인이 생성 누적 오차인가 조건부 학습 실패인가, 그리고 어떤 최소 수정이 이를 복원하는가.

"드문 상태 구간"은 사기에 한정하지 않는다. 사기 구간, 연체, 드문 상품 사건처럼 라벨로 표시되고 연속으로 나타나는 구간을 가리킨다. 이렇게 넓혀야 Sparkov 규칙 하나에 묶이지 않는다.

### 기여 후보

| | 내용 | 이미 가진 근거 | 더 필요한 것 |
|---|---|---|---|
| **A. 진단** | 순차 생성기는 사기율을 맞춰도 구간 지속을 잃는다. 실제 과거를 줘도 실패하므로 원인은 조건부 학습이다 | ARGN에서 완결. 손실 가중·열 순서 대조 포함 | REaLTabFormer 등 다른 생성기 1–2개, 다른 데이터 2개에서 같은 진단 |
| **B. 평가** | 상태 조건부 지표와 실제 대 실제 기준선. 합친 지표가 조건별 오차를 가린다는 증거 | 조건별 0.419 대 합산 0.162 | Seq2Synth 지표와의 대응, 기준선 배율, 탐지기 활용도 |
| **C. 방법** | 드문 상태의 지속·종료 과정을 명시적으로 두고, 상태별 출력을 균형 학습하는 하나의 모듈. 생성기 종류와 무관하게 붙인다 | ARGN 위의 개별 구성으로 효과 확인 | 하나의 모듈로 통합, 두 번째 생성기에 적용, 5개 시드 |

- 주장의 중심은 A와 B다. C는 "큰 구조 없이 복원된다"를 보이는 역할이다.
- C의 각 부품은 알려진 방법이다. 새롭다고 쓸 수 있는 것은 부품이 아니라 "이 분해가 필요하고 충분하다"는 실험 근거다.
- 시간 보정은 기여 후보에서 뺀다.

### 이 방향의 위험

- 다른 생성기가 사기 지속을 잘 재현하면 A는 "ARGN 설정의 문제"로 줄어든다. 그 경우 여러 생성기를 비교하는 벤치마크 논문으로 방향을 바꾼다.
- 실제 데이터에서 드문 구간이 Sparkov처럼 뚜렷하지 않으면 효과가 작게 나온다. IEEE-CIS는 고객당 거래 수 중앙값이 4건이라 구간 분석이 제한된다.
- 추가 데이터도 대부분 시뮬레이션이다. 실제 금융 사기에 대한 일반화는 주장할 수 없고, 그 한계를 논문에 써야 한다.

**유지할 것**

- 고객 단위 분할과 미개봉 test.

**추가할 것**
1. **실제 대 실제 기준선.** 학습 고객을 반으로 나눠 모든 지표의 기준 오차를 구한다. GPU가 필요 없다.
2. **REaLTabFormer 실행.** Sparkov에서 같은 진단(구간 길이, 실제 과거를 준 다음 사기 확률)을 낸다.
3. **두 번째·세 번째 데이터.**
   - IBM 카드 거래(TabFormer): 약 2,400만 건, 사기 약 0.12%. 시뮬레이션이지만 사기 생성 방식이 Sparkov와 다르다. CPAR 금융 논문과 TimeAutoDiff가 쓴다.
   - IEEE-CIS: 실제 데이터. 사기 행동 벤치마크와 직접 비교할 수 있다.
   - 보조: MBD-mini(실제 은행 데이터, 사기 없음, 드문 상품 사건), FINESSE-Bench.
4. **하나의 모듈로 통합.** 지금의 여러 head를 "상태 과정 + 상태별 출력"으로 묶어 한 번에 학습·기술할 수 있게 한다.
5. **활용도와 프라이버시.** 합성 데이터로 학습한 탐지기(순차 특징 포함)를 실제 데이터로 평가한다. 최근접 거리와 Seq2Synth의 n-gram 노출 지표를 잰다.
6. **시드 5개.** HoTPP와 LBDTPP가 5–10개를 쓴다. 3개로는 지금 같은 구간 폭이 나온다.
