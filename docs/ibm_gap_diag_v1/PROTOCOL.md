# ibm_gap_diag_v1 — 봉인 test 이후의 진단 (등록 2026-11-11, 실행 전)

사용자 지시(2026-11-11): "진단부터 시작". [봉인 test 결과](../ibm_sealed_test_v1/RESULTS.md)에서 (a) 생성 사기율이 train의 약 1.6배, (b) 효용이 실제 상한의 57–80%에 머문다는 두 사실이 나왔다.
이 문서는 두 사실의 **원인을 재는 진단**이다. 모델 변경·새 생성·새 학습·GPU 없음. **train과 dev만** 쓴다. 봉인 test(`prepared/test*`)는 다시 읽지 않는다(이미 연 test로 개발하지 않는다).
IBM 채택 모델과 봉인 test 판정은 그대로다. 여기서 나온 것은 다음 설계의 근거일 뿐 기여 주장이 아니다.

## D1. 사기 과다 생성의 원인 (`scripts/diag_label_rate.py`)

전이표는 P(사기 | 이전 라벨, 이전 구간 나이 1–21, 이전에 사기가 있었는가)이며 Jeffreys 평활(0.5)을 쓴다. train 사기율 .00116, 생성 .0018–.0019. 후보 원인과 가르는 측정:

- **H-a 평활.** train의 실제 경로를 따라 표의 확률을 더한 기대 사기 수(교사 강제)와 실제 1,303건의 차이가 평활이 더한 양이다.
- **H-b 자유 생성의 동역학.** 같은 표로 train 고객의 실제 길이만큼 라벨 사슬을 자유 모의(100회)한 사기 수가 교사 강제 기대보다 크면, 표가 조건으로 쓰는 상태(특히 "이전에 사기가 있었는가")의
  체류 시간이 실제와 모의에서 다르다는 뜻이다. 실제와 모의의 첫 사기 위치(상대 위치), "이전 사기 있음" 상태에서 보낸 사건 수, 고객당 사기 수 분포, 사기 고객 수를 비교한다.
- **H-c backbone 길이.** dev 생성물(채택 모델 4 생성)의 길이로 같은 모의를 해 생성물의 실제 사기 수와 비교한다(생성이 표를 그대로 따르는지 확인 겸).
- 원인 분리용 모의 변형(모의만, 생성기 변경 아님): 평활 없는 표 / "이전 사기" 조건을 뺀 표 / 나이 조건을 뺀 표.
- 판정: 초과분(모의 − 실제)의 절반 이상을 설명하는 원인을 "주 원인"으로 적는다. 어느 것도 절반에 못 미치면 그대로 적는다.

## D2. 효용 격차의 분해 (`scripts/diag_utility_gap.py`)

등록 탐지기(`stable`, 이력 특성 포함), 평가는 실제 dev. 대상: 채택 모델(`visitrate`) dev 생성 4개와 `rtf_table` dev 생성 4개. 실제 기준: train 240명 부분표본 4개(상한 계산과 같은 seed 규칙).

- **행 교체.** 특성은 각 표에서 따로 계산한 뒤 행을 섞는다: 실제 사기 행 + 합성 정상 행 / 합성 사기 행 + 실제 정상 행. 실제 + 실제(상한)와 합성 + 합성(현재 효용)을 양 끝으로 놓고,
  어느 쪽 행을 실제로 바꿀 때 상한에 가까워지는지 본다. 격차의 60% 이상을 한쪽이 설명하면 그쪽을 "주 원인"으로 적는다.
- **판별기.** 실제 train의 사기 행 대 합성 사기 행을 구분하는 분류기(5겹 교차검증 AUC)와 순열 중요도 → 합성 사기 행이 어느 특성에서 실제와 다른지. 구간 첫 행(진입)과 이후 행을 나눠서도 잰다.
  정상 행도 같은 방식으로(각 5만 행 표본) 잰다. AUC .5 = 구분 불가.
- **특성 묶음 제거.** 묶음(금액 / 간격 / 가맹점 반복 / 업종 / 채널 / 위치)을 하나씩 뺀 탐지기로 실제 부분표본과 합성을 각각 학습해 격차(상한 − 합성)가 어느 묶음을 뺄 때 줄어드는지 본다.

## 한계(미리 적음)

dev는 이미 부품 선택에 쓰였으므로 여기서의 수치는 탐색용이다. 실제 부분표본 4개·생성 4개의 평균 차이 .03 미만은 해석하지 않는다. 진단이 가리킨 원인을 고치는 것은 별도 등록(선행 연구 대조 포함) 뒤의 일이다.

## 수정안 1 (등록 2026-11-12, 실행 전) — 행 교체를 독립 생성 24개로 다시 재고, 채택한 정상 행 부품 뒤에 남은 격차의 위치를 본다

사유: (i) D2의 행 교체는 seed가 겹친 생성 4개(라벨에 대해 독립 표본 약 2개)로 쟀다 — [ibm_normal_impl_v1](../ibm_normal_impl_v1/RESULTS.md)에서 같은 조건의 효용 수치가 .491 → .450으로 정정됐으므로 "격차 전부가 정상 행"이라는 결론도
독립 seed로 다시 확인해야 한다. (ii) 정상 행 부품(`RA`)을 채택했으므로(2026-11-12 사용자 결정), 다음 부품을 고르기 전에 **남은 격차(.467 대 .610)가 어느 쪽 행에 있는지** 다시 잰다.
위의 등록 내용과 원 결과는 바꾸지 않는다. 모델 변경·새 생성·새 학습·GPU 없음. 2013 train·dev와 이미 만든 dev 생성물만 쓴다. test 미열람.

- **대상.** `ibm_normal_impl_v1`의 독립 생성 24개(fit 2 × seed 12, seed는 fit마다 다름)의 두 팔: `B`(채택 전 모델)와 `RA`(채택한 구성). 실제 기준은 train 240명 부분표본 24개(seed = 20261108 + i; 앞의 4개는 원 진단과 같다), 생성 i와 부분표본 i를 짝짓는다.
- **측정(원 진단과 같은 방식).** 등록 탐지기 `stable`, 평가는 실제 dev, 특성은 각 표에서 따로 계산한 뒤 행을 섞는다. 네 구성: 실제 + 실제(RR, 상한) / 합성 + 합성(SS) / 합성 사기 + 실제 정상(SfRn) / 실제 사기 + 합성 정상(RfSn).
  회복 비율 = (교체 구성 − SS) / (RR − SS)를 24쌍 평균으로, 짝지은 차이의 표준오차와 함께 적는다.
- **판정(원 규칙 그대로).** 한쪽 교체가 격차의 60% 이상을 회복하면 그쪽을 "주 원인"으로 적는다.
  - G1: `B`에서 "주 원인 = 정상 행"이 독립 seed로도 성립하는가(SfRn 회복 ≥ 60%).
  - G2: `RA`에서 남은 격차의 주 원인은 어느 쪽인가. SfRn이 상한과 표준오차 2배 안이면 "남은 격차도 정상 행", RfSn 쪽이 60% 이상 회복하면 "사기 행", 둘 다 아니면 "양쪽 / 상호작용"으로 적는다.
  - 두 교체의 효과는 더해지지 않을 수 있다(특성이 표마다 따로 계산되므로) — 두 회복 비율을 모두 적고 합이 1이 아님을 그대로 둔다.
- **쓰임.** 다음 부품의 순서(시간 구조·정상 행 쪽 대 사기 묶음 쪽)를 정하는 근거일 뿐 기여 주장이 아니다. `rtf_table`은 독립 seed의 dev 생성물이 없어 이번에 다시 재지 않는다(원 진단의 4개 결과 — 어느 쪽을 바꿔도 15–22%만 회복 — 가 그대로 남는다).
