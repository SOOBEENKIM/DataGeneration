# ibm_normal_rows_v1 — 정상 행의 이력 참조(금액·최근성·간격): CPU 모의 먼저 (등록 2026-11-11, 실행 전)

사용자 지시(2026-11-11): "정상 거래 진행". 근거 [진단 D2](../ibm_gap_diag_v1/RESULTS.md)(효용 격차 전부가 합성 정상 행), [사기 묶음 결과 §3](../ibm_episode_state_v1/RESULTS.md)(생성된 1년이 280–540일),
선행 대조 [PRIOR_WORK](../ibm_design_v2/PRIOR_WORK.md)(기제는 복사·포인터, 재소비의 최근성, 순위 결합 — 모두 알려진 것, **새로움 주장 없음**; Banksformer·UniTTab 본문은 2026-11-11 재시도에도 확인하지 못해 미해결).
개발은 **2013 train·dev만**, test 미열람. 이 단계는 **CPU 모의**다: 채택 모델의 기존 dev 생성물 4개에서 **정상 행만** 다시 정하고(사기 행·라벨·길이·새 가맹점은 그대로) 구조와 효용을 잰다. 학습·GPU·새 생성 없음.
모의가 기준을 넘으면 생성기 안 구현(또는 2단계 모듈로의 채택)을 별도로 등록한다.

## 1. 부품 (모든 표는 train에서만 추정)

- **`AMT` 금액 기준점.** 정상 행(금액 > 0)에서
  - 고객이 그 가맹점을 정상 행으로 방문한 적이 있으면: 금액 = (그 고객의 그 가맹점 **첫 금액**) × exp(δ), δ는 train의 "재방문 금액 ÷ 첫 금액"의 로그 경험 분포(가맹점 업종별; 표본 200 미만 업종은 통합)에서 추출.
  - 가맹점은 처음이지만 그 업종을 방문한 적이 있으면: 금액 = (그 고객의 그 업종 첫 금액) × exp(δ), δ는 train의 해당 경험 분포.
  - 업종도 처음이면: train에서 "업종 첫 금액"의 경험 분포(업종별)에서 추출.
  - 사기 행과 금액 ≤ 0인 행은 그대로 두고 기준점으로도 쓰지 않는다. 기준점을 "첫 금액"으로 고정하는 이유: 직전 금액을 기준으로 하면 방문이 쌓일수록 분산이 커진다(표류).
- **`REC` 최근성.** 원래 생성에서 "반복"이던 정상 행(그 고객이 이미 방문한 가맹점)에 대해, 확률 s로 **직전 정상 행의 가맹점**을 다시 고르고 아니면 원래 가맹점을 둔다. s는 직전 가맹점의 업종별로
  train의 P(직전과 같은 가맹점 | 반복 행)에 맞춘다: s = (t − p₀) / (1 − p₀), p₀는 **생성물**에서 잰 현재 값(dev 실제 자료 미사용). 업종·채널은 가맹점에서 다시 정한다(기존 속성 규칙). 새 가맹점 행은 그대로라 고객별 가맹점 집합과
  새 가맹점 시점은 바뀌지 않는다.
  - 기록: `ibm_merchant_marginal_v1`에서 같은 종류의 "끈적임"을 우도 이득으로 기각했다. 그 기준이 생성 통계의 결손(.042 대 .175)을 재지 못했음을 진단에서 확인했으므로 생성 통계 기준으로 다시 본다.
- **`GAP` 시간.** 정상 → 정상 행의 간격만 다룬다(사기에 인접한 행의 간격은 그대로).
  - 순서 재배열: 고객의 정상 간격 **값들은 그대로 두고 순서만** 바꿔 연속성을 준다 — 자기상관 φ인 AR(1) 정규 잠재열의 순위대로 간격을 배치(순위 결합). φ는 train의 로그 간격 1차 순위 자기상관에서 닫힌 식으로 정한다.
  - 창 맞춤: 고객별 정상 간격에 상수를 곱해 총 기간을 train 중앙값(약 364일)에 맞춘다.
- 조합: `AMT`, `REC`, `GAP`, `AMT+REC`, `ALL`(REC → GAP → AMT 순으로 적용). 기준은 채택 모델 그대로(`base`).

## 2. 측정과 판정

각 팔 × 기존 dev 생성 4개(fit 2 × seed 2; 같은 생성물에서 정상 행만 바꾸므로 팔 간 비교는 **짝지은 비교**다).

- **구조(대상 통계, 실제 train 기준):** (고객, 가맹점) 안 log 금액 표준편차(1.00), 재방문 금액 차이 중앙값(.32), 업종 안 표준편차(1.19), 직전과 같은 가맹점(.175), 최근 5행 안 같은 가맹점(.350), 상위 3 가맹점 비율(.377),
  간격 1차 자기상관(.186), 고객별 총 기간(363–365일).
- **N1 (구조).** 각 부품이 자기 대상 통계를 `base`보다 실제 쪽으로 **격차의 절반 이상** 옮긴다(AMT: 금액 통계 3개, REC: 가맹점 통계 3개, GAP: 자기상관·총 기간).
- **N2 (효용, 1차).** `ALL`의 효용(등록 탐지기, dev)이 `base`보다 **+.03 이상**(4쌍 평균; 4쌍 중 3쌍 이상에서 양). 상한선은 행 교체 진단의 .597이다.
- **N3 (판별기).** 정상 행 판별기 AUC(실제 train 대 합성, 5겹)가 `base`(.825)보다 .05 이상 내려간다.
- **N4 (비열화).** 표준 지표 최댓값 ≤ 3배, 사기 구조(사기 새 가맹점·구간 내 간격·진입 금액비) ≤ 3배, 정상 행 속성 일관성 ≥ .99, 사기 행의 개인 대비 금액(실제 .56)이 `base`(.46)보다 실제에서 멀어지지 않음.
- 제거 실험(AMT / REC / GAP 단독, AMT+REC)의 효용과 구조를 모두 보고한다. 판정은 `ALL` 기준이며, N2가 미달이어도 단독 팔이 +.03을 넘으면 그 사실을 적고 그 부품만의 채택은 **별도 등록**으로 한다(여기서 고르지 않는다).
- N1–N4를 모두 충족하면 생성기 구현 단계를 등록한다. 아니면 그대로 기록한다.

## 3. 한계(미리 적음)

- 후처리 모의이므로 backbone이 바뀐 정상 행을 "보고" 다음 행을 생성하는 효과는 없다. 특히 사기 행의 금액은 원래 정상 금액 이력을 보고 생성된 것이라, 정상 금액을 바꾸면 사기 금액의 개인 대비 관계가 달라질 수 있다(N4에서 측정).
- dev는 이미 여러 번 썼고 기존 생성 4개는 라벨에 대해 독립 표본이 약 2개다. 짝지은 차이만 해석하며 확인은 봉인된 연도에서 한다.
- 경험 분포에서의 추출은 train의 금액 차이·첫 금액 값을 재사용한다(표·히스토그램과 같은 수준의 train 의존).

## 수정안 1 (2026-11-11, 위 판정 뒤 · 실행 전 등록): 격차가 있는 정상 행을 직접 찾는 진단

세 부품을 합쳐도 +.02인데 행 교체 상한은 +.10이다. 구조 통계를 하나씩 맞추는 것보다 **탐지기가 실제로 걸려 넘어지는 정상 행**을 먼저 찾는다(`scripts/diag_utility_gap_d.py`; CPU, train·dev, 모델 변경 없음).
- 실제 부분표본으로 학습한 탐지기로 (a) 합성 정상 행과 (b) 학습에 쓰지 않은 실제 train 정상 행을 채점해, dev 상위 1% 경보 임계값을 넘는 **"사기처럼 보이는 정상 행"의 비율**을 비교한다. 합성 쪽이 훨씬 많으면 합성 정상 행에
  실제에는 없는 사기 유사 행이 섞여 있다는 뜻이다(그 행들이 탐지기에게 "이 패턴은 정상"이라고 잘못 가르친다).
- 반대로 합성으로 학습한 탐지기로 실제 정상 행을 채점해, 합성에는 없는 실제의 어려운 정상 행을 본다.
- 임계값을 넘는 행의 구성(온라인, 새 가맹점, 대면 업종에서의 온라인, 표기된 희귀 가맹점, 업종, 금액, 간격)을 실제와 합성에서 비교한다. "대면 업종" = train 정상 행의 온라인 비율이 1% 미만인 업종.
- 판정 없음(진단). 여기서 특정된 행 유형이 다음 부품 설계의 대상이 된다. 금액 부품의 재설계(평균 회귀를 반영한 참조)는 그 뒤에 별도 등록한다.

## 수정안 1의 결과 (2026-11-11, `FRAUDLIKE_NORMALS.json` + train 측정)

- 실제로 학습한 탐지기가 "사기 같다"고 보는 정상 행: 합성 정상 행의 **1.61%**, 학습에 쓰지 않은 실제 정상 행의 0.90%(1.8배). 그 합성 행들의 구성: 온라인 .76, **이미 가 본 가맹점**(.63), 금액은 평소보다 작고(개인 대비 −.38),
  **간격이 짧고**(개인 대비 −1.03, 10분 미만 .17), 최근 5행에 같은 업종이 거의 없다(.16; 실제 쪽은 .33). 대면 업종에서의 온라인 정상 거래는 실제·합성 모두 0이다(이 가설은 기각).
- 반대로 합성으로 학습한 탐지기가 잘못 경보하는 실제 정상 행: 새 가맹점 .70, 고액(log 4.2, 개인 대비 +.64), 상위 업종이 여행사(4722)·백화점·택시.
- **구조 S1 — 짧은 간격의 연속 거래는 같은 가맹점에서 일어난다.** 실제 정상 행에서 직전과 같은 가맹점일 확률: 간격 1분 이하 .79, 1–5분 .75, 5–10분 .68, 10–30분 .42, 30–60분 .16, 1시간 이상 .05–.09.
  합성은 간격과 무관하게 .04–.06이다. 실제의 짧은 간격 행은 온라인이 드물고(.05) 새 가맹점도 드물다(.02); 합성은 각각 .12, .08이다. 즉 합성의 짧은 간격 정상 행은 "다른 가맹점·가끔 온라인·가끔 새 가맹점"이라
  사기 구간과 같은 모양이고, 탐지기에게 그 모양이 정상이라고 가르친다.
- **구조 S2 — 업종이 금액의 크기를 정한다.** 업종별 평균 log 금액의 표준편차(행 가중): 실제 .75, 합성 .29. 업종 안 표준편차도 실제는 업종마다 다르고(택시 .52, 백화점 .91, 식료품 1.15, 여행사 2.55) 합성은 어디서나 1.3–1.4다.

## 수정안 2 (2026-11-11, 위 결과 뒤 · 실행 전 등록): S1·S2를 겨냥한 부품의 CPU 모의

같은 방식(채택 모델의 기존 dev 생성물에서 정상 행만 후처리, train에서만 추정, GPU·학습 없음).

- **`REC2` 간격 조건부 머무름.** 첫 모의의 `REC`와 같되 머무를 확률을 **그 행의 간격 구간별**(1분 이하, 1–5분, 5–10분, 10–30분, 30–60분, 1–4시간, 4–24시간, 24시간 초과)로 둔다. 대상은 그대로 "원래 반복이던 정상 행"(새 가맹점 행은
  건드리지 않아 고객별 가맹점 집합이 유지된다). 머무르면 가맹점·업종·채널을 직전 행에서 가져온다. 생성 순서상 간격이 가맹점보다 먼저 정해지므로 생성기 안에서도 같은 조건화가 가능하다.
- **`AMT0` 업종 조건부 금액.** 정상 행 금액을 train의 업종별 경험 분포에서 추출(고객 구조 없음; 대조용).
- **`AMT2` 업종 + 고객 수준.** log 금액 = (업종 평균) + B(n) × (그 고객의 그 업종 지난 금액들의 평균 − 업종 평균) + 잔차. B(n)은 지난 방문 수 구간(1, 2–4, 5–19, 20 이상)별 회귀 기울기(평균 회귀를 자료에서 추정),
  잔차는 (구간, 업종)별 경험 분포. 첫 모의 `AMT`의 결함(독립 추출로 분산을 두 번 더함)을 회귀로 고친 것이다. 가맹점 수준은 두지 않는다 — 실제 분산 분해에서 (고객, 가맹점) 수준의 추가 몫이 1% 미만이기 때문이다.
- 팔: `REC2`, `AMT0`, `AMT2`, `REC2_AMT0`, `ALL2`(= `REC2` → `AMT2`). `GAP`(창 맞춤)은 이번에 넣지 않는다(첫 모의에서 효용 −.008, 간격 지표 악화; 달력 시계 문제는 별도로 다룬다).
- **판정(1차 팔 `ALL2`; 수치는 첫 등록과 같다):**
  - **N1′(대상 구조).** 간격 10분 미만 정상 행의 "직전과 같은 가맹점" 비율, 업종 평균 금액의 표준편차, 업종 안 금액 표준편차가 각각 `base`와 실제 사이 격차의 절반 이상 닫힌다. 그리고 실제 탐지기가 사기 같다고 보는 합성 정상 행의
    비율(1.61%)이 실제 수준(0.90%) 쪽으로 절반 이상 내려간다.
  - **N2** 효용 +.03 이상(4쌍 중 3쌍 이상 양), **N3** 정상 행 판별기 AUC −.05 이상, **N4** 표준 지표 ≤ 3배·사기 구조 유지·속성 일관성 ≥ .99·사기 행의 개인 대비 금액이 실제에서 멀어지지 않음.
- 모두 충족하면 생성기 구현을 등록한다. 일부만 충족하면 그대로 기록하고, 충족한 부품만의 채택은 별도 등록으로 한다.
- 한계: 진단과 같은 dev 생성물·같은 dev 평가 표에서 설계와 판정을 모두 했다(사후 적합 위험). 확인은 봉인된 연도에서 한다.

## 수정안 3 (2026-11-11, 수정안 2의 결과 뒤 · 실행 전 등록): 금액 분포의 모양 보정

사용자 지시: "보정 진행". [수정안 2의 결과](RESULTS.md): `AMT2`는 고객 수준을 맞추지만 금액 분포의 꼬리를 늘려 금액 표준 지표가 4.0배가 됐고(N4 미달), `AMT0`는 모양은 맞지만(1.18배) 고객 수준이 없다.

- **`AMT3` = `AMT2` + 업종별 분위 맞춤.** train 고객의 실제 거래열(가맹점·업종 순서)에 `AMT2`를 적용해 "이 부품이 만드는 업종별 금액 분포"를 구하고, 그 분포의 분위를 train의 실제 업종별 분위로 보내는 **고정된 단조 함수**를 업종마다 만든다
  (분위 201점, 선형 보간; 표본이 적은 업종은 통합). 생성 때는 `AMT2`가 낸 값에 이 함수를 적용한다. 단조 함수라 업종 안의 순위(따라서 고객 간 높낮이)는 유지되고 분포의 모양만 실제로 돌아간다.
  표와 함수 모두 train에서만 추정하며, 생성기 안에서도 같은 함수를 그대로 쓸 수 있다. 주변분포를 맞추고 의존 구조를 유지하는 표준 보정이다(새로움 주장 없음).
- 팔: `AMT3`, `ALL3`(= `REC2` → `AMT3`). 비교 기준은 `base`와 수정안 2의 `ALL2`(같은 생성물, 짝지은 비교).
- **판정(1차 팔 `ALL3`; 수치는 그대로):** N2 효용 +.03 이상(4쌍 중 3쌍 이상 양), N4 표준 지표 ≤ 3배·사기 구조 유지·속성 일관성 ≥ .99·사기 행의 개인 대비 금액 유지, N1′(구조 3개 + 사기 유사 정상 행 비율의 절반 이상),
  N3 판별기 AUC −.05 이상. 추가로 **고객 수준 유지**: (고객, 업종) 안 금액 표준편차가 실제(1.011)의 ± .10 안.
- 규칙은 바꾸지 않는다: 모두 충족하면 생성기 구현을 등록하고, 일부만 충족하면 그대로 기록한다. 그 경우 미달 항목을 안고 구현으로 갈지는 사용자가 정한다.

## 수정안 4 (2026-11-11, 위 결과 뒤 · 실행 전 등록): 반복 추출과 사기 금액의 기준 재설정

- **반복 추출.** `ALL2`·`ALL3`와 아래 `ALL4`를 같은 생성물 4개 위에서 **난수를 바꿔 5번씩** 다시 만든다(팔당 20개). 효용의 평균과 표준오차를 보고해 팔 간 차이가 변동 안인지 가린다.
- **`ALL4` = `ALL3` + 사기 금액의 기준 재설정.** 사기 행의 금액을, 원래 생성물에서 그 금액이 "그 고객의 그때까지 정상 금액 중앙값" 대비 갖던 로그 비율을 그대로 유지하도록 새 정상 금액의 중앙값에 맞춰 옮긴다
  (이전 정상 금액이 5개 미만이면 그대로). 사기 출력층이 이력 대비 금액 도약을 만들어 내던 것을 후처리에서도 보존하려는 것이며, 생성기 안에서는 사기 출력층이 바뀐 이력을 직접 보므로 따로 필요 없는 장치다.
  이 팔에서는 사기 행의 **금액만** 바뀐다(다른 열·라벨·위치는 그대로).
- **판정:** (i) `ALL4`의 사기 행 개인 대비 금액이 `base`(.457) 이상으로 돌아오는가, (ii) 20개 평균 효용이 `base`보다 +.03 이상이고 그 차이가 표준오차의 2배를 넘는 팔이 있는가, (iii) `ALL2`와 `ALL3`·`ALL4`의 평균 차이가
  표준오차의 2배 안인가(그러면 충실도가 좋은 쪽을 택한다). `ALL4`의 표준 지표·사기 구조는 반복 0번으로 다시 잰다(≤ 3배).
- 규칙은 그대로다: N2(등록한 4쌍 기준)의 판정은 바꾸지 않고, 반복 추출은 불확실성을 재는 추가 증거로 함께 적는다. 구현으로 갈지는 결과를 보고 사용자가 정한다.
