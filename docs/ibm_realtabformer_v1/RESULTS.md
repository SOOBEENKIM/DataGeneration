# ibm_realtabformer_v1 — 결과 (2026-11-09)

프로토콜: [PROTOCOL.md](PROTOCOL.md). REaLTabFormer 0.2.4(relational, GPT-2 encoder-decoder)를 IBM 2013 과제에
학습하고, 동결 fit 위에 (i) 전이표 디코딩(+창 간 상태 이월, 학습 0), (ii) 라벨 라우팅 사기 전용 출력 head를
얹었다. 기제 검사(`CHECK_*.json`): 미학습 복사본 = 원형 logits(최대 차 0.0, Sparkov fit 5.7e-6), 전이표 강제
p=1/0 → 사기 비율 1.0/0.0, 라우팅 개입 수 = 사기 행 × 라우팅 열 10(정확히 일치).

- head: 마지막 블록 `ln_2+mlp` + `ln_f` + lm_head 라우팅 열 행(K=431) 복사본, **5,056,512 파라미터**. 학습 창

  4.73→2.24(fit 09, 12 epoch) / →2.31(fit 08, 7 epoch), 각 10–30초.
- 생성 16회(팔 4 × fit 2 × draw 2), 각 27분. 전이표 팔은 window_index 순 라운드 생성(길이 혼합 배치, 사후
  절단), 창 행 수 불일치 0.
- 평가: 1단계 재실행(64개 생성, 바닥 200회), 효용 stable, Spearman 재계산(`../ibm_tabformer_v1/stage1`,
  `utility_detector_stable`).

## 3. 판정 (프로토콜 §3·§5)

- **T0.** REaLTabFormer 원형은 IBM에서 사기 질량을 **1/4로 과소 생성**(82–129건)하되, 상태별 출력(온라인
  .70–.95, 금액·간격·업종 2.0–2.4배)과 고객 배분(17–29명)은 대체로 보존한다. 구간 축에서는 고객당 구간 수
  7.2배·지속률 3.7배가 깨진다. Sparkov RTF(진입 과소)와 같은 방향이고 ARGN(과잉 진입·파편화)과 반대다.
  표준 지표에서 간격 W1 3.3배(ARGN 1.3)로 더 나쁘고 가맹점 다양성은 4.8배(ARGN 63)로 훨씬 낫다.
- **T1 강한 채택.** 전이표+이월은 지속률 .4배, 사기 고객 .8배, 나이 1 종료 .8배(모두 바닥 안), 고객당 구간 수
  7.2→1.9배, 사기 건수 82–129→298–566(실제 487). 24h 구간 수만 4.1→4.7로 악화 없음 기준(≤ +1) 안.
- **T2 채택(약).** `routed_subst`는 사기 출력 4지표 1.6 / 2.0 / 1.9 / 1.2배로 모두 바닥 3배 이내이고 전이표 팔
  대비 20–30% 개선. 그러나 **원형이 이미 3배 이내**(2.4 / 2.4 / 2.4 / 2.0)였고, `routed`는 학습 자체가 일어나지
  않아(epoch 0) 원형과 같다. 라벨 단독 P(온라인) ≥ .6은 원형(.41–.78)이 이미 부분 충족, subst .85–.87 충족.
- **T3 충족.** 표준 지표 변화: 업종 TV .000, 금액 .000, 간격 +.006, 가맹점 −.011(모두 ±.03 이내).
- **T4 강한 지지(전이표).** 이력 AUPRC .290(원형) → **.448**(전이표; 상한 .61의 73%), 조기 탐지 .65→.83(상한 .88).
  `routed_subst`는 .423으로 전이표 팔보다 낮다(draw별 .46/.44/.36/.43 대 .55/.50/.37/.38 — 2개 하락, 1개 상승).
- **backbone 불문 판정.**
  - 부품 (i) 전이표: **두 backbone에서 채택**, 반대 방향의 배분 오류(ARGN 과잉·파편화, RTF 과소)를 같은
    표·같은 코드로 고친다. ARGN에서는 효용이 오르지 않았고(상태별 출력이 깨져 있어서), RTF에서는 .29→.45로
    가장 큰 효용 상승을 만든다 — 배분 축 복구가 효용으로 이어지려면 상태별 출력이 보존되어 있어야 한다는
    2026-11-08 결론("두 축이 함께 효용을 예측")의 역방향 확인이다.
  - 부품 (ii) 라우팅 head: **ARGN에서는 필수**(.27→.84, 효용 16배), **RTF에서는 불필요**(원형이 이미 보존;
    실제 문맥 학습은 0 epoch; 치환 학습은 지표를 20–30% 개선하지만 효용은 올리지 않음). 즉 상태별 출력의
    붕괴는 backbone 특성(ARGN의 공유 저용량 출력 head)에 의존하고, 구간 배분의 붕괴는 두 backbone에 공통이다.
  - 따라서 주장은 "두 부품 모두 backbone 불문"이 아니라: **구간 배분은 backbone 공통 실패이며 학습 0의 전이표가
    두 backbone에서 복구한다; 상태별 출력 실패는 진단으로 판별되는 backbone 조건부 실패이며 해당 backbone에만
    라우팅 head를 붙인다.** 진단(라벨 단독 탐침, teacher-forced 사기 CE)이 두 번째 부품의 필요 여부를 미리
    알려준다(ARGN .15 / RTF .41–.78).

## 5. 한계

- 사기 창 167개, eval 분할 사기 창 10–21개로 head 조기 종료 기준이 얇다. `routed`의 epoch 0 종료는 "개선할 것이
  없음"과 "표본 부족" 중 전자로 해석했다(epoch 1부터 val CE가 오르고 train CE만 내려감 = 과적합).
- 전이표 팔의 draw 간 분산이 크다(사기 298 대 566). 240명 표본의 한계이고 fit 2 × draw 2로는 효용 차이 .02–.03을
  가르지 못한다(`rtf_table` 대 `routed_subst`).
- 창 60건·실제 창 수·창 길이 조건은 ARGN(자체 길이)보다 유리하다. 생성 시 패키지 기본 샘플링(do_sample,
  top-k 50)을 양쪽 팔에 동일 적용했다.
- 전이표의 창 간 이월은 원형 팔에 없다(원형은 창 독립). 원형의 지속률·구간 수 일부는 창 경계 효과를 포함한다.
- 두 데이터 모두 시뮬레이터. 대안 비교군(사기 oversampling, 라벨 조건부 전체 재학습, 사기 특화 생성기)은
  아직 없다.
