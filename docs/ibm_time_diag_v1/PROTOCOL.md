# ibm_time_diag_v1 — 시간 구조 진단 (등록 2026-11-12, 실행 전)

사용자 지시(2026-11-12): "시간 구조 진단". 근거: [행 교체 재측정](../ibm_gap_diag_v1/RESULTS.md)에서 채택한 구성(`RA`)의 남은 격차 .142 중 약 .10이 정상 행 쪽이다. 다음 정상 행 부품의 후보로 시간 구조를 꼽아 왔으나
(생성된 "1년"이 280–540일, 간격의 연속성 부족, 정상 행 판별기에서 간격 묶음의 중요도 .095), **그것이 탐지 효용의 격차와 이어지는지는 잰 적이 없다.** 이 문서는 그것을 재는 **진단**이다.
모델 변경·새 생성·새 학습·GPU 없음. 2013 train·dev와 이미 만든 dev 생성물(`ibm_normal_impl_v1`의 독립 생성 24개, 팔 `B`·`RA`)만 쓴다. test 미열람. 여기서 나온 것은 다음 설계의 근거일 뿐 기여 주장이 아니다.

## 0. 실행 전에 이미 아는 것 (숨김 없이)

- 등록 탐지기가 시간에서 쓰는 특성은 **둘뿐**이다: `log_gap`(직전 사건과의 간격)과 `gap_vs_med20`(그 고객의 직전 20개 간격 중앙값 대비). 달력·시각·기간 길이는 탐지기에 들어가지 않는다.
  따라서 "1년의 길이"나 시각 주기는 이 탐지기의 효용에 **직접** 영향을 줄 수 없고, 충실도와 달력 기반 사기 진입(사기 묶음 부품)의 전제로서만 문제가 된다.
- 원 진단(seed가 겹친 4개)의 특성 묶음 제거에서 간격 묶음을 빼도 격차가 줄지 않았다(.102 → .108). `ibm_normal_rows_v1`의 간격 부품 `GAP`은 효용을 내렸다(−.008).
  즉 **시간 구조가 효용 격차의 원인이 아닐 가능성**을 미리 적어 둔다. 이 진단은 그 가능성을 독립 생성 24개로 가르는 것이다.
- 가장 가까운 선행(나중에 부품을 만들 경우): Banksformer의 date mechanism(달력 특징의 분포를 곱해 날짜를 뽑음; [대조](../ibm_design_v2/PRIOR_WORK.md)). 이 진단은 부품을 만들지 않으므로 네 항목 대조는 부품 등록 때 한다.

## 1. 측정 (`scripts/diag_time_structure.py`, CPU)

실제 기준은 train 240명 부분표본 24개(seed = 20261108 + i, 행 교체 재측정과 같음), 생성 i와 부분표본 i를 짝짓는다. 탐지기 `stable`, 평가는 실제 dev.

- **T1 특성 묶음 제거.** 묶음(금액 / 간격 / 가맹점 반복 / 업종 / 채널 / 위치)을 하나씩 뺀 탐지기로 실제 부분표본과 합성(`B`, `RA`)을 각각 학습한다. 묶음 g를 뺐을 때의 격차(실제 − 합성)가 전체 특성의 격차보다 얼마나 줄어드는지를 24쌍의 짝지은 차이로 적는다.
  격차가 줄어드는 묶음 = 합성 자료가 그 특성에서 탐지기를 잘못 가르치는 곳.
- **T2 시간만 바꾸는 대조.** 다른 열은 그대로 두고 **정상 행의 간격만** 바꾼다(사기 행의 간격은 그대로).
  - `real_perm`: 실제 부분표본에서 정상 행의 간격을 고객 안에서 무작위로 섞는다(분포는 그대로, 순서·연속성·주기 제거).
  - `real_marg`: 실제 정상 행 간격의 순위는 두고 값을 `RA` 생성물의 정상 행 간격 분포로 바꾼다(순서는 그대로, 주변 분포만 합성의 것).
  - `real_both`: 둘 다.
  - `RA_marg`: `RA` 생성물의 정상 행 간격을 실제 부분표본의 분포로 바꾼다(주변 분포만 고친 합성 — 고칠 때의 상한선을 보는 대조이지 부품의 모의가 아니다).
  실제를 망가뜨렸을 때 상한이 얼마나 내려가는지, 합성의 주변 분포를 고쳤을 때 효용이 얼마나 오르는지를 짝지은 차이로 적는다.
- **T3 시간 구조 표(정상 행, 기술 통계).** 실제 train 전체·dev, train 부분표본 24개의 범위(바닥 대신), `B`·`RA`의 24개 평균:
  고객별 기간(간격의 합, 일); 간격 분위수; 구간별 비율(1분 이하 / 10분 미만 / 1시간 미만 / 1–6시간 / 6–24시간 / 1일 이상 / 7일 이상); 분 단위 정수 비율; 로그 간격의 1차 자기상관(전체, 고객 평균 제거 후);
  하루 주기와 주 주기의 집중도(고객별 사건 시각을 24시간·7일로 나눈 위상의 합 벡터 길이, 고객 중앙값 — 절대 시각이 없어도 잴 수 있다); 하루 사건 수의 분포(활동일 비율, 활동일당 사건 수, 분산 / 평균);
  개인 대비 간격(`gap_vs_med20`)의 표준편차. 부분표본 24개의 범위를 벗어난 항목을 "실제와 다른 항목"으로 표시한다.

## 2. 판정 (수치 고정)

- **J1 — 시간 구조가 효용 격차와 이어지는가.** 다음 중 하나라도 성립하면 "이어진다":
  (i) `RA`에서 간격 묶음을 뺐을 때 격차가 **.03 이상** 줄어든다(짝지은 95% 구간이 0을 넘지 않음);
  (ii) T2의 실제 망가뜨리기 중 하나가 상한을 **.03 이상** 내린다(같은 조건);
  (iii) `RA_marg`가 `RA`보다 **+.02 이상** 높다(같은 조건).
  셋 다 아니면 **"등록 탐지기의 효용 격차는 시간 구조에 있지 않다"**로 적고, 다음 정상 행 부품의 표적은 T1에서 격차를 가장 많이 줄이는 묶음으로 옮긴다.
- **J2 — 충실도.** T3에서 부분표본 범위를 벗어난 항목을 그대로 나열한다. 이것은 효용과 별개로 "시간 구조가 실제와 다른가"의 답이며, 달력 기반 사기 진입을 다시 등록할 때의 전제 조건(기간 길이)을 포함한다.
- 두 판정은 독립이다. J1이 "아니다"이고 J2에 벗어난 항목이 있으면: 시간 구조는 **충실도 문제이되 효용 문제는 아니다**로 적는다.

## 3. 한계(미리 적음)

- 등록 탐지기는 시간 특성을 둘만 쓴다. 다른 탐지기(시각·속도 특성을 쓰는 것)에서는 결론이 달라질 수 있다 — 여기의 J1은 등록 탐지기에 대한 진술이다. 탐지기를 바꾸는 것은 평가 틀의 변경이므로 이 진단의 범위가 아니다.
- T2의 대조는 간격 열만 바꾼다. 간격과 다른 열의 결합(예: 짧은 간격에서 같은 가맹점)은 실제를 섞을 때 함께 깨진다 — `real_perm`의 하락은 순서 자체와 결합의 합이다.
- dev는 부품 선택과 판정에 이미 쓰였다. 수치는 다음 설계의 방향을 정하는 데만 쓴다.
