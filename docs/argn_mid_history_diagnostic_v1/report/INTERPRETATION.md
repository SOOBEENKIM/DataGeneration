# 초기 수정 모델의 중반 간격 오류: 원인 분리 완료

2026-09-28. **생성된 개인 속도를 GMR에 넣는 경로가 중반 과대 간격의 중요한 원인으로 확인됐다. 다만 기존 보정은 단일 출력에서 과대 간격을 늘리면서도, 반복 생성에서는 간격이 지나치게 짧아지는 것을 막고 있었다. 보정을 없애는 것만으로 해결되지 않는다.** 속도 입력과 보정의 상호작용을 다음 개발 대상으로 좁힌다.

## 무엇을 고정하고 무엇을 바꿨는가

직전 초기 수정 모델 `argn_clock_initial_coupling_v1/init_only/time_head.pt`를 고정했다. 가중치 적합, 새 모델 학습, 전체 거래 생성은 모두 **0회**다. 기존 초기 mixture/가맹점/금액/라벨/길이 모델을 수정하지 않았다.

- **156회 반복 재생:** 실제 라벨 경로 및 기존 8개 생성 라벨 경로에서 시간만 1023번째까지 재생했다. 초기부터 스스로 생성한 시간 과거를 사용하되, 100–199번째 normal→normal 출력에만 등록된 개입을 적용했다.
- **96회 과거 고정 대조:** 기존 init_only 전체 생성의 실제 저장된 과거 간격으로 입력을 고정하고, 해당 구간의 다음 간격만 다시 뽑았다. 이 출력은 다음 과거로 되먹이지 않았다.
- 총 **20,790,732개 유효 시간값**을 평가했다. CPU worker 4개로 실행했고 모두 종료했다. 새 GPU 작업은 필요하지 않았다.
- 새 구현의 무개입 재생은 직전 구현과 정확히 일치했고, NumPy/Torch 모수 차이는 최대 1.78e−15였다. 모든 개입의 1–99번째 출력 동일성도 확인했다.

G/R은 생성/실제 strict-past 속도다. 두 문자는 각각 GMR과 기존 보정에 주는 입력이며, off는 해당 구간의 보정만 0으로 만드는 진단이다. 모든 실제 과거 사용 결과는 **oracle 진단**이고 새로운 자유 생성 성능이 아니다.

## 핵심 결과: 같은 고객·위치·라벨·난수의 대조

100–199번째에서 원본과 생성 라벨이 모두 normal→normal인 행을 비교했다. 생성 라벨 8경로×재생 noise 2개 =16대조의 평균이다. 각 대조의 평균 지원은 12,332거래/125.5고객이다. W1은 낮을수록 좋다.

| 대조 | 반복 입력 gap W1 | 저장 과거 고정 gap W1 |
|---|---:|---:|
| 그대로: GG_on | 0.152997 | 0.172234 |
| **GMR 속도만 실제 값: RG_on** | **0.054459** | **0.052641** |
| 보정 속도만 실제 값: GR_on | 0.168459 | 0.177766 |
| 둘 다 실제 속도: RR_on | 0.054933 | 0.054933 |
| 생성 속도 유지·보정 제거: GG_off | 0.298989 | 0.055980 |
| 실제 속도·보정 제거: RR_off | 0.105922 | 0.105922 |

GMR 속도만 교체한 개선은 반복/과거 고정 모두 **16/16대조**에서 관찰됐다. 보정 속도만 교체하면 모두 악화했다. 두 입력을 모두 교체해도 GMR 입력만 교체한 경우보다 더 좋아지지 않았다.

보정을 제거하면 과거 고정에서는 16/16대조에서 좋아졌지만, 반복 입력에서는 16/16대조에서 악화했다. **한 번의 출력만 보고 보정을 삭제했다면 잘못된 다음 변경을 선택했을 것**이다. 직접 출력 효과와 반복 입력 효과를 따로 확인한 이유다.

위 수치를 직전 전체 생성의 100–199 오류 **0.162779**와 직접 증감 비교하지 않는다. 이번은 라벨 조건이 일치하는 행에 한정한 별도 시간 재생/재표본 진단이고, 난수도 전체 native engine의 stream과 다르다. 기존 GPU 생성의 위치별 원래 지표 40개는 별도 재계산해 정확히 일치함을 확인했다.

## 오류가 생기는 방향

저장된 과거를 고정하면 생성 clock의 평균 log 편향은 +0.142925였다. 이 clock으로 GMR이 내는 보정 전 평균 log 출력의 편향은 +0.019882였고, 기존 보정은 평균 +0.141223을 더했다. 반면 실제 clock을 넣은 GMR의 보정 전 편향은 −0.109042였다. 실제 clock에서는 기존 양의 보정이 그 짧은 출력 편향을 상당 부분 상쇄한다.

따라서 보정은 언제나 나쁜 상수가 아니다. **실제 속도에서 필요한 보정과, 이미 길어진 생성 속도에서 필요한 보정이 다르다.** 보정 입력만 실제 속도로 바꾸면 양의 보정이 +0.146172로 조금 더 커져 오히려 악화한다. 실제 GMR 속도 교체의 효과가 훨씬 큰 것은 다음 출력의 기준이 되는 속도 경로를 우선 살펴야 한다는 근거다.

반복 입력에서는 이 차이가 이후 과거에 다시 반영된다.

| 구간 | 그대로: signed log gap 편향 | 보정 제거 | GMR 실제 속도 |
|---|---:|---:|---:|
| 100–149 | +0.101106 | −0.218514 | +0.040557 |
| 150–199 | +0.198544 | −0.370817 | +0.047314 |
| 100–199 전체 | +0.150153 | −0.295153 | +0.043953 |

그대로 두면 긴 간격 편향이 커지고, 보정을 완전히 없애면 짧은 간격이 다음 속도 기준을 낮추면서 반대 방향으로 틀어진다. 이 수치는 이번 고정 모델 내 개입 결과이며, 일반 ARGN 전체의 구조적 한계나 현실 고객 행동의 인과관계 증명으로 확대하지 않는다. 아직 oracle에서도 남는 오차가 있으므로 GMR의 조건부 법칙이 완벽하다고 하지 않는다.

## 학습·내부 검증에서도 같은가

동일한 100–199 normal→normal 반복 재생이다. 학습은 noise2, 내부 검증/개발의 실제 라벨 경로는 noise4다.

| 자료 | 그대로 | GMR 실제 속도 | 보정 실제 속도 | 보정 제거 |
|---|---:|---:|---:|---:|
| optimization | 0.199377 | 0.053712 | 0.243928 | 0.229056 |
| internal_validation | 0.239966 | 0.056412 | 0.280204 | 0.188009 |
| development 실제 라벨 | 0.149473 | 0.055303 | 0.173150 | 0.280742 |
| development 생성 라벨 | 0.152997 | 0.054459 | 0.168459 | 0.298989 |

GMR 실제 속도 개입의 개선과 보정 속도만 바꾼 악화는 모든 경로/noise에서 반복됐다. **보정 제거는 내부 검증의 W1만 보면 4개 중3개가 개선**됐지만, 간격 편향이 +0.239789에서 −0.182333으로 뒤집혔다. 학습·개발 및 실제 저장 생성 prefix의 반복 대조와 함께 보면 보정 제거를 일관된 해결책으로 채택할 근거가 없다.

여러 경로/noise는 독립적으로 새 모델을 학습한 seed 반복이 아니다. 고객도 공유되므로 16대조를 독립적인 16개 데이터셋의 통계적 증명으로 해석하지 않는다.

## 유지된 부분과 해석의 한계

1. 1–99는 개입 전이므로 출력이 정확히 같다. 이것은 국소 진단의 통제 조건이며 새 모델이 초반 품질 보존에 성공한 성능 실험이 아니다.
2. 개입을 끝낸 200–499의 W1은 그대로 0.074541, GMR 실제 속도 0.065736, 보정 제거 0.050188이었다. 보정 제거의 그 구간만 좋아진 것을 100–199 실패를 대신하는 근거로 쓰지 않는다.
3. 500–1023은 각각 0.104447/0.104854/0.104242로 비슷해졌다. 이번 재생은 1023까지이므로 **1024+ 전체 후반 성능을 새로 검증했다고 하지 않는다.** 이전 전체 생성의 후반 결과는 보존돼 있다.
4. GMR 실제 속도로 시간 marginal을 고쳐도 생성 과거 대비 개인 간격 관계 W1은 **0.015724→0.029466**으로 악화했다. 생성 경로의 실제 raw 과거 중앙값을 분모로 사용했다. oracle이 출력 기준만 교체하므로 이 비용이 생길 수 있고, 새 개발은 시간 전체와 개인 관계를 함께 확인해야 한다.
5. 금액·가맹점을 다시 생성하지 않았으므로 새 방법의 금액 품질·다양성·사기 시작 관계 유지 여부는 이번으로 알 수 없다. 라벨 경로도 고정했다.
6. 기존 학습 metadata와 원본 prepared 자료 사이에 알려진 간격 표현 차이 1건(event_index 384)이 있다. 주요 진단인100–199와 그 이전 과거는 정확히 같으며 영향이 없다. 이후 재생 지표는 기존 metadata 표현을 사용하고, 원래 전체 생성 지표 재현은 원본 prepared 표현을 사용했다. 이를 동일한 전체 원시 경로라고 혼용하지 않는다. `INPUT_REPRESENTATION_NOTE.json`에 구체적 차이를 기록했다.

## 다음 개발 판단

**초기 출력 수정은 유지하고, GMR이 사용하는 생성 개인 속도와 출력 보정의 연결을 수정하는 쪽으로 좁힌다. 기존 보정을 일괄 삭제하거나 보정 쪽 입력만 실제 속도에 가깝게 만드는 방식은 채택하지 않는다.**

다음 학습 후보는 실제 거래의 과거를 생성 때 가져오지 않으면서, 생성 속도의 편향이 GMR의 기준으로 그대로 되먹임되는 정도를 줄이는 작은 변경이어야 한다. 같은 정보·용량의 단순 보정 강도 조절과 비교하고, 실제 생성 이력에서 100–199/전체 시간 및 개인 대비 간격 관계를 동시에 확인해야 한다. 이번 결과는 수정할 경로를 좁힌 근거이지, 특정 새로운 보정식이나 안정화 구조가 반드시 성공한다는 보장이 아니다. 그 구조와 학습은 아직 실행하지 않았다.

[Lin et al.2026 §III-B](https://arxiv.org/html/2604.27182v1)의 조건부 출력/입력 분포 구분과 [He et al.2021 §4–5](https://aclanthology.org/2021.emnlp-main.415.pdf)의 prefix 교체 대조를 참고했다. 이번은 이 선행의 전체 방법 재현, 새로운 누적오차 이론, 최신 모델 대비 우위 입증이 아니다.

원본 head·생성 결과·등록 조건을 모두 보존했다. 이전 artifact 309개 hash와 기존 생성 위치 지표 40개를 확인했고, 최종 test 거래는 읽지 않았다. **모델 교체·commit·push 없음, 실행 중 실험 없음.** 상세 표는 `TARGET_MEANS.csv`, `paired_contrasts.csv`, `mean_diagnostics.csv`; 실행 감사는 `FINAL_AUDIT.json`; 그림은 `clock_correction_diagnosis.pdf`다.
