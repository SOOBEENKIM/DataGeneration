# sparkov_transfer_v1 — 두 번째 데이터(Sparkov)에서의 재현: 같은 절차로 구조를 재고, 있는 구조의 부품만 적용 (등록 2026-11-10, 실행 전)

사용자 지시(2026-11-10): "Sparkov부터 진행"(모델 고정 후 최종 확인의 첫 단계; 봉인 test는 이 단계에서 열지 않는다). IBM에서 채택한 모델은
[ibm_merchant_marginal_v2](../ibm_merchant_marginal_v2/RESULTS.md)의 스택이다.

## 0. Sparkov는 IBM과 구조가 다르다 (fraud_structure_v1 `sparkov/REAL_STRUCTURE.csv`, train 688명 / dev 147명)

| 구조 | IBM | Sparkov | 함의 |
|---|---|---|---|
| 사기 행 비율 / 사기 고객 비율 | .12% / 15% | .57% / 77% | 라벨 과정이 다름 |
| 정상 행 새 가맹점 비율(습관) | .08 | **.37**(가맹점 693개를 거의 고르게 방문) | 습관 구조 약함 |
| 사기 대 정상 새 가맹점 | .55 대 .08 | .52 대 .37 | 대비 약함 |
| 가맹점 → 업종 | .999 | .992 | 종속 있음 |
| 채널 열 | 있음(지배 신호) | **없음** | 채널 부품 해당 없음 |
| 구간 내 간격 대 정상 간격 | 36분 대 221분 | 64분 대 275분 | 몰아치기 있음 |
| 구간 직후 간격비 | .5–.6(빨리) | **1.4–1.5(늦게)** | 방향 반대 — 표가 데이터에서 읽어야 함 |
| 진입 금액 / 개인 중앙값 | 3.0배 | 7.6–8.6배 | 금액 도약 큼 |

따라서 "IBM 스택을 그대로 붙여 같은 수치가 나오는가"가 아니라 **IBM에서 쓴 절차 — 구조를 재고, 실제에 있는데 생성기가 놓치는 구조에만 그 부품을 넣는다 — 가 다른 데이터에서도 작동하는가**를 본다.
Sparkov는 모의 생성 데이터이고 dev 147명의 실제 효용 상한 표준편차가 .17이라 좋은 생성기들 사이를 효용으로 가르지 못한다([fraud_utility_v1](../fraud_utility_v1/RESULTS.md)) — 효용 판정은 거칠게만 한다.

## 1. 단계

- **기본 스택 `sf_base`**(IBM의 State-First 최소 인스턴스와 같은 구성): 기존 원형 ARGN(`sparkov_argn_control_v2`의 `native_20260928/29`, 작업공간은 이 연구 폴더로 **복사**해 원본 불변) +
  Sparkov train으로 추정한 전이표(라벨 먼저) + 라벨 라우팅 사기 출력층(`routed_subst`; 열 = 간격·금액·업종; fit별 학습, 내부 검증 사기 행 CE로 조기 종료 — IBM과 같은 설정).
- **부품 적용 규칙(사전 고정)**: 각 부품은 (i) 그 구조가 실제 Sparkov에 있고 (ii) `sf_base`의 해당 지표가 바닥 3배 이상(또는 일치율 차 ≥ .05)일 때만 넣는다.

| 부품 | 대상 지표 | (i) 실제 구조 |
|---|---|---|
| 구간 위치 간격 표(`table_kind`) | 구간 내 간격 W1, 구간 후 간격비 W1, 구간 시간폭 | 있음(64분 대 275분; 간격비 1.4–1.5) |
| 가맹점 → 업종 일관성(업종 표; 채널 없음) | 정상 행 업종 = 가맹점 일치율(실제 .992) | 있음 |
| 이력 참조 가맹점(게이트·방문율 포인터·사기 풀) | 사기 새 가맹점, 고객당 가맹점 수, 정상 새 가맹점 | 약함(.52 대 .37) — 지표가 3배 이상일 때만 |

- **최종 스택 `sf_full`** = `sf_base` + 규칙을 통과한 부품. 표는 모두 Sparkov train만으로 추정, 새 backbone 학습 0.

## 2. 가설과 사전 판단 (fit 2 × 생성 2 평균)

- **T1 (라벨 과정).** `sf_base`의 지속률·사기 고객 수·고객당 구간 수 바닥 배 ≤ 3(원형은 크게 벗어남). 전이표 상태 과정이 데이터를 바꿔도 작동하는지.
- **T2 (절차 재현).** 적용된 각 부품이 자기 대상 지표를 바닥 3배 안으로 넣고, 다른 표준 지표를 3배 밖으로 밀지 않는다. 규칙상 적용되지 않은 부품은 "구조 없음/이미 맞음"으로 기록 — 그것도 절차의 결과다.
- **T3 (효용, 거칠게).** Sparkov 등록 탐지기 TSTR에서 `sf_full` ≥ 원형 ARGN + .10이고 실제 부분표본 상한 분포(평균 ± 1 표준편차) 안. `sf_full` 대 `sf_base`의 우열은 차이가 상한 표준편차(.17)보다 작으면 판정하지 않는다.
  이전 Sparkov 파이프라인의 결과(`gap_and_transition` 등)는 참고로 함께 적되 코드 경로가 달라 직접 비교로 쓰지 않는다.
- **T4 (대조).** 모든 표준 지표 바닥 배 ≤ 3. 넘으면 그 부품은 Sparkov에서 채택하지 않는다.
- 실패도 결과다: T1이 실패하면 "전이표 상태 과정의 일반화 실패"로, T2가 실패하면 그 부품의 Sparkov 실패로 기록한다. IBM 채택 결정은 바뀌지 않는다.

## 3. 선행·주장

새 부품 없음(IBM 단계들의 선행 비교를 그대로 따른다). 이 단계의 주장은 "절차의 재현"이며 Sparkov에서의 최고 성능이 아니다. 시각(야간 비율) 구조는 어느 모델에도 시간 열이 없어 다루지 않는다.

## 4. 실행

- 스크립트 `scripts/run_sparkov_transfer.py`(전이표 → 출력층 학습 → `sf_base` 생성 → 구조 측정 → 부품 추정 → `sf_full` 생성). 평가: `run_fraud_structure.py --dataset sparkov`,
  `run_rare_state_persistence.py --dataset sparkov`, `run_fraud_utility.py --dataset sparkov`(등록 탐지기; `stable`은 보조).
- 예산: 출력층 학습 2회(각 ≤ 10분), 생성 ≤ 12(각 ~1분), 평가 ~30분. GPU 1개. 산출 `artifacts/sparkov_transfer_v1/`, 기록 `RESULTS.md`. Sparkov의 test 분할은 읽지 않는다(dev만).

## 수정안 1 — 규칙 적용 결과와 팔 확정 (2026-11-10, `sf_base` 평가 후·부품 생성 전)

`sf_base`(4 생성) 측정으로 적용 규칙을 판정했다(바닥 배; `docs/fraud_structure_v1/sparkov`, `docs/rare_state_persistence_v1`):

| 부품 | `sf_base` 대상 지표 | 판정 |
|---|---|---|
| 구간 위치 간격 표 | 구간 내 간격 1.72, **구간 후 간격비 3.22**, **구간 시간폭 11.4** | **적용** |
| 가맹점 → 업종 일관성 | 정상 행 일치 **.22–.27**(실제 .992) | **적용** |
| 이력 참조 가맹점 | 사기 새 가맹점 1.11, 고객당 가맹점 수 1.36, 정상 새 가맹점 .374(실제 .384) | **적용 안 함**(이미 맞음 — Sparkov에는 습관 구조가 없어 원형이 재현) |

- 사기 행의 업종 규칙(train 사실로 결정, `DIAG_FRAUD_CATEGORY.json`): train에서 사기 행도 가맹점 → 업종을 따른다(.994). 그러나 `sf_base`가 사기 행에 고른 가맹점이 함의하는 업종 분포는 train 사기 업종
  분포와 TV .230(사기 출력층이 낸 업종은 .126, 바닥 .032)이다 — 사기 행에 업종 규칙을 그대로 적용하면 사기 업종 분포가 **나빠질 것으로 예측**된다. 원인은 사기 행의 가맹점 선택이 사기 업종
  (grocery_pos·shopping_net·misc_net 집중)을 모른다는 것이고, 이를 고칠 부품(업종 먼저 고르는 사기 가맹점 선택)은 이번 적용 대상에 없다.
- 팔: `sf_gap`(간격 표), `sf_attr`(업종 규칙, **정상 행만**), `sf_full` = `sf_base` + 간격 표 + 정상 행 업종 규칙, 그리고 예측 확인용 `sf_attr_all`(사기 행까지; 사기 업종 TV가 나빠지는지 확인).
  각 4 생성. 사기 행의 가맹점-업종 불일치는 Sparkov에서 **미해결**로 기록한다.
- T1 중간 결과(기록): 지속률 3.7배(.897 대 .911), 사기 고객 수 6.75배(92–96명 대 114명), 첫 사건 사기 3.25배 — 3배를 넘는다. Sparkov는 사기 고객마다 구간이 거의 1개인 모의 데이터라
  (train 533명에 548구간), 고객을 가리지 않는 전이표의 평균 위험률은 "사기를 한 번이라도 겪는 고객 수"를 낮게 낸다. T1은 부분 실패로 판정될 예정이며 최종 스택에서 다시 잰다.
