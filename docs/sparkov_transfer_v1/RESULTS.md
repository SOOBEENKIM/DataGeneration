## 2. 판정

- **T1 부분 실패.** 구간 길이(1.05배)·진입률(2.35배)은 맞지만 지속률 3.73배(.897 대 .911), **사기 고객 수 6.75배**(94명 대 114명), 첫 사건 사기 3.25배. Sparkov는 사기 고객마다 구간이 거의 1개인
  모의 데이터라, 고객을 가리지 않는 평균 위험률 전이표로는 "한 번이라도 사기를 겪는 고객 수"가 낮게 나온다. 전이표 상태 과정은 **구간의 모양**은 옮기지만 **고객 간 배분**은 이 데이터에서 못 맞춘다.
- **T2: 절차는 재현.**
  - 적용 규칙이 고른 **간격 표**는 구간 내 간격 1.72 → 0.96배, 구간 후 간격비 3.22 → 2.95배, 사기 간격 2.67 → 0.94배, 진입 개인 대비 간격 3.29 → 1.82배로 대상 지표를 3배 안에 넣었다. IBM과 반대 방향인
    "구간 직후 거래가 늦게 온다"도 표가 데이터에서 그대로 읽었다. 구간 시간폭은 11.4 → 8.65배로 줄었으나 3배 밖(미해결).
  - 규칙이 **적용하지 않기로 한** 가맹점 선택 부품: 해당 지표가 1.1–1.4배로 이미 맞았다 — Sparkov에는 습관 구조가 없다는 측정과 일치.
  - **업종 규칙(정상 행)** 은 일치율을 .24 → .99로 올리지만 업종×금액 쌍 TV를 4.11 → **5.79배**로 악화시킨다(T4 위반). 금액은 업종보다 먼저 가맹점 임베딩에 조건부로 생성되는데, 업종을 가맹점에
    맞추자 "업종–금액" 결합이 backbone의 약한 "가맹점–금액" 조건화에 의존하게 됐다. **Sparkov에서는 채택하지 않는다.**
  - 사기 행까지 적용한 진단 팔은 train 사실로 예측한 대로 사기 업종 TV 2.17 → 3.26배, 구간 내 업종 반복 1.08 → 15.8배로 나빠졌다(예측 확인).
- **T3 충족(거칠게).** 등록 탐지기 효용 .148 → **.33**(원형 + .10 이상, 상한 분포 .317 ± .174 안), `stable` .598 → **.79–.80**. `sf_base`·`sf_gap`·`sf_full`의 차이(.01 안팎)는 판정하지 않는다.
- **T4.** `sf_gap`은 표준 지표를 바꾸지 않는다(기본 스택에서 이미 3배를 넘던 업종×금액 쌍 4.11은 원형 4.14에서 온 것). `sf_attr`·`sf_full`은 5.79배로 위반.
- **Sparkov 채택 스택 = `sf_gap`**(원형 + 전이표 + 라벨 라우팅 출력층 + 구간 위치 간격 표).

## 3. 해석 — 무엇이 재현됐고 무엇이 아닌가

- **재현된 것**: (i) 상태를 먼저 정하고 사기 행을 따로 내는 최소 구성이 원형 대비 효용과 구간 구조를 크게 올린다(두 데이터 모두). (ii) "실제에 있는데 생성기가 놓치는 구조에만 부품을 넣는다"는 규칙이 Sparkov에서
  다른 부품 조합을 골랐고, 고른 부품은 대상 구조를 고쳤으며, 고르지 않은 부품은 실제로 필요 없었다. (iii) train 사실로 한 예측(사기 행 업종 규칙이 해롭다)이 생성 결과와 맞았다.
- **재현되지 않은 것**: IBM의 5부품 스택은 그대로 옮겨지지 않는다. IBM에서 가장 큰 이득을 준 가맹점 속성 일관성이 Sparkov에서는 대조 기준을 어긴다. 그리고 현재 코드 경로의 Sparkov 스택(`stable` .80)은
  Sparkov 전용으로 만든 이전 파이프라인(.82–.85)보다 낮다 — 차이는 **사기 금액**(16.5배 대 2.07배)이다. Sparkov의 지배적 구조는 진입 금액 도약(개인 중앙값의 7.6–8.6배)인데 현재 사기 출력층이 이를 못 잡는다.
- 따라서 주장할 수 있는 것은 "하나의 고정된 아키텍처가 두 데이터에서 최고"가 아니라 **"구조를 재고 빠진 구조에 부품을 넣는 절차가 두 데이터에서 작동하며, 데이터마다 필요한 부품이 다르다"** 이다.

## 4. 남은 것 (Sparkov)
