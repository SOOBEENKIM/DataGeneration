[프로토콜](PROTOCOL.md)과 수정안 1–2(모두 실행 전 등록). 2013 train·dev만 사용, test 미열람. 새 학습 0. 1단계는 CPU 모의, 2단계는 dev 문맥 4 생성(fit 2 × seed 2, GPU가 다른 사용자 작업으로 차 있어 **CPU로 생성**,
생성당 약 3분; 다른 작업은 건드리지 않음) + 구조·1단계·효용 평가.

### 판정 (등록한 수치 그대로)

- **E1 일부 미달.** 사기율 .00154 = train의 **+33%**(기준 ± 15%; 현재 +66%). 사기 고객 수 30.5명(범위 20–36 안, 충족), 고객당 최대 28–42건(≤ 54, 충족; 현재 74–83).
- **E2 근소하게 미달.** 사기 행 상대 위치 평균 .625 — 기준(.73 ± .10)의 하한 .63에 .005 못 미친다(현재 .53).
- **E3 충족.** 지속률 1.21배, 구간 길이 1.14배, 구간 내 간격 1.35배(모두 ≤ 3).
- **E4 충족(근소).** 효용 .464 ≥ .461. 채택 모델 .491보다 높지 않다. 로지스틱 탐지기에서는 .530 대 .577.
- **E5 일부 미달.** 표준 지표는 유지(고객당 가맹점 수 1.22 → 1.41). 가맹점 구조에서 사기 새 가맹점 1.85 → 2.22(+.37), 공유 사기 가맹점 2.50 → 2.93(+.43)으로 +.3을 넘는다(둘 다 3배 안).
- **결론(등록 규칙): 일부만 충족 → 채택하지 않는다.** 채택 모델의 라벨 과정은 그대로다.

### 나아진 것과 그렇지 않은 것

- 나아짐: 사기율 초과 +66% → +33%, 고객당 최대 사기 수 74–83 → 28–42, 묶음 시작 위치 3.7 → 2.2배, 묶음 간 간격 2.6 → 1.7배, 사기 금액 변동 4.1 → 2.6배.
- 나빠짐: 사기 고객의 길이비 0.96 → 2.68배(아래 §3-2), 사기 금액 2.39 → 2.96배, 야간 비율 8.2 → 10.3배.
- **효용은 오르지 않았다.** [진단 D2](../ibm_gap_diag_v1/RESULTS.md)와 맞는다 — 효용 격차는 사기 행이 아니라 정상 행에 있다. 사기 묶음 상태는 **충실도** 쪽 수정이지 효용의 지렛대가 아니다.

## 3. 이 단계에서 새로 확인한 것

1. **같은 생성 seed를 쓰면 두 fit의 사기 위치가 겹친다.** 라벨이 표에서 나오므로 난수열이 같으면 fit이 달라도 같은 고객·같은 위치에 사기가 생긴다: 이 팔에서 seed 11은 사기 고객 28 / 26명 중 11명, seed 12는 33 / 35명 중
   15명이 같고(사기 행 94 / 157개의 위치가 동일), 채택 모델은 32 / 34명 중 24명, 39 / 43명 중 34명이 같다(다른 seed끼리는 6명 = 우연 수준). 즉 **"fit 2 × seed 2 = 4 생성"은 라벨에 대해 독립 표본이 약 2개**다.
   지금까지 표를 쓴 모든 팔의 라벨 통계(사기율·구간 수 등)와 그 표준편차가 이 영향을 받는다. 모의의 회당 표준편차(사기 건수의 약 21%)로 보면 ± 15% 기준은 생성 4개로 가를 수 없는 기준이었다 — E1 등록 수치의 설계 결함으로 기록한다.
   생성물 경로 위의 교사 강제 기대는 335 / 447 / 310 / 476건으로 실제 생성(355 / 465 / 329 / 507)과 가깝다 — 생성기는 표를 따르고 있고, 예측(약 320건)과의 차이는 표본 변동으로 설명될 수 있는 크기다(확정은 아님).
2. **실제 사기 진입은 "사건당"이 아니라 "고객당"이다.** 실제 train에서 사기 고객의 거래 수는 다른 고객의 1.06배(1,184 대 1,116)인데, 사건당 위험률 모형이면 1.26배가 나와야 하고 생성물은 1.2–1.4배(1,300–1,570 대 1,070–1,100)다.
   거래가 많은 고객일수록 사기를 더 겪게 만드는 것은 자료에 없는 구조다. 진입은 달력 시간당 위험률로 두는 것이 맞다.
3. **생성된 "1년"의 길이가 280–540일**(실제는 모두 364일)이다. 달력 시계가 틀리므로 달력 기반 진입률은 간격·시간 구조를 먼저 고쳐야 제대로 작동한다(수정안 2는 임시 처리).
