# ibm_merchant_attr_v1 — 가맹점 속성 일관성: 가맹점이 업종·채널을 정하고, 사기 상태에서는 채널만 상태가 정한다 (등록 2026-11-10, 실행 전)

사용자 지시(2026-11-10): "진단 먼저" → 진단 [ibm_row_joint_diag_v1](../ibm_row_joint_diag_v1/RESULTS.md)이 원인을 특정했고, 그 프로토콜이 "원인이 특정되면 부품은 별도 등록"으로
정해 두었다. 이 문서가 그 등록이다.

## 0. 설계 대상과 근거

- 실제 구조(IBM 2013): 정상 행에서 가맹점 → 업종 일치 .999, 가맹점 → 채널 일치 1.000. 사기 행에서 업종은 여전히 가맹점을 따르고(.996) 채널은 따르지 않는다(.315;
  "평소 대면인 가맹점에서의 온라인 거래"가 사기 행의 68.5%, 정상 행의 0.0%). 이 조합이 지배적 사기 신호다(행 단독 TSTR: 업종+채널 묶음 .375, 각각 단독 .012 / .013).
- 남은 문제의 증거: ARGN 현재 모델의 정상 행은 업종 일치 .306, 채널 일치 .839, "대면 가맹점 온라인" 8.4%; 사기 행 업종 일치 .058. 행 단독 TSTR .109(RTF .337, 상한 .435–.458).
  정상 행의 업종·채널을 가맹점 기준으로 재구성한 가상 실험에서 효용 .334 → .466, 사기 행까지 .476(what-if; 생성 후 편집).
- backbone 원인: ARGN은 열별 범주 예측이며 가맹점 9,411 코드 + `_RARE_`의 임베딩으로 업종·채널을 **느슨하게** 조건화한다. 가맹점 부품이 가맹점을 고른 뒤에는 그 선택과
  backbone의 업종·채널 예측이 더 어긋난다(업종 일치 원형 .48 → 현재 .31). RTF는 토큰 조건화로 이 종속을 지킨다(1.000).

## 1. 부품 (동결 ARGN + 현재 모델 위, 새 학습 0; 표는 train만)

현재 모델 = `native_{fit}` + 전이표(라벨 먼저) + `routed_subst` 사기 출력층 + 가맹점 부품 `full` + 간격 표 `table_kind`. 생성 순서는 라벨 → 간격 → 가맹점 → 금액 → 업종 → 채널.
그 행에서 이미 뽑힌 가맹점 코드 m과 라벨 상태로 업종·채널의 출력을 대체한다.

| 행 | 업종 | 채널 |
|---|---|---|
| 정상, 알려진 가맹점 | 표 P(업종 \| m) | 표 P(채널 \| m) (train 정상 행) |
| 정상, `_RARE_` | 표 P(업종 \| `_RARE_`, 정상) | 표 P(채널 \| 업종, `_RARE_`, 정상) |
| 사기, 알려진 가맹점 | 표 P(업종 \| m) | 상태 표 P(온라인 \| 사기, m이 그 고객에게 새/반복) ([수정안 4](../ibm_merchant_memory_v1/RESULTS.md)의 2칸 표) |
| 사기, `_RARE_` | 사기 출력층 그대로 | 상태 표 |

- 표 추정: 그 fit의 ARGN 인코딩 자료(train 고객 전체)에서 가맹점 코드별 업종 코드·채널 코드 빈도(평활 없음 — 실제 종속이 결정적이므로; 가맹점 코드가 train 인코딩 자료에
  없으면 backbone 출력 유지). 채널-by-가맹점 표는 정상 행만으로 추정(사기 행은 채널이 가맹점을 따르지 않으므로).
- 사기 출력층의 라우팅 hook 뒤에 적용(게으른 등록). backbone·출력층 가중치, 라벨 과정, 간격, 가맹점 선택, 금액은 그대로.

## 2. 가장 가까운 선행 (2026-11-10 재검색; 초록 수준 확인, 본문 전체는 읽지 않음)

| 요소 | 선행 | 겹침 | 차이 |
|---|---|---|---|
| 종속 열을 규칙으로 재구성 | Umesh et al. 2025, HFGF (arXiv 2507.19211): 독립 열 생성 후 FD/LD 규칙으로 종속 열 재구성 | **구조가 같다**(결정 열 → 종속 열을 모델 밖 표로) | 규칙이 전역. 우리는 라벨 상태가 종속을 켜고 끈다(사기 상태에서 채널만 가맹점 종속 해제), 시퀀스 생성 도중에 적용해 다음 행의 이력이 일관된 값을 본다 |
| 생성기의 종속 미보존 측정 | Umesh et al. 2024 (arXiv 2409.17684) | "생성기가 함수 종속을 못 지킨다"는 관측 | 그 위반이 **희귀 클래스 탐지 효용을 무너뜨리는 경로**(정상 행의 위반이 사기 전용 조합을 오염)는 다루지 않음(초록 기준) |
| 제약 층 | Stoian et al., ICLR 2024 (arXiv 2402.04823): 제약을 층으로 넣어 위반 0, 효용 최대 +4.5% | 생성 시 제약 강제 | 선형 부등식 등 사전 지정 제약; 범주 간 함수 종속의 클래스 조건부 해제는 아님(초록 기준) |
| 토큰 조건화 | REaLTabFormer | 종속을 학습으로 지킴(이 데이터에서 1.000) | 별도 기제 없음 — RTF에는 이 부품이 필요 없다 |
| 이 연구 | 수정안 4의 채널 표, 가맹점 부품 | 부품의 재료 | 이번에 정상 행까지 확장해 하나의 규칙으로 묶음 |

**새로움 주장 범위**: FD 재구성 자체는 HFGF가 선행한다. 읽은 범위에서 겹치지 않는 것은 (i) "종속이 클래스에 따라 달라진다(정상에서는 성립, 사기에서는 채널만 해제)"를 데이터에서
재고 그대로 부품으로 쓴 점, (ii) 정상 행의 종속 위반이 희귀 클래스 TSTR 효용을 무너뜨린다는 경로의 실증(교체 실험)이다. 없다고 단정하지 않는다.

## 3. 가설과 사전 판단 (fit 2 × 생성 2 평균)

- **F1 (구조).** `attr_all`에서 정상 행 업종 일치 ≥ .99·채널 일치 ≥ .99(알려진 가맹점), 정상 행 "대면 가맹점 온라인" ≤ .005, 사기 행 업종 일치 ≥ .90, 사기 온라인 비율 .77 이상,
  사기 행 채널-가맹점 일치가 실제(.315) ± .10.
- **F2 (효용, 등록 탐지기).** `attr_all` 또는 `attr_normal` ≥ **.448**(RTF+전이표)이면 "ARGN 모델이 시험한 것 중 최고"로 기록하고 채택. .40–.448이면 "부분(현재 .331 대비 이득)"으로
  채택하되 최고 주장 없음. < .40이면 what-if와 실제 부품의 차이 원인(다음 행 이력 효과 등)을 기록. 보조 탐지기 3종은 분해 보고.
- **F3 (ablation = 설명).** `attr_cat`(업종만), `attr_chan`(채널만), `attr_normal`(정상 행만), `attr_all`. 진단상 신호가 업종 × 채널 **결합**에 있으므로 `attr_cat`·`attr_chan` 단독은
  `attr_normal`보다 뚜렷이 낮아야 하고, `attr_normal` ≈ `attr_all`(사기 행 몫은 작음)이 예상이다. 어긋나면 그대로 기록.
- **F4 (대조; 수정안 1 기준).** 라벨 과정 동일, 표준 지표 바닥 배 ≤ 3, 가맹점 구조(새 가맹점·고객당 가맹점 수)와 간격 구조(구간 내 간격·구간 후 간격비) ≤ 3배 유지.
  표준 업종 TV·사기 업종 TV의 변화는 방향과 함께 보고(악화가 3배를 넘으면 그 팔은 무효).
- 효용 주장 단서(미리 적음): 이 이득은 탐지기가 업종 × 채널을 볼 때의 이득이다. `no_channel` 보조 탐지기에서는 사라질 것으로 예상하며 그대로 보고한다.

## 4. 설계

| 팔 | 정상 행 | 사기 행 | 생성 |
|---|---|---|---|
| 참조 `table_kind`(현재 모델) | backbone | 사기 출력층 | 기존 4 |
| `attr_cat` | 업종 표 | 업종 표 | 4 |
| `attr_chan` | 채널 표 | 상태 표 | 4 |
| `attr_normal` | 업종·채널 표 | 사기 출력층(그대로) | 4 |
| `attr_all` | 업종·채널 표 | 업종 표 + 상태 표 | 4 |

- fit 20261108/09 × seed 20261011/12. 평가: 구조(바닥 재사용) · 1단계 · 효용 4종 · 일관성 측정(`diag_row_joint_fd.py`의 C1을 새 팔에 적용).
- 예산: 표 추정 < 1분, ARGN 생성 16(각 ~75초), 평가 ~45분. 스크립트 `scripts/run_ibm_merchant_attr.py`, 모듈 `benchmarks/argn_merchant_attr.py`.
- 하지 않는 것: backbone 재학습, RTF 적용(필요 없음), 금액의 가맹점 조건화, Sparkov, 봉인 test.
