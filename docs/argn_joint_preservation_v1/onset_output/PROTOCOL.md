# 사기 시작 거래의 조건부 금액 출력 대조 — 2026-09-27 등록

앞선 결합 대조의 전체 개인 대비 금액 W1은 개선됐지만, 시작 거래만 보면
0.400→0.528(고객 count context 제거 팔)로 악화했다. 실제 과거와 현재
라벨·업종·간격을 제공해도 시작 거래 금액 W1은 optimization0.250/0.140,
development0.285/0.146이며 지속 거래보다 크다. **조건부 학습 부족과
자유 생성 조건 변화가 모두 남아 있다.** 시작 거래는 optimization433,
internal-validation48, development102건이다.

고정 기준은 앞선 `count_hazard_no_context`의 저장된 길이/초기 상태 혼합분포,
노출 hazard, 업종·간격·금액 출력이다. 이것을 이번 국소 대조의 기준으로
쓴다는 것이 전체 연구 기준으로 이미 승격했다는 뜻은 아니다. 새 생성 seed
확인은 병행하며, 기존 원형과 모든 실패 팔을 계속 보존한다.

## 선행 방법 및 이번 가설

[TabCascade 2026 v3 §4.1](https://arxiv.org/html/2601.22816v3)의 조건부 수치
출력, [OmegaSDS 2026 §2](https://arxiv.org/html/2605.06315v1)의 상태별 전이와
출력 결합처럼, 상태 조건부 출력/전문가 자체는 알려져 있다. 기존 저장소의
라벨별 expert 대조도 이미 있다. 이번은 새 이론이 아니라 **사기 라벨 안의
드문 시작 거래를 별도로 학습하면 남은 오류를 줄이는가**를 확인한다.
전환 확률을 class balance로 바꾸지 않고 조건부 금액 출력만 바꾼다.
TabDiT의 길이·내용 공동 생성과의 중복도 별도 참고문서에 기록했다.

## 제거·용량 대조

- `onset_fit`: 회복된 금액 head를 복제해 정상→사기 시작 거래만으로 미세조정.
- `all_fraud_fit`: **동일 복제 구조·초기값·optimizer·최대step**을 전체 사기
  거래로 미세조정. 둘 다 생성에서 시작 거래에만 적용하므로 용량 증가와
  출력 교체 자체를 대조한다. 학습 자료의 구간별 비중만 다르다.
- 두 팔 모두 internal-validation의 시작 거래 NLL로 checkpoint 선택한다.
  초기 step0도 후보. lr1e-4, AdamW decay0.001, batch256, max1000step,
  매50step 평가, patience5, clip1. development로 checkpoint를 고르지 않는다.
- 이전의 검증된 실제 이력 cache를 hash로 고정하고 재사용한다. encoder,
  전환·길이·초기상태·업종·간격 및 기존 금액 head는 모두 고정한다.
- 생성 시 현재 생성 라벨1, 직전 생성 라벨0, 과거 거래 존재 조건에서만
  새 금액 head를 사용한다. 첫 거래/사기 지속/정상 거래에는 기존 head를 쓴다.
  변경된 과거 금액이 이후 생성에 미칠 영향은 별도 평가 대상이다.

부모2seed × 2학습 팔 =4작은 head학습. 각2draw로8새 전체 생성.
기준의 이미 저장된4생성은 재사용한다. 동일 draw에서 길이와 라벨열은 기준과
정확히 같아야 하므로 고객 사기 구성과 사기율을 금액 수정으로 바꾸지 않는다.
새 전문가를 제거하면 코드 경로는 앞선 고정 기준으로 돌아간다.

## 판단

실제 이력 시작 거래 NLL 및 생성 금액/개인 대비 금액이 개선되는지 확인한다.
전체만 좋아지고 시작 거래가 악화하면 성공으로 보지 않는다. 지속 거래·정상
품질·사기 간격·다양성의 모든 비용을 함께 보고한다. 큰 비용 제외 기준은
앞선 +0.05 W1/TV, 고객 수 +5오차, 다양성5% 감소를 그대로 적용하고, 허용
범위 내 악화도 숨기지 않는다. 두 부모에서 방향이 다르면 안정된 개선으로
승격하지 않는다. 최종 test event는 읽지 않는다.
