# 공동 관계 개선 이후의 실행·판단 순서 — 2026-09-27

이 문서는 완료 결과 이후의 후속 계획이다. 새 학습이나 직접 baseline 비교를
완료했다고 의미하지 않는다. 연구를 중단하지 않으며, 이미 확인한 개선을
보존한 상태에서 남는 오류를 겨냥한 방법과 가까운 선행의 차이를 검증한다.

## 1. 비교 기준과 남는 문제

MODEL_REGISTRY.json의 마지막 후보와 수정 전 강한 기준을 모두 유지한다.
개인 대비 사기 금액 W1 0.180→0.114, 사기 경험 고객 102.1→116.1의 개선은
출발점이다. 동시에 사기 간격 0.123→0.137, 정상 금액 0.058→0.063의 비용이
있다. 현재 결과는 2부모 학습×4생성 seed이며 독립 8학습 결과가 아니다.

다음 질문은 **개인 행동과 사기 구간을 고려한 동일 조건에서도 오차가 남으며,
전환과 출력을 함께 학습해야만 그 오차를 줄일 수 있는가**다. 아직 공동 학습이
해결책이라고 결론 내리지 않는다. 모든 지표를 0으로 만드는 것을 연구 완료
조건으로 삼지도 않는다.

## 2. 바로 다음 진단: 남은 비용이 발생하는 위치

기존 원본/생성 결과와 저장 checkpoint부터 사용한다. 추가 대규모 학습 전에
다음 결과표를 만든다. 이미 끝난 구버전 진단을 새 후보의 결과로 대신하지 않는다.

- 정상→사기 시작, 사기 지속, 사기→정상 복귀, 그 밖의 정상 거래를 구분한다.
  첫 관측부터 사기인 고객은 별도로 둔다. 개인 활동량과 과거 금액 수준도
  optimization에서 고정한 구간으로 구분하고 각 셀 고객 수/거래 수를 함께 적는다.
- 사기 간격·정상 금액 비용을 구간 구성의 변화와 같은 조건 안의 출력 오차로
  나눈다. 가중 표준화는 진단이며 실제 자유 생성의 개선으로 보고하지 않는다.
- 남는 조건에서 실제 과거를 제공한 출력과 자유 생성 출력을 대조한다.
  자유 생성에는 정답 미래 라벨, 실제 전체 길이, 고객 정답 사기 비율을 넣지 않는다.
- 개인 금액 기준이 사기 구간 안에서 어떻게 변하는지도 확인한다. 평가용 과거20건
  중앙값은 그대로 유지하고, 정상 과거로 계산한 기준은 원인 진단으로만 추가한다.

실제 과거에서도 틀리면 출력 학습/표현을 우선한다. 실제 과거에서는 맞고 자유
생성에서 악화하면 생성된 개인 상태·구간 구성과 출력의 연결을 우선한다.
구성 변화로 설명되면 그 사실을 보고하고 불필요한 출력 모듈을 추가하지 않는다.

## 3. 연구 후보와 구별 실험

남는 개인 조건 오류가 확인되면 ARGN 본체를 유지하면서, 엄격한 과거에서 계산한
개인 행동과 현재 사기 구간을 같은 상태 표현으로 전환·간격·금액에 연결하는
후보를 검토한다. 상태는 실제 이력으로 학습하고 생성 시 생성 이력으로 갱신한다.
최근 개인 금액/간격/업종·방문 이력과 이미 관측된 구간 나이가 후보 입력이다.
구체 입력, 손실, 학습량은 위 진단 및 선행 방법과의 대응을 기록한 뒤 고정한다.

필수 대조는 현재 기준, 전환에만 상태 입력, 출력에만 상태 입력, 양쪽에 각각
독립 상태 입력, 양쪽에 공유 상태 입력이다. 마지막 두 비교가 없으면 단지 입력이
늘어난 효과를 공동 학습 효과로 주장할 수 없다. 학습량과 용량을 맞춘 대조를 둔다.
같은 라벨/길이를 고정한 출력 진단과 완전 자유 생성의 결과를 따로 보고한다.

공유 구조가 독립 구조보다 이득이 없으면 공유 구조 가설을 기각한다. 출력 보강만
효과가 있으면 연구 주장을 해당 조건부 학습 문제로 좁히고, 이미 알려진 방법과의
차이를 다시 확인한다. 특정 모듈의 기각을 전체 연구 불가능으로 확대하지 않는다.

실행 비교에는 원형 ARGN, 현재 강한 개선 기준, 충분히 학습·선정한 CPAR를 둔다.
가까운 최신 생성기는 데이터 조건·생성 단위·공개 학습 코드까지 확인해 추가한다.
2026 논문 검토를 최종 결과 뒤로 미루지 않으며, benchmark나 사기 행 증강을
전체 고객 거래열 생성기의 직접 비교로 대체하지 않는다.

**TabDiT 실행 가능성 재확인:** 공식 저장소가 있다는 사실만으로 Sparkov 재학습
가능하다고 판단하면 안 된다. 2026-09-27 확인한 [CODE_README](https://github.com/fabriziogaruti/TabDiT/blob/main/CODE_README.md)와
[run_experiments.sh](https://github.com/fabriziogaruti/TabDiT/blob/main/run_experiments.sh)는
배포된 생성 자료를 읽는 평가 명령을 제공한다. 보존된 recursive tree도 평가 코드
중심이다. 이번 확인에서 생성기 학습 경로는 확보하지 못했다. 직접 비교 우선
대상이지만 즉시 공식 학습 실행 가능으로 표시하지 않는다. 추가 공개 구현 확인과
필요 시 논문 기반 구현의 범위·검증을 별도로 정하고, 그동안 현재 진단과 실행
가능한 baseline 작업은 계속한다.

## 5. 채택 및 확장 기준

사기 발생·지속·종료, 개인 대비 금액, 간격, 정상 품질, 다양성을 동시에 보고한다.
현재까지의 2부모 확인을 넘어 독립 학습 seed를 추가하고 고객 단위 불확실성을
평가한다. 생성 seed를 늘리는 것으로 학습 불확실성을 대신하지 않는다.
기존 실험의 큰 비용 제외 기준은 초기 screening일 뿐 논문 수준 비열등성 증거가
아니다. 새 비교의 주지표·비용 허용 기준·학습 예산은 결과를 보기 전에 등록한다.

제안 요소 제거 시 효과가 줄고 강한 선행 대비 추가 이득이 재현되면 데이터/조건을
확장한다. Sparkov 한 자료에서 생긴 특수 현상인지 구분할 다른 라벨 있는 거래열
자료의 적합성을 점검한다. Berka는 정상·사기 관계 일반화의 증거로 사용하지 않는다.
최종 test 이벤트는 모델·프로토콜 선택을 마친 뒤에만 연다.

다음 보고는 단순 점수표로 끝내지 않고 **오류 위치 → 지지된 원인 → 채택/기각한
변경 → 바로 다음 실행**을 함께 제시한다.

## 2026-09-27 실행 후 갱신

위 진단과 작은 출력 대조를 실제 완료했다.4head학습/24전체생성에서
공유 상태 구조를 먼저 추가할 근거보다 **시간 출력의 조건부 학습 문제**가
확인됐다. 기존 최종 후보는 보존하고, 단순 phase GMM을 강한 시간 대조로
추가한다. 개인 대비 사기 시작 gap은 이력 모형이 낫다는 차이가 추가 draw와
CPU 같은 장치 대조에서도 반복됐다. 복귀의 개인 관계 우위는 반복되지 않았다.

따라서 바로 다음 구현은 일반 history 조건부 시간 mixture와 고객 과거 기준
재표현을 비교하는 단일 시간 출력으로 좁힌다. 전환과 출력의 공유 상태4대조는
필요성이 확인될 때 실행하며 현재 완료한 것처럼 표시하지 않는다.
