# 기술 검증·실행 기록

- 추가 학습 CPU smoke에서 첫 호출은 공식 enum 값에 소문자 문자열을 넘겨 실패했다. 공식 `ModelStateStrategy.resume`로 수정했다. 두 번째 호출은 HuggingFace cache가 읽기 전용 경로를 가리켜 실패했다. 별도 실험 cache를 쓰도록 바꿨다. 두 실패 폴더를 각각 보존했고 과학적 추가 학습은 시작하지 않은 상태였다.
- 세 번째 CPU smoke는 저장된 optimizer/scheduler를 복구해 제한된 step을 실행하고 원본 불변성을 확인했다. smoke의 최선 가중치는 그대로 유지되고 마지막 학습 가중치는 바뀌어, 실제 업데이트와 best 유지가 각각 작동함을 확인했다.
- 확률 변환 CPU 검증에서 numpy/torch 값, 확률 정규화, 원래 반복률을 넣었을 때의 항등성, 비반복 행동 간 상대확률 보존을 확인했다.
- ARGN의 numeric bin 코드 중 MIN/MAX는 일반 bin 번호순과 값의 순서가 다르다. 학습·생성 양쪽에 같은 순서 변환을 적용해 MIN은 맨 아래, MAX는 맨 위로 보낸다. 무작위 디코딩된 gap의 미래 값을 사용하지 않는다.
- ARGN adapter는 공식 생성 함수의 정확히 한 지점에 정렬된 이전 mark와 현재 집단을 전달하는 호출을 삽입하고, mark 추출 직전 확률만 변경한다. library 파일은 수정하지 않는다. 적용한 공식 함수 소스 hash를 실행마다 남긴다.
- 공식 progress의 validation loss는 반올림된 값으로만 남아 있다. 추가 학습에서 기존 best를 포함할 때 이 저장 정밀도를 사용한다. 이를 정밀한 최적 수렴 검정으로 해석하지 않는다.
