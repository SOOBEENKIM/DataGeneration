# 저장된 D의 금액 꼬리와 이력 피드백: 진단 전 고정

Parent: `c4d4c721481b804ec0ee29ab530c3df84cac411d`. 이전 결과에서 Berka의
과도한 상위 금액을 이미 확인했다. 이번 등록은 **후속 탐색 진단의 범위를 먼저
고정한 것**이며 새로운 독립 확인 실험이 아니다. 모델의 성공/실패 기준을 바꾸지 않는다.

## 대상과 종료 범위

- Berka/Sparkov의 저장된 `D_both/best.pt`, raw만 주 분석한다. 기존 생성 난수
  20261021/20261022의 거래열 네 개를 모두 사용한다. 유리한 seed를 선택하지 않는다.
- 가중치·출력 분포·보정·생성물을 변경하지 않는다. 학습 0, 새 생성 0,
  test outcome 접근 0. 기존 validation은 이미 살펴본 개발 평가 자료다.
- 임계 금액은 fit 금액의 99%, 99.9% 분위, 최댓값, 최댓값의 10배로 고정한다.
  최댓값은 참 support 상한이 아니다. 이상 금액의 진단 기준이며 금융 손실 허용치가 아니다.
- 모델 분포에서 임계 금액을 넘을 확률을 해석적으로 계산한다. 큰 표본을 새로
  생성해 tail을 추정하지 않는다. 관측 초과율과 비교하며, 전역 분포 보정의
  문제를 개별 거래의 알려진 참 조건부 오차로 부르지 않는다.

## 1. 실제 이력에서도 출력 분포가 잘못되는가

모든 validation 거래의 실제 과거·실제 현재 간격·행동에 조건화한 금액 분포를
계산한다. 예측 초과율(조건부 확률의 평균)과 실제 초과율, Brier, log1p MAE를
기록한다. 각 성분이 초과 확률에 기여한 질량과 log 금액 표준편차도 기록한다.
0은 별도 원자이며 양의 임계값 초과 확률에 포함하지 않는다.

## 2. 같은 고객 조건에서 이력과 현재 거래 구성을 교차한다

기존 생성 plan의 `fit_position`, `source_entity_id`, 길이를 검증한다.
plan과 동일한 원래 fit 고객의 실제 거래열을 거래 순번으로 짝짓는다. 따라서
정적 특성과 길이·순번은 같지만 실제 경제 상태까지 같아지는 것은 아니다.
짝지어진 원본은 **학습 자료**이며 validation 결과와 구별한다. 중복 고객도
있으므로 128개 plan을 128개의 독립 고객/학습 반복으로 해석하지 않는다.

현재 금액 분포 입력은 이력 H와 현재 간격·행동 X이다. 네 조건을 계산한다.

| 코드 | 과거 H | 현재 간격·행동 X |
|---|---|---|
| RR | 실제 | 실제 |
| GR | 생성 | 실제 |
| RG | 실제 | 생성 |
| GG | 생성 | 생성 |

GR−RR와 GG−RG는 현재 X를 고정한 이력 변경의 모델 반응이다.
RG−RR와 GG−GR는 H를 고정한 현재 X 변경의 반응이다. 둘의 상호작용도 기록한다.
대칭 분해 `history=.5[(GR−RR)+(GG−RG)]`,
`current=.5[(RG−RR)+(GG−GR)]`의 합은 GG−RR이다.
이는 순서 평균의 산술 분해이며 현실의 인과적 원인 비율이 아니다.

현재 X를 생성값으로 고정한 상태에서 추가 두 이력을 평가한다.

- AG: 과거 금액만 생성값, 과거 간격·행동·보조 필드는 실제값.
- OG: 과거 금액은 실제값, 나머지 과거 필드는 생성값.

이를 RG/GG와 함께 금액 이력/나머지 이력의 대칭 분해에 사용한다.
짝이 맞지 않는 혼합 이력은 비현실적인 조합일 수 있다. **읽기 전용 모델 입력
민감도 진단**이며 실제로 이력을 수정해 재생성했을 때의 개선을 입증하지 않는다.
현재 보조 필드(category/type)는 금액 뒤에 생성되므로 금액 예측에 넣지 않는다.
현재 금액도 입력 이력에 들어가지 않도록 경계·인과성 검사를 한다.

## 기록·검산·판단

- 거래 위치 0, 1–7, 8–31, 32–127, 128+별 결과, 실제/생성 현재 행동별 결과도
  고정하여 기록한다. 모델 이력은 최대 과거 31거래로 유지한다.
- 같은 checkpoint에서 추정한 validation log-MAE를 이전 기록과 검산한다.
  해석적 생존 확률은 별도 SciPy lognormal survival 계산과 검산한다.
  생성물의 초과율과 GG 예측 평균을 함께 보고, 네 데이터에서 표본 변동도 남긴다.
- 숨은 상태를 단일 prefix로 재구성한 값과 batch 평가를 경계 위치에서 비교한다.
  파일 해시가 전후 같아야 한다. 새 optimizer/sample 호출은 없다.
- 실제 이력에서 과도한 tail이 남으면 출력 분포/학습된 파라미터의 적합성 문제가
  생성 피드백만으로 설명되지 않는다고 판단한다. 생성 이력이 더 키우거나 줄이는
  방향은 위 교차 차이를 그대로 보고한다. 둘이 함께 존재할 수 있다.
- 이 진단으로 특정 코드 결함, 전체 GRU 구조의 실패, 새 출력 후보의 성공을
  단정하지 않는다. 결과 보고와 한 가지 다음 비교 제안까지만 하고 종료한다.
  새 금액 head 학습·seed 확대·tail clipping을 자동 실행하지 않는다.

설정과 소스는 계산 전에 commit한다. 집계·그림은 Git, 거래 단위 배열은
워크스테이션 artifacts에 남긴다. 기존 판정은 그대로 보존한다.
