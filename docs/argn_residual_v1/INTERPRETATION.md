# 잔여 오류 진단: 전체 평균보다 사기 구간 경계가 문제

기존3기준×2부모×4생성 = 저장된24개 거래열을 분석했다. GPU2·3에서 실제
development 과거를 통한 gap/amount 출력도 각각4회씩, 두 부모 총2,847,952개
조건부 값을 생성했다. 전체 고객 거래열을 새로2,847,952행 생성했다는 뜻은 아니다.
gap cache는 native logits와 총2,491,958개 token-position을 대조했고, 금액 cache는
기존 검증본의 hash와 행/라벨을 확인했다. 학습0회, 최종 test 접근0회다.

## 실제 과거에서도 크게 틀린 조건

| 조건 | 실제 거래 수/고객 수 | 실제 gap 중앙값 | 실제 과거를 준 출력 중앙값 평균 | 조건부 gap W1 |
|---|---|---:|---:|---:|
| 정상→사기 시작 | 102/102 | 57,328초 | 19,253초 | 1.2213 |
| 사기→정상 복귀 | 101/101 | 41,621초 | 11,670초 | 1.3830 |
| 사기 지속 | 912/102 | 3,849초 | 5,043초 | 0.2142 |

실제 과거와 실제 현재 label/category를 모두 사용했다. 사기 시작/정상 복귀는
너무 짧게, 지속 사기는 길게 생성하여 전체 gap 분포에서 서로 다른 방향의
오차가 일부 상쇄될 수 있다. 전체 사기 gap W1 0.1367만으로 조건부 성공을
판단하면 안 된다. 이는 현재 강한 설정에서의 출력 학습 문제이며 ARGN 전체의
표현 불가능성이나 다른 최신 모델의 실패를 증명하지 않는다.

최종 후보 자유 생성의 시작 gap W1은1.4962, 복귀1.2261, 지속0.1739다.
실제 과거에서도 오류가 남으므로 생성 중 누적 오차만을 원인으로 삼지 않는다.
조건부/자유 생성 차이는 과거뿐 아니라 현재 조건과 구간 구성 차이도 포함한다.

## 정상 금액 비용은 별도다

최종 후보 정상 금액 W1 0.0630은 주로 일반 정상 거래에 남는다(같은 조건
0.0630; 이전 강한 기준0.0579). 실제 과거에서는0.0419다. phase 비율을
맞춘 표준화에서도0.0630으로, 정상 복귀 비중 변화 하나로 설명되지 않는다.
복귀 거래의 금액 조건부 W1 0.4029는 크지만101건이며, 전체 정상176,851건의
악화를 이 조건 하나로 설명할 수 없다. 간격 수정을 하면 정상 금액까지
자동 해결된다고 가정하지 않는다.

## 다음 한 변경

공유 상태 구조를 먼저 추가하지 않는다. [경계 gap 대조](../argn_boundary_gap_v1/PROTOCOL.md)에서
새 gap head를 같은 용량으로 전체 label별 추가 학습하거나 경계에 집중 학습하고,
양쪽 모두 경계에만 적용한다. 입력·금액 head·전환/길이는 고정한다. 새 gap이
현재 금액 조건과 이후 이력을 바꾸는 비용은 전체 자유 생성으로 확인한다.

이 선택은 [현재 mark 조건의 시간 분포](https://arxiv.org/html/2210.15294v2),
[LBDTPP 2026 시간/mark 복원](https://arxiv.org/html/2606.24982v1),
[OmegaSDS 상태/출력 결합](https://arxiv.org/html/2605.06315v1)과 대조한
최소 원인 실험이다. 경계의 중요성·조건부 출력·전문가 사용 자체를 새 기여로
선언하지 않는다. 가까운 최신 생성기의 같은 조건 직접 비교는 남아 있다.
