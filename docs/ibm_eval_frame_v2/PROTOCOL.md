# ibm_eval_frame_v2 — 새 평가 틀: 다른 연도, 같은 고객 분할, 새 봉인 test (등록 2026-11-11, 새 연도 자료를 만들기 전)

사용자 지시(2026-11-11): "진행". 2013년 봉인 test는 [한 번 열렸다](../ibm_sealed_test_v1/RESULTS.md). 그 뒤의 모델 개선을 같은 test로 다시 재면 수치가 무의미하므로, 개선된 모델의 확인 평가는 **아직 읽지 않은
자료**에서 한다. 이 문서는 그 틀만 고정한다. 모델 변경·학습·생성은 이 문서의 범위가 아니다.

## 0. 등록 전에 읽은 것 (숨김 없이)

원자료 `raw_events.parquet`(1991–2020, 2,000명)에서 **연도별 집계만** 읽었다: 30건 이상 고객 수, 사건 수, 사기 건수, 사기 고객 수, 그리고 2013 분할 역할(train / dev / test)별 고객 수와 사기 고객 수.
행 단위 사건은 읽지 않았다. 아래 표가 읽은 전부다.

| 연도 | 고객(≥ 30건) | 사기 건수 | 사기 고객 수(비율) | 그중 2013-test 고객의 사기 고객 수 | 2013 과제에 없던 고객 |
|---|---:|---:|---:|---:|---:|
| 2012 | 1,462 | 1,333 | 175 (12.0%) | 27 | 9 |
| 2013 (개발에 사용, test 개봉) | 1,479 | 2,018 | 174 (11.8%) | 19 | 0 |
| 2014 | 1,493 | 1,052 | 108 (7.2%) | 18 | 22 |
| **2015** | 1,516 | 3,281 | 387 (25.5%) | **66** | 48 |
| **2016** | 1,520 | 3,579 | 787 (51.8%) | **115** | 60 |
| 2017 | 1,524 | 255 | 34 (2.2%) | 3 | 74 |
| **2018** | 1,531 | 2,491 | 249 (16.3%) | **38** | 89 |
| **2019** | 1,535 | 2,087 | 229 (14.9%) | **31** | 100 |

같은 고객이 여러 해에 걸쳐 나온다(2013 과제의 1,479명 대부분이 매년 활동). 완전히 새로운 고객은 해마다 9–100명뿐이라 "새 고객만의 test"는 만들 수 없다.

## 1. 고정하는 것

- **고객 분할은 2013의 것을 모든 연도에 그대로 쓴다**(`prepared/roles.parquet`: train 1,000 / dev 240 / test 239). 이렇게 하면 test 고객은 **어느 연도에서도 학습·선택에 쓰인 적이 없다**(고객 수준의 완전한 분리).
  2013 과제에 없던 고객은 확인 연도에서 제외하고 수를 기록한다.
- **확인 연도 = 2015, 2016, 2018, 2019.** 규칙: 2013 이후의 완전한 연도 중 test 고객의 사기 고객 수가 30명 이상인 해 전부(2014는 18명, 2017은 3명이라 제외). 네 해를 합치면 test 사기 고객 250명(2013 test는 19명).
  2016은 고객의 절반이 사기를 겪는 다른 양상의 해다 — 규칙이 고른 대로 포함하고, 2016을 뺀 결과도 함께 보고한다(둘 다 사전에 정한 보고 항목).
- **과제 정의는 2013과 같다**: 달력 1년 창, 30건 이상 고객, 같은 열, 정적 문맥 4개는 창 이전 이력에서만 계산. 연도마다 backbone·출력층·표를 **그 해의 train 고객으로만** 새로 적합한다(초매개변수와 부품 구성은 동결된 것 그대로; 연도별 선택 없음).
- **봉인**: 준비 스크립트가 연도별 `test.parquet`·`test_context.parquet`를 쓰고 해시만 기록한다. 이 파일들은 §3의 동결 등록 커밋 전에는 읽지 않는다. 준비 단계가 내는 집계는 위 표의 범위(고객 수·사건 수)로 제한하고,
  test의 사기 관련 집계는 추가로 내지 않는다.
- **개발에 쓸 수 있는 것**: 2013 train·dev(지금까지와 같음). 확인 연도의 **train·dev 고객 자료**는 개발에 써도 test 고객과 분리돼 있으나, 쓰면 무엇을 왜 썼는지 기록한다. 2013 test와 확인 연도 test는 개발에 쓰지 않는다.

## 2. 평가 설계 (2013 평가와 같은 스크립트, 다음만 다름)

- 팔: 동결된 개선 모델(v2), 현재 채택 모델(v1; 비교용), ARGN 원형, RTF 원형, RTF + 전이표. 모든 팔은 test 고객의 문맥으로 생성하고 RTF는 2013에서와 같이 실제 창 길이를 받는다.
- 적합 수: ARGN 계열 **연도당 5 fit**(fit당 약 65초), RTF **연도당 3 fit**(fit당 약 1.5시간; GPU는 다른 사용자와 공유하므로 기다리며, 줄여야 하면 수정안으로 먼저 기록). fit당 생성 2회.
- 지표: TSTR 효용(등록 탐지기 `stable`; 보조 3종), 1단계·구조 지표, 속성 일관성. 바닥·상한은 그 해 train에서 test 크기의 부분표본으로 다시 계산.
- **1차 평가 변수**: 연도별 [효용(v2) − 효용(RTF + 전이표)]의 네 해 평균. 불확실성은 (i) test 고객 재표집(탐지기는 한 번 학습하고 점수만 재표집, 2,000회)과 (ii) fit·생성 간 변동을 함께 반영한 95% 구간으로 보고한다.
- **우월 주장의 조건(사전 고정)**: 네 해 평균 차이의 95% 구간 하한 > 0 **이고** 네 해 중 세 해 이상에서 차이의 부호가 양. 둘 중 하나라도 아니면 "같은 수준"으로만 쓴다. 상한 대비 비율도 연도별로 보고한다.

## 3. 순서

1. (지금) 이 문서 커밋 → 연도별 자료 준비·봉인(test 미열람).
2. 2013 train·dev에서 v2 부품 개발(각 부품은 별도 등록; [선행 연구 대조](../ibm_design_v2/PRIOR_WORK.md)).
3. v2 동결 등록: 구성·초매개변수·판정 수치를 확인 연도 test를 **열기 전에** 커밋.
4. 확인 연도 test를 **한 번** 열어 평가. 결과가 나쁘면 그대로 기록한다. 그 뒤에 또 고치려면 다시 새 평가 자료가 필요하다(남는 것: 2012, 2014, 2017 — 사기 고객이 적어 검정력이 낮다).

## 4. 한계(미리 적음)

- 같은 고객의 다른 연도이므로 "완전히 새로운 고객 집단"에 대한 일반화는 아니다. test 고객은 어느 연도에서도 학습에 쓰이지 않았다는 것까지가 보장이다. 또 같은 시뮬레이터의 자료다 — 다른 자료원 재현은 Sparkov가 맡는다.
- 2013 dev 고객의 2013 자료는 부품 선택에 쓰였다. 확인 연도의 dev 고객 자료를 개발에 쓰면 그 사실이 남는다.
- 연도별 사기 고객 수를 등록 전에 읽었다(§0). 연도 선택 규칙은 그 집계에만 의존하며 모델 결과와 무관하다.
