# fraud_utility_v1 — downstream 효용 프로토콜 (등록 2026-11-08, 실행 전)

목적: 구간 배분·경계 지표가 **합성 데이터의 용도**(사기 탐지기 학습)에 실제로 영향을 주는지
확인한다. 125개 기존 생성물은 표준 지표는 비슷하면서 구간 지표가 크게 다른 자연 실험 집합이다.
새 생성 0, GPU 0, 최종 test 미읽음.

## 1. 관측 오류와 근거

1단계·2단계에서 사기율이 맞아도 구간 배분이 반대로 틀린 생성기 둘(ARGN, REaLTabFormer)과
구간을 복원한 전이 head 가족이 있다. 이 차이가 탐지기 성능으로 이어지는지는 측정한 적이 없다.
효용이 구간 지표와 함께 움직이지 않으면 기여 B(평가)의 근거가 약해진다.

## 2. 가장 가까운 선행 방법

TSTR(train-synthetic-test-real; Esteban et al. 2017, Seq2Synth v3 §4 utility, 사기 행동 벤치마크
2604.13125 §5의 탐지 효용). 본 프로토콜은 그 절차를 그대로 쓰되 **이력 특징 탐지기**와
**행 단독 탐지기**를 나란히 둬 효용 차이가 시퀀스 구조에서 오는지 분리한다.

## 3. 중복과 남는 가설

TSTR 자체는 선행이다. 남는 가설: (U1) 생성물 간 TSTR 효용의 차이는 표준 지표보다 구간 배분·경계
지표와 더 강하게 상관한다. (U2) 그 상관은 이력 특징 탐지기에서 크고 행 단독 탐지기에서 작다.
(U3) 전이 head 가족의 효용은 원형 ARGN보다 높고 실제 대 실제 상한에 가깝다.

## 4. 비교 실험

- 평가 대상(고정): 실제 development 147명 177,997건의 모든 사건. 라벨 `event_is_fraud`.
- 학습 자료: (i) 125개 생성물 각각(같은 147명의 합성 사건), (ii) 실제 상한: train 688명에서
  147명 비복원 추출 20회(seed 20261108) → "실제로 학습·실제로 평가"의 같은 표본 크기 분포,
  (iii) 참조: 실제 development 자체로 학습·평가(과적합 상한, 해석용).
- 특징(모두 strict past, 라벨 미사용): 행 특징 = log1p 금액, log1p 간격, 업종(one-hot), 가맹점
  재방문 여부, 위치(log1p event_index). 이력 특징 = 직전 20건 금액 중앙값 대비 비율, 직전 20건
  간격 중앙값 대비 비율, 직전 5건 평균 log 금액, 직전 5건 중 재방문 가맹점 수, 직전 5건 업종 중
  현재 업종 일치 수, 직전 1·2·3건의 log 금액. 고객 정적 열은 쓰지 않는다.
- 탐지기: `sklearn.ensemble.HistGradientBoostingClassifier`(max_iter 300, learning_rate .1,
  early_stopping off, class_weight 없음, random_state 20261108). 두 변형: 행 단독 / 행+이력.
- 지표: AUPRC(주), AUROC, 실제 사기 구간의 조기 탐지율(구간의 첫 2건 안에 점수 상위 1% 임계로
  탐지된 구간 비율), 구간 단위 재현율(구간 중 1건 이상 탐지).
- 분석: 생성물 125개에 대해 효용 대 1단계 지표의 Spearman 상관(표준 S_* 대 구간 R_*), 가족별
  평균, 실제 상한 분포와의 거리. 생성물과 평가 대상이 같은 147명이라는 점(정적 조건 공유)을
  한계로 기록한다.

## 5. 판단 조건

- 이력 특징 탐지기 AUPRC가 구간 지표(지속률·구간 길이·사기 고객 수)와 |ρ| ≥ .5 이고 표준 지표
  와의 |ρ|보다 크면 U1·U2 채택 → 기여 B 유지.
- 효용이 표준 지표와만 상관하거나 어떤 지표와도 상관하지 않으면(|ρ| < .3), 구간 지표는 "용도와
  무관한 충실도"로 내려 기여 B를 수정한다.
- 실제 상한과 최선 생성물의 AUPRC 차이가 상한의 표본 분산 안이면 Sparkov에서는 효용으로
  생성기를 구별할 수 없다고 기록하고 실제 데이터로 넘어간다.

## 6. 실행 후 갱신

생성물별 효용, 상한 분포, 상관표, 실패·제외를 `RESULTS.md`와 CSV에 남긴다.

## 수정안 1 — 탐지기 설정 (2026-11-08, IBM 적용 중 발견, Sparkov 결과 산출 후)

등록 설정(`max_iter 300, learning_rate .1, early stopping 없음`)은 사기율 .0018인 IBM development에서
**수치적으로 발산**한다: 같은 표에서 학습·평가해도 이력 탐지기 AUPRC가 20회 .41 → 50회 .07 → 300회
.002로 떨어지고 예측 확률이 1.0으로 포화된다(고유값 116개). 실제 train 240명 → development에서도
행 .023 / 이력 .002다. Sparkov 실제 상한 20회 중 2회가 무작위 수준이었던 것도 같은 현상으로 본다.
수정 설정 `stable`: `max_iter 300, learning_rate .05, l2_regularization 1.0, min_samples_leaf 50, early stopping
없음`(반복 예산 동일, 정규화만 추가). 같은 실제 240명 추출에서 행 .40 / 이력 .58로 복원된다.
적용: IBM 효용은 `stable`로 실행하고 등록 설정의 결과(`utility/`)도 발산 증거로 보존한다. Sparkov
효용은 `stable`로 다시 실행해 `detector_stable/`에 두고 원래 `RESULTS.md`는 고치지 않는다. 판단
조건(5항)은 바꾸지 않는다. 이 수정은 설정 발견이며 모델 변경이 아니다.
